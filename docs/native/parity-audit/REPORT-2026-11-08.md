## Continuity findings

Where it lives: `N/android/migration` (runner S0, M1 to M6), `N/engine/migration`, `N/feature/gate`, wiring in `N/androidApp/.../graph/MigrationWiring.kt`. The store ledger is `F`-side data copied to `N/../docs/native/migration/store-ledger.json` (379 rows).

Good news (verified in source):
- Same package and same signer rule are enforced by `adoptsFlutterData` (package == `io.github.eslamasabry.opencode_mobile`) and the identity gate in `N/../docs/native/switch-day.md`.
- Native reads Flutter's own prefs file in place (`FlutterSharedPreferences.xml`, `flutter.` key prefix, `N/core/data/.../FlutterPrefsCodec.kt`). No copy, no conversion. The runner takes a byte backup first (S0), counts stores (M1), moves secrets (M2), finishes Flutter's one-shot transforms (M3), audits (M4/M5). A gate holds every store until it opens.
- Profiles and servers: `oc.profiles`, `oc.activeProfile`, per-profile keys all READ (154 pref rows READ). Secrets: `flutter_secure_storage` entries `pw.<id>`, `oc.codexToken.`, `oc.githubToken.`, `oc.byoHostSecrets.`, `oc.agentHostSecret.`, `oc.quotaToken.` are decrypted and re-stored in the native Keystore store (`N/android/migration/.../steps/M2Secrets.kt`). An unreadable secret is flagged and the person is asked to re-enter it; nothing is invented. Proven on an emulator 2026-11-03 (`N/../docs/native/qa/migration-proof-2026-11-03/README.md`): servers connect without retyping the password.
- Drafts (`oc.draft.`, `oc.sessionDrafts`, attachment vault), queued prompts (`oc.offlineQueue`, `oc.keptQueuedPrompts`, `oc.withdrawnPrompts.`), saved prompts (`oc.promptStash.`), prompt history, schedules (`oc.scheduledPrompts.`, index, claims, leases), settings (appearance, locale, notify rules, automation), last project and chat tail, pins, widget choices, voice prefs: all READ.
- Scheduled prompts: Flutter's WorkManager job and exact alarm both name the Flutter classes; native keeps those class names and re-arms every schedule on app update (`N/androidApp/.../FlutterSchedules.kt:19,43`; `MY_PACKAGE_REPLACED` in `N/android/schedules/src/main/AndroidManifest.xml:31`). The B-148 fix (6b0ec4235) is in this HEAD. The store ledger still lists the alarm and `oc.scheduleReceipts.` as MISSING; the ledger is stale on the alarm.
- Built-in Linux: same paths. Native `BuiltinLinux` is a fork with the same `files/linux/ubuntu`, `ubuntu.ready`, `linux/agent-root-view`, `.oc-profiles/<id>/{claude,codex,paseo}` layout (`N/android/linux/.../BuiltinLinux.kt:44-70,1193-1258`). Proot and sherpa libraries are now packaged (`N/androidApp/build.gradle.kts:381-389`); the 2026-11-03 proof's "Linux and voice absent" blockers no longer apply.
- Voice models: read in place from `files/voice_models` (`N/engine/voice/.../ModelCatalog.kt:9`); `voice.selected_pack`, `voice.language` are READ.
- Notifications: 11 channels, 2 tiles, 7 widgets, 3 shortcuts are carried (ledger rows READ). Launcher shortcuts include the pinned-conversation one now (part B).
- Running servers: an in-place update kills the app's processes, including the proot servers. Native restarts the phone server on app open (`AppOpenStart`, `N/androidApp/.../graph/LinuxVoiceWiring.kt:635,1609`) and honours the owner's deliberate stop (`oc.phoneServerStopped.`). So a project server comes back after the first launch, not instantly. A turn in flight when the update lands is cut; the session list and history return from the server on reconnect (refetch, per AGENTS.md).
