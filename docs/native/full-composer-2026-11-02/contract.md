# Native composer: model choice and files

Finish line: in the Android preview, select an available model and attach/remove a real local file; the sent request uses that selection and those bytes, unsent text/files survive restart, and profile deletion removes their local state.

Non-goals: voice, camera, clipboard pictures, saved prompts, phone Linux adoption, all-pages parity and production release.

Use the existing acknowledged chat composer path. The dormant FullComposerHost clears before acknowledgement and must remain unbound until replaced; do not adopt its old send semantics. This slice delivers the richer visible composer by extending the working host. No feature-to-feature dependency.

## Frozen integration API

* `core.domain.platform.PromptFilePicker`: `suspend fun pickFile(current: List<PromptAttachment>): Outcome<PromptAttachment?>`. A null success is cancellation. Output is bounded, MIME-validated data, never a content URI. Android contributes one implementation into an AppScope set. Desktop's empty set disables the action. Android adapter owns ActivityResults and bounded file reads; MainActivity attaches before rendering and detaches on destroy.
* `DraftState` appends `attachments: List<PromptAttachment> = emptyList()` and `savedAttachments: List<PromptAttachment> = emptyList()`. `DraftSubmission` appends `attachments: List<PromptAttachment> = emptyList()`. Redacted toString remains content-free.
* `DraftSession.replaceAttachments(files: List<PromptAttachment>): Outcome<Unit>` is suspend, snapshots its inputs, persists through the existing vault/index owner, publishes accepted chips only after commit, preserves newer text edits and invalidates old submission tokens on a file edit. Missing recovered files fail closed without overwriting metadata. Whitespace text is preserved exactly. Text autosave always retains the current file snapshot. Clear after accepted send compares identity, revision, text and files. Profile fences precede all writes, including delayed picker results.
* `ChatWorld` appends defaults for `replaceAttachments(files): Outcome<Unit>`, `models: StateFlow<ComposerModels>`, `loadModels(): Outcome<Unit>`, and `selectModel(choice: ComposerModel?): Outcome<Unit>`. `ComposerModel(providerId, modelId, label, supportsAttachments)` contains safe display metadata only. `ComposerModels(choices, selected, loading, failure)` contains no raw config. Selection is scoped to the conversation/server; supported model mutation/readback must be proven before enabling choices. A failed selection must not replace the previous choice. A stale graph cannot publish or mutate another target.
* `DraftFacts` appends attachments/savedAttachments with defaults; unsaved compares text AND files. GraphChatWorld captures the exact file snapshot in the same DraftSubmission as text; retry sends retain the original snapshot. `ConnectionDelivery.send` accepts defaulted immutable attachments/model arguments and passes them to SendRequest. Online model selection must actually reach the callable OC2 model API before prompt dispatch, never silently ignore a choice. Busy steering remains steer-only, no queue fallback.
* `BasicComposerUi` appends `models: ComposerModels = ComposerModels()`, `pickingFile: Boolean = false`, `attachmentFailure: Failure? = null`, `filesAvailable: Boolean = false`. `BasicComposerActions` adds `loadModels()`, `selectModel(choice: ComposerModel?)`, `attachFile()`, `removeAttachment(index: Int)`, `dismissAttachmentFailure()`, with no-op defaults for old fakes. UI owns kit arrangements only. ViewModel owns file selection/persistence, target checks and flow mapping; GraphChatWorld owns all canonical draft/send/model truth.

## UI and copy

Visible model control, visible Attach file control, file-name chips with explicit Remove, model list with Loading / Retry / no available models, EN and AR copy. File selection cancellation makes no change. Storage, unsupported-file and size failures use plain words and retry/remove paths; technical Details remain redacted. Preserve existing synchronous onTextChanged, restoreRevision/IME rules, Stop, focus, inserts and explicit repeat confirmation. Send is allowed for text OR files, disabled while a picker/attachment commit/model change is active or draft storage/acknowledgement is uncertain. No voice or approval controls without their real implementation. No raw provider config in UI, logs or screenshots.
