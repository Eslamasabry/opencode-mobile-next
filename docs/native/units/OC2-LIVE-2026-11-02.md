# OC2 live preview transport — 2026-11-02

Finish line: the preview app can connect to an authenticated OpenCode 2 beta or stable server, read and create conversations, admit a prompt once, and receive real streamed content. This is a side-by-side preview adapter, not parity or an in-place migration release.

## Contract and implementation

`Oc2GatewayFactory` contributes one `GatewayFactory` for OpenCode2. Its app-scoped constructor requires `HttpClientFactory`, `AppDispatchers`, `Clock`, `Redactor` and a secure-backed `kotlin.random.Random`. Android binds `HttpClientFactory(OkHttpEngineFactory())` and `SecureRandom().asKotlinRandom()`.

- Uses `:core:net`'s existing hardened transport: exact-origin trust, explicit non-loopback HTTP consent, optional certificate pin, no redirects and no automatic mutation replay.
- Resolves Basic credentials from `GatewaySpec`; registers the password before transport use. Provider config endpoints are never read.
- Recognizes numeric `0.0.0-beta-N` health versions and versioned OC2 health payloads. The implemented API routes and envelopes are ported from frozen `lib/api2/client.dart`, `gateway.dart` and `dialect.dart`. An unknown connection first reads `/health`; only a clean 404 may read stable `/info`. A valid version pins the dialect before any mutation. Authentication errors and ambiguous reads never trigger a dialect fallback. Stable rename uses PATCH, permission replies use `decision`, and interrupt continuation uses `resume`; beta retains its original routes and fields. Mutations are never retried under another dialect.
- Implements health, sessions, create/rename/delete, strict active-session snapshots, paged chronological history, prompt admission, interrupt, public provider/model/agent inventory, pending permissions and permission replies.
- Fetches the newest message page in descending server order and reverses it for the reducer; a short page never advertises another older page. Fetched text/reasoning/tool part IDs and tool projection share the live event adapter.
- Uses the existing volatile event stream and adapter. Every reconnect announces `Connected` so consumers reconcile with fresh reads, with no event replay.
- Generates sortable client prompt IDs with the existing `Oc2ClientIds`. Staged revert preflight runs before dispatch; the exact-scope callback is checked immediately afterward. A response confirms only the matching session, prompt type and client ID. An unreadable response or transport ambiguity remains uncertain and never retries the POST.
- Interrupt uses the actual beta contract: no JSON body and optional `continue=true`; it distinguishes interrupted, nothing running and unknown acknowledgement.
- Unsupported features are explicitly capability-off and return `Unavailable` for unsupported mutations. Queue is refused; steering remains the admitted delivery mode.

## Verification

The coordinator runs Gradle and records final candidate results in `REPAIR-INTEGRATION-2026-11-02.md`.

`Oc2LiveGatewayTest` has nineteen focused regressions covering redirect refusal, exact prompt admission, staged revert, stale scope after preflight, canonical paged history, strict active snapshots, beta/legacy health recognition, malformed prompt acknowledgement, interrupt, empty-location omission, public model inventory and captured permission targets, typed history notices/attachments, short/full-page continuations and JSON-null fields.

`LiveOc2ServerSmokeTest` is an explicit live gate. Without `OC_NATIVE_LIVE_URL` and `OC_NATIVE_LIVE_PASSWORD` it is reported as skipped via a JUnit assumption. Optional `OC_NATIVE_LIVE_USERNAME` and `OC_NATIVE_LIVE_DIRECTORY` configure only the isolated test server. It creates and deletes its own session, requires actual event parts and a real model response, and prints fixed status booleans only. It never reads owner profiles or credentials.

The isolated real-server smoke passed against both official beta `0.0.0-beta-19242` and stable `2.2.5`: authenticated health, create/list, exact admission, real GLM response, streamed parts and stop; each live run had one test, zero skips and zero failures. The final nineteen-mock run passed separately. The Android preview then completed actual server setup, real chat, restart/update recovery and profile-secret removal on an Android 15 emulator; see the combined report and screenshots. Physical-device and tool-execution acceptance are not inferred from these proofs.

## Remaining limits

- Server forms, file browsing, shell/slash commands and the remaining product-operation facets are unavailable. Stable route normalization is covered by focused contract tests and the isolated stable 2.2.5 smoke; other server versions remain unqualified.
- The current stream uses the `UnknownNetworkStatus` gate and foreground visibility default until app demand/network wiring is supplied. This is not background-service qualification.
- This slice supplies no migration, physical-device, release, signing or full parity proof.
