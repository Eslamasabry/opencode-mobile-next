## Changes and evidence

- **Original crash:** `DiagnosticsAttentionStartup` now calls `Log.e` with the original throwable before category
  capture, records its class, message and first 15 frames through `Diagnostics.record` (the existing
  `Redactor.diagnostics` boundary), and chains it into the categorized error. `NativeCrashStore.install` also chains
  that error into its fixed `Native application error` wrapper, so the final Android handler retains the cause.
  User-facing category/termination behavior stays the same. The original full throwable in logcat is explicitly
  requested; the in-app record remains redacted.
- **N-13:** `FirstMessageReview` was the only `@Serializable` DTO in `androidApp`.
  `OcAndroidApplicationPlugin` applies Android, Compose and Metro, but **not** the serialization compiler plugin
  (`OcKmpLibraryPlugin` does apply it). The receipt's `WireJson.encodeToString(FirstMessageReview(...))` therefore
  requires a missing generated serializer. This call is after session creation/read and before `delivery.send`,
  matching the successful session requests and absent prompt in QA. Inspection of the installed serialization 1.12.0
  class with `javap` confirms `SerializationException extends IllegalArgumentException`, matching the recorded
  category. Use explicit `DartJson` receipt encoding/decoding with the existing session/directory/target fields.
  Save the chosen model/project in the same acknowledged pre-send transaction, rather than only after acceptance.
  The delivery request still carries the exact model; selection/readback still precedes prompt admission.
- **N-14:** `git log -p` identifies `584400598` adding the nonempty transcript/pending/live condition to chat's
  `overlayChrome`. The first optimistic bubble switches false to true. `KitScreen` previously used raw slots when
  false and movable slots when true, disposing the composer whose `rememberCoroutineScope` owned the send tap.
  This cancels admission before a prompt POST and leaves the optimistic bubble and draft protection behind.
  Both layouts now invoke the same movable slots; send/repeat admission also runs in the entry ViewModel scope.
  The empty-chat layout and compact status improvements remain.
- **N-15:** remove the transient Servers header action that displaced Settings while opening/recovering a server;
  Settings stays before the optional update action. Servers remains in More and connection recovery.
- **N-16:** ordinary persisted project drafts no longer hydrate a fresh New conversation entry or overwrite it on
  resume. Text already being edited in that entry survives picker visits. An unresolved first-send receipt still
  restores its text for review and blocks duplicate dispatch.
- **N-18:** details observes per-profile startup failures and live stream status. Typed failures select plain English
  and Arabic reasons; credential failures offer Fix sign-in and open the editor. A stopped stream supplies its current
  failure, waiting for network reports offline, and unknown states ask the person to connect/check. Cached failures
  are described as the last connection attempt so an edited password is not presented as newly checked.
