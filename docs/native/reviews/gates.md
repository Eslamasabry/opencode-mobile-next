Verdict: **BLOCKER — the push gate can publish unscanned commits, and the ladder can qualify the wrong tree.**

1. **BLOCKER — [native/tool/scan_push.sh:76](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/scan_push.sh:76): pushed objects differ from scanned objects.**  
   The scanner resolves one source SHA, then pushes the original symbolic ref with unrestricted options. `--push origin clean --tags` scans `clean` but also publishes tags pointing to unrelated, unscanned commits. A concurrent branch update can likewise replace the scanned tip before line 82 pushes it. A mocked invocation confirmed `--tags` reaches Git after a clean scan. **Fix:** restrict options that expand the published refs, resolve the complete update set, and push the exact scanned object IDs.

2. **MAJOR — [native/tool/lib/scan_push.py:107](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/lib/scan_push.py:107): valid private hosts bypass blocking.**  
   Every address ending in `.0` or `.255` is exempted, although those are valid host addresses on larger subnets. The CIDR exemption also mistakes a numeric URL path for a prefix: synthetic private URLs ending in `/12345` scan clean. In-memory probes confirmed both bypasses. This violates plan 15 §2.1.1’s private-address gate. **Fix:** detect URL hosts separately; allow only explicit, reviewed range literals instead of inferring network boundaries from the last octet.

3. **MAJOR — [native/tool/lib/scan_push.py:181](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/lib/scan_push.py:181): forbidden-file detection misses renames.**  
   Forbidden paths are checked only in `+++` and binary-difference records. A pure rename produces neither, so renaming an opaque `.bin` into `.jks`, or another file into `key.properties`, passes. Empty forbidden files also pass. Replaying those patch forms produced zero hits. **Fix:** enumerate added, modified and renamed destination paths independently using Git’s NUL-delimited filename output, then apply `BAD_FILE`.

4. **MAJOR — [native/tool/check_write_set.sh:85](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/check_write_set.sh:85): an unavailable merge base becomes a successful write-set check.**  
   `mapfile < <(oc_changed_files …)` discards the producer’s failure. If a valid base is unrelated or shallow history prevents finding its merge base, the gate sees zero changed paths and exits 0. A mocked Git failure reproduced `write-set: OK` with an empty merge-base field. **Fix:** capture and validate the changed-file command’s exit status before checking paths; return 2 when enumeration fails. Apply the same correction to T1’s changed-file collection.

5. **MAJOR — [native/tool/vps_gradle.sh:66](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/vps_gradle.sh:66): VPS locking permits source replacement during a build.**  
   `rsync --delete` runs before acquiring the remote lock. Another invocation can replace source files while Gradle reads them. This is especially reachable because every worktree without an `ocn-` prefix defaults to the same `adhoc` directory. T2 also releases its remote lock between steps, allowing separate T2 runs to interleave. These results cannot establish plan 02 §8’s “tree it ran on” guarantee. **Fix:** use an explicit per-worktree workspace and hold its lock across synchronization, execution and result collection; hold T2’s exclusion lock for the complete ladder.

6. **MAJOR — [native/tool/t2.sh:63](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/t2.sh:63): VPS assembly builds an unsynchronized APK tree.**  
   T2 synchronizes through `help -q`, which selects `ocn-<unit>`. Every subsequent step uses `--no-sync`, but the assemble arguments make `vps_gradle.sh` select `ocn-<unit>-apk`. That directory is either missing or contains an older tree. In the latter case, T2 can print `LAST_GREEN` for the current SHA while assembling stale source. The direct VPS assembly self-test synchronizes first and misses this sequence. **Fix:** synchronize and identify each selected workspace before use, including the APK workspace.

7. **MAJOR — [native/tool/t2.sh:65](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/t2.sh:65): local builds bypass the shared PC build slot.**  
   Local T2 holds only `.oc-native-t2.lock`; T3’s instrumented Gradle invocation at `t3.sh:107` takes no build-slot lock. Both can overlap T0/T1 or Flutter builds despite plan 02 §7.8 explicitly requiring the same `oc-build.lock` across both apps to prevent OOMs. **Fix:** wrap every local Gradle invocation in the shared build lock while retaining the separate T2/emulator locks.

8. **MAJOR — [native/tool/t3.sh:94](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/t3.sh:94): cleanup overwrites cancellation status and can write PASS.**  
   The EXIT trap calls `anim` before passing `$?` to `oc_finish`, so it passes cleanup’s status rather than the interrupted run’s status. T4 repeats this at line 81. A shell probe with exit 143 and successful cleanup passed 0 to `oc_finish`; with `OC_STATUS=0`, that writes a successful done-file for an incomplete run. **Fix:** save the entry status immediately, preserve cleanup failures, and handle termination by stopping/waiting for children before reporting completion.

9. **MAJOR — [native/tool/vps_gradle.sh:79](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/vps_gradle.sh:79): golden recording never returns the generated baselines.**  
   T1 advertises `--record` as producing goldens to commit, but the pull-back includes only `build/test-results` and `build/reports`. The target revision’s kit configuration records into `src/screenshots`. T1 therefore reports success without returning the changed images; the next source synchronization can overwrite them remotely. **Fix:** explicitly retrieve the selected module’s recorded screenshots and fail if that retrieval fails.

10. **MAJOR — [native/tool/lib/common.sh:83](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/lib/common.sh:83): T1 does not compile both KMP targets.**  
    Android tasks are included only when `src/androidHostTest` exists. For modules such as `:core:common`, T1 runs desktop tests while changes in `androidMain` remain uncompiled. An unresolved Android-side contract reference can therefore pass T1, contrary to binding ADR §4 row 17’s default that T1 compiles both targets. **Fix:** always add Android compilation for touched KMP modules, independently of whether they contain Android host tests.

11. **MAJOR — [native/tool/t1.sh:118](/home/eslam/Storage/Code/wt/native-reviews/src-gates/native/tool/t1.sh:118): the VPS strings check lacks its required inputs.**

The VPS runner synchronizes only `native/`, leaving those files absent from the asserted repository root. A clean strings change therefore cannot pass this check on a fresh VPS workspace. **Fix:** synchronize the frozen source inputs alongside native code, or run this repository-dependent check locally against the same source tree.
