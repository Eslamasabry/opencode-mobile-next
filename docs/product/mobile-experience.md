## Current brief contract

- Entry: below Workspace's project/context header, before its session sections. It reuses Activity's exact resolvers and F5 results; no new tab or inbox.
- Results are unreviewed idle **sessions**, not proof of successful runs or phone-observed run endings. The user opens results for the recorded outcome. No "since last visit" timestamp is inferred, including after restart.
- First use has no acknowledgements. Unsupported read state, incomplete session inventory and last-observed offline/request-refresh state are stated separately from a confirmed empty brief.
- Up to three result rows and three request rows are displayed. Overflow remains unacknowledged. Dismissing a page may reveal the next page of items. Session/request state is never changed by rendering, dismissing or opening results.
- Persistence: `oc.returnBrief.<profileId>`, keyed by `[baseUrl, directory, workspace]`. Exact `(sessionID, idle)` pairs and `[sessionID, request kind, requestID]` identities only; no transcripts, request bodies or credentials. At most 64 locations, 64 result pairs and 32 request identities per location. Eviction shows more work again; it never blanket-acknowledges unseen work.
- Save-before-hide: the saved set comes from the displayed snapshot, serialized with prior writes. A refused write leaves the card visible with retry. Profile deletion drains pending writes, uses the existing per-profile sweep and forgets the in-memory cache.
- Action callbacks retain profile/location scope. Result routes retire on scope change; permission/question use existing request guards. Form routes now retire on request/scope change and controller sends recheck after transport recovery.
