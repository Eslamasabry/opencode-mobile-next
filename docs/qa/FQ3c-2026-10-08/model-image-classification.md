## Exact app and harness paths

App selection: `lib/state/connection/models.dart::_selectModelForSession` normalizes the ref, validates catalog/variant admission, serializes mutations, awaits `SessionSelectionGateway.setSessionModel`, then refetches the session through `_mutateSessionSelection`. `lib/api2/gateway.dart::setSessionModel` delegates to `Api2Client.switchModel`. Both app and harness write `POST /api/session/:id/model` with `{"model":{"id":modelID,"providerID":providerID}}`; the app additionally preserves a nonempty variant. Session creation also carries the chosen ref. Ordinary OC2 prompts use the server-owned session selection rather than repeating a model override in the prompt body. The existing request-body fixture is `test/api2_interaction_gateway_test.dart`, “v2 explicit selection writes replace the model ref and creation uses defaults”.

The harness additionally requires a fresh matching `session.model.selected` SSE event before its HTTP readback. The app uses serialized write plus HTTP reconciliation; it does not wait for that exact event to finish the mutation. An event-observation timeout would therefore be a distinct harness failure requiring separate diagnosis, even if HTTP selection were retained.

App attachment send: `Api2Gateway._promptAsync` checks unresolved revert state, converts each `PromptAttachment` to `Api2PromptFile(uri: attachment.url, name: nonemptyFilename)`, then calls `Api2Client.prompt`. Harness image send uses one URI-only inline PNG file. Both use the same `/api/session/:id/prompt` envelope and shared stable dialect route mapping; model/session/prompt payloads are not rewritten there. The harness adds `delivery: queue, resume: true`; an ordinary app send omits both. Pinned server source defaults omitted delivery to `steer` and wakes execution unless resume is false. These bodies differ; there is no observed busy-session delivery comparison here to establish a defect.

The harness PNG is a 32×32 red-left/blue-right image. Strict JSON semantic checking happens after successful terminal execution and fresh HTTP message retrieval. A completed response with incorrect formatting produces `image_content_answer_missing`, not the execution wait's generic timeout. Relaxing that semantic guard cannot justify the existing timeout.
