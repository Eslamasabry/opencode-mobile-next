# FQ9 offline driver contract

Finish line: four pre-release device checklist drivers have deterministic offline tests and a runnable, credential-free plan for the coordinator-posted candidate 2197, with package/signature, existing-data, lock and restoration fences. Device qualification remains pending the APK and scheduled device slots.

Non-goals: build/sign/download APKs, rotate certificates, UI/localization changes, uninstall/clear data, change shared Android users, provider enrollment, fake a live turn or claim host tests are device proof.

Base: feat/genui-fe 6a7589446 (exact revision recorded in the README). New branch sol/bc-fq9. QA-only Python standard-library modules under tool/qa/fq9; no edits to production libraries or existing QA clusters.

## Frozen shared interface

`common.py` is root-owned. `DriverFailure(code)` carries fixed driver-authored failure tokens only. Frozen `Artifact(apk, build, version, sha256, signer, origin)` values come from a reviewed manifest; `apk` is an absolute Path, digests lowercase hex. Candidate and normal artifact must be the same approved 2197 artifact. Previous and published-stable artifacts are optional. Stable identity must report actual versionName 1.2.0 and a reviewed published origin; no invented build number or download.

Upgrade module: `run_upgrade(ports, previous, candidate, *, published=False)` returns a safe result dictionary. Ports: `installed_identity()` returns `{build, version, sha256, signer, uid}`; `capture_preservation()` returns an opaque memory-only snapshot; `install_update(artifact)` performs only install -r -d; `launch()`; `verify_preservation(snapshot)` returns booleans `{sentinel, profiles, preferences, secureStorage, histories}`; `remove_sentinel(snapshot)` cleans only the exact owned sentinel. Artifacts are verified by root before device access. Require exact installed previous hash/version/build/signer and same candidate signer BEFORE capture/mutation. Stable-to-candidate may not downgrade the shared modern app to establish a baseline. No credential use or serialization in snapshots/results. Actual Keystore sign-in usability requires a manual app assertion, recorded separately from encrypted-storage preservation.

Background module: `run_background(ports, *, checkpoints=(300,1800), poll_seconds=30)` attaches to an operator-created app-managed fixture turn rather than starting an owned HTTP server. Ports: `live_snapshot()` returns only safe booleans/counters `{ownedTurn, appManaged, appVisible, appAlive, serverAlive, foregroundService, ongoingNotification, turnActive, progressCounter, completed, failed}`; `home()`; `monotonic()`; `sleep(seconds)`; `resume()`; `cleanup_turn()`. Driver must refuse absent/unrelated/finished/retrying-only fixture or missing initial app/FGS identity. HOME once, poll with waits <=30 seconds, no foreground launch/heartbeat HTTP mutation during dwell; verify background and actual active turn at both checkpoints. After resume require observed app visibility and own live/final turn; no fabricated pass on an early final. Progress counters count distinct persisted fixture calls that reached running/completed, not polling counts. Exact latest-prompt ownership plus OC1 busy state admits inference gaps between these calls; retry state never qualifies, and each checkpoint needs newer calls. Report durations and fixed booleans, never raw messages, URLs or credentials. Cleanup only the dedicated operator-provided owned fixture. One 30-minute dwell checks both checkpoints; this holds the emulator lock throughout and must be booked with the coordinator.

Fresh module: `plan_fresh(snapshot)` uses a read-only `{currentUser, users, maxUsers, supportsManagedProfiles, appUsesUserScopedRuntime}` snapshot and always either returns `needs_second_avd` or a supported isolated-user plan. Creation/switch/removal of Android users is deliberately excluded from this driver until a separately-qualified user-scoped runtime exists; never touch user 0. `run_fresh(ports, candidate)` runs only on a separately provisioned AVD verified by root (non-shared serial, boot identity, user0, no installed app, no app-data directory). Ports: `fresh_snapshot()` returns `{dedicated, currentUser, packageInstalled, appDataPresent}`; `install_fresh(artifact)`; `launch()`; `first_run_snapshot()` returns safe `{appVisible, onboardingVisible, profilesEmpty, setupAbsent, crashFree}`. Do not turn a reused/wiped shared device into a clean-first-run claim. The newly installed normal candidate remains installed.

## Ownership and acceptance

Root: common manifest/host artifact verifier, executable CLI, real ADB/observation ports, evidence, README/status, integration tests, all heavy/device processes. Root-owned `find_live_receipt(directory)` is read-only: resolve a unique exact-title/scope OC1 fixture, validate latest-prompt and initial live predicates, export only `{engine,directory,sessions:[{id,title,promptID}]}`. CLI discovery writes a separate readiness report under the same lock; it cannot qualify survival.
Worker upgrade: upgrade.py and test_upgrade.py only; read common contract and app persistence source. Acceptance: signer and exact previous fences, truthful subset preservation, no mutation before fences, failures and sentinel cleanup covered.
Worker background: background.py and test_background.py only; inspect native FGS/app turn contracts. Acceptance: virtual-clock 5/30-minute active-turn checkpoints, early completion/failure, process/service loss, setup and resume/cleanup failures; no real sleeps/jobs.
Worker fresh: fresh.py and test_fresh.py only; inspect user-scoping feasibility. Acceptance: shared-user refusal, explicit second-AVD requirement, dedicated absence check and truthful first-run signals.

Workers are not alone: preserve other edits, accommodate root changes, do not edit shared ports/docs, run tests/formatters/device jobs or commit. Root runs offline tests serially through machine_lock once integrated; no Flutter/APK/emulator jobs are needed for this Python-only slice.
