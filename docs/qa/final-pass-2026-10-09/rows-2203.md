## FQ9 background: harness causes by attempt

1. `setup_active_or_unknown`: `final_pass_live.background` called `require_idle_setup` before resolving the app UID (fixed, tested).
2. `app_managed_socket_unavailable`: the managed runtime was OpenCode 2 or stopped; the row needs OpenCode 1. Added the app's own runtime switch (`RuntimeTransaction` begin/restore; tested).
3. `runtime_switch_timeout`: the switch was attempted while the app was backgrounded after the reinstall. A manual run of the same switch took about 20-35 s.
4. `app_managed_socket_unavailable` again (labelled "socket-idle-pause"): see below.
5. Same code: the batch runner reinstalls the candidate before the first row, which stops the managed server; the wrapper must start it after that.
6. Attempt with start-after-reinstall not applied (executor bound its dispatch at import).
7. `command_failed` creating the fixture project: an empty directory left by my own diagnostic script (removed with the owned session).
8. `navigation_target_unavailable`: stale selector "All conversations" (now Search); old model picker labels.
9. Turn sent but `live_fixture_not_ready`: the app's default `glm-5.3-highspeed` returned `APIError` (provider side, assistant message with no parts). Driver now selects exactly GLM-5.3 (BC baseline); not exercised to completion.
10. `setup_active_or_unknown` immediately after the reinstall; the prep now waits for idle setup. An 11th run was stopped by the coordinator before it produced a receipt.

**Did attempt 4 show the app's idle pause stopping the server during a background turn? No (unknown for real behaviour).** It failed in `RuntimeTransaction.begin` at the first `/proc/net/tcp` read, before any fixture, prompt or background dwell existed. The server was down because the batch runner had just reinstalled the APK (cause 5, shown by the attempt 6 traceback and the later runs where starting the server after the reinstall removed the error). My "idle pause" guess was wrong and no turn was running. Whether the product pauses a server with a live turn after the app goes to the background is unmeasured: no row has run that scenario yet.

One unexplained observation: the demo/settings screens showed the banner "Background connection stopped for an unknown reason" after the reinstall/kill cycles. Treat as unknown until FQ9 background runs.
