responsive layout work; every supported remote action is reachable; native-only
actions never appear as dead buttons; and the browser-mode capability and

## Audit of browser-specific assumptions (current source)

| # | Assumption | Where | Effect in a browser before this slice | Now |
|---|---|---|---|---|
| 1 | "desktop" means a native window | `desktop_interaction.dart` (`isDesktop`) | A Linux/macOS/Windows *browser* reported `defaultTargetPlatform` = that OS but `isWeb` = true, so `desktopInteractions` was false: no shortcut layer, no right-click menus, no persistent scrollbars, no transcript selection, no file drop | `usesDesktopInteractions` = native desktop **or** desktop browser; window geometry, taskbar icon and release check still key off `isDesktop` |
| 2 | Ctrl/Cmd+N and Ctrl/Cmd+W are free | `shortcuts.dart` | Browsers reserve both (new window, close tab); a page cannot intercept them, and Ctrl+W closes the tab with the session in it | In a browser those two bind to Alt/Option; help sheet and command launcher print the live keys |
| 3 | Right-click has one menu | `context_menu.dart` | The page's `contextmenu` event also opened the browser menu on top of the app's | Browser menu is switched off only while a `ContextMenuRegion` is hovered (counted for nesting), so text fields keep the browser menu whose Paste works everywhere |
| 4 | A Paste button can read the clipboard | `servers_screen.dart` (pairing, password, Codex token) | `navigator.clipboard` is absent outside a secure context; the engine throws `Clipboard is not available in the context`, surfacing as a platform error, not "clipboard empty" | `supportsClipboardRead` = native or secure origin. Elsewhere the buttons are not built; pairing shows a sentence pointing at keyboard paste into the address field, which already recognises a payload |
| 5 | A password can always be saved | `servers_screen.dart` editor | `flutter_secure_storage_web` 2.1.1 throws `UnsupportedError` outside a secure context; `ProfileStore.upsert` rethrows it and the editor showed the raw text; `load` marks every profile as needing password re-entry | `supportsSecureCredentialStorage` = native or secure origin. The editor shows the reason from the first frame; passwordless servers still save |
| 6 | Codex can be offered anywhere | `servers_screen.dart`, `main.dart` root | The Codex transport sends `Authorization` on the WebSocket upgrade via `dart:io`; browsers cannot set upgrade headers and `dart:io` sockets are unsupported on the web. The chip, Test and Save all led to a raw failure; the root auto-connect failed on start | `supportsCodexConnections` = `!isWeb`. Chip disabled with the reason, Test/Save explain, list rows say so, the root shows the servers screen instead of connecting. OpenCode 1/2 untouched |
| 7 | Secure context is knowable | new | — | `PlatformCapabilities.secureContext` from `Uri.base` (https, file, or http on `localhost`/`*.localhost`/`127.0.0.1`/`::1`). The current preview host `http://100.126.15.6:8789` is **not** secure |
| 8 | Browser back | `home_screen.dart` | Already correct: the root `PopScope` returns to Workspace first; the second back reaches `SystemNavigator.pop`, which the web engine maps to leaving the page. Pushed routes pop normally | Covered by a test; no change |
| 9 | Responsive layout | `home_screen.dart` | Already width-driven (rail ≥ 760, dock below) | Covered by a test under browser capabilities; no change |
| 10 | Phone features | many, via capability flags | Termux, voice, read-aloud, photos, PDF, background service, notifications, widget, launcher shortcuts, tile, code push, USB bridge, QR scanning were already gated on `isAndroid`, which is false in every browser | Unchanged; the Browser mode page names them |

## Integration notes for coordinator-owned files

- `lib/feedback/bug_report.dart` — `bugReportPlatformLabel()` returns
  `'Web (unsupported)'`. Suggest `'Web browser (preview)'` once the mode is
  supported.
- `lib/ui/screens/about_screen.dart` — the identity branch falls to the
  desktop copy ("OpenCode for desktop", "A desktop client…") in a browser;
  wants a browser variant keyed on `platformCapabilities.isWeb`.
- `lib/ui/screens/guide_screen.dart` — `platformSecureStorageGuide` promises
  secure credential storage; on a non-secure origin that is false. Gate on
  `supportsSecureCredentialStorage` and reuse `browserEditorInsecureOrigin`.
- `lib/state/profiles.dart` — `secureStorageProblem()` probes only Linux and
  treats `UnsupportedError` (the web plugin's non-secure-context failure) as
  "not a keyring failure", so `upsert` rethrows the raw message. The editor
  now pre-empts this with its own notice, but the store could map that error
  to `SecureStorageUnavailable` with browser copy so a save attempt also
  reads as product copy.
- `lib/state/connection.dart` — `connect()` builds the Codex transport
  unconditionally; the UI now never calls it for Codex in a browser, but a
  guard on `supportsCodexConnections` returning `lastError` would close the
  remaining path (deep links, future sync).
- Transport (`lib/api/`, `lib/api2/`) — Dio and the SSE reader over Dio
  responses compile for the web; not verified live here. Codex
  (`lib/codex/transport.dart`) imports `dart:io` and stays unavailable by
  design. No query-token workaround was built.
- Web hosting: for the secure-origin path the served page must be https or
  reached as `localhost` (an SSH tunnel to the phone works: `ssh -L 8789:…`).
  The server must answer CORS for the page origin; the Browser mode page
  tells the user this.

## Unresolved limitations

- Shift+F10 / Menu key inside a hovered app region opens the app menu; if the
  pointer is elsewhere the browser's own menu may also open. Keyboard-only
  users see one extra dismiss. A page-wide `BrowserContextMenu.disableContextMenu()`
  would remove it at the cost of the browser Paste in text fields on
  non-secure origins; not taken.
- macOS browser: Option+N / Option+W may produce a dead-key composition in
  some layouts before the accelerator fires. Not verified on hardware.
- Chrome on ChromeOS reserves more accelerators (Ctrl+1..8 among them); the
  destination shortcuts may not reach the app there. Ctrl+K works.
- No real-browser proof exists in this slice; the table above is source
  reasoning plus the engine and plugin sources in the pinned SDK and pub
  cache (`engine/src/flutter/lib/web_ui/lib/src/engine/clipboard.dart`,
  `flutter_secure_storage_web-2.1.1`).
- The strings are English constants until the arb keys land.
