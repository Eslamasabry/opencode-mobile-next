# External A2A agents — implementation evidence

## Finish line

From a reachable External agents entry, inspect and save a supported agent,
explicitly submit text, follow progress and answer input on the same task,
review bounded results/artifacts, reopen the tracked task after app restart,
request cancellation with its actual outcome, and delete local agent/task data
and credentials.

Non-goals: hosting/SaaS, public listeners, provider use, automatic delegation or
context export, OpenCode project/file/terminal operations, implicit terminal-task
restart, and blind resend after uncertain delivery. The Codex account worktree
remains a separate preserved WIP to resume after this slice.

## Pinned feasibility choice

- [Official protocol release 1.0.1](https://github.com/a2aproject/A2A/releases/tag/v1.0.1),
  with its [tagged protobuf contract](https://github.com/a2aproject/A2A/blob/v1.0.1/specification/a2a.proto).
  Advertised wire version is `1.0`. JSON-RPC methods are `SendMessage`, `GetTask`
  and `CancelTask`; this is not the older `message/send` binding.
- [Official Python SDK 1.1.0](https://github.com/a2aproject/a2a-python/tree/v1.1.0),
  `DefaultRequestHandlerV2`, `AgentExecutor`, `InMemoryTaskStore`, official
  JSON-RPC and public Agent Card routes. No legacy compatibility mode.
- Dedicated agent surface; no fabricated `ServerGateway` capabilities.
  First subset: public cards, same-origin JSON-RPC endpoint, no authentication
  or explicit HTTP bearer. Unsupported versions, required extensions, binding
  and authentication combinations remain unavailable.
- Fresh polling through `GetTask` supplies progress/reopen. Input continuation
  retains the server task/context IDs. Returned URLs use the app's reviewed
  external-link path; no automatic artifact download or execution.

## Product implementation checkpoint

The Servers screen opens a dedicated External agents list. An inspected card
must support the pinned binding, text input and the narrow authentication subset
before it can be saved. Credentials use secure storage, are never attached to
card discovery, and never follow redirects. Only loopback HTTP is permitted;
other origins require HTTPS. Network reads have a size and time limit.

Each explicit send writes an unresolved local marker before dispatch. Lost
receipts have no automatic recovery by resend. Confirmed task IDs support fresh
queries on reopen and bounded foreground polling; input continuation retains the
same task/context and terminal tasks cannot implicitly restart. Cancel rechecks
the task and displays the actual returned state. Saved output is bounded text
and reviewed links, with omitted binary/structured content called out.

Separate agent identities use `oc.externalAgents`, `oc.a2aTasks.<id>` and secure
`oc.a2aBearer.<id>`. Delete agent removes all three through a recoverable tombstone;
it does not claim to stop remote work or erase the agent's copy. Removed records
cannot be recreated by late callbacks. No existing OpenCode profile format is
migrated. Native backups and the platform secure-storage limitations remain those
of the existing application.

## Coordinator draft-loss correction — verified

Review found that Back before Send retained only the 160-character row title;
reopening lost the full prepared text. The local task record now includes the
full unsent draft (at most 16,000 characters), persists review edits, and restores
it on route/store reconstruction. Back and Send wait for the latest edit to be
saved. A refused save keeps the editor open with retry guidance. A confirmed
send clears draft text; uncertain delivery remains non-resendable. Local task or
agent deletion removes the draft as part of the existing bounded record.

Regression source covers review/edit/Back/reopen, full-text reconstruction,
save-refusal Back/Send blocking and recovery, deletion and oversize refusal.
The save gate checks both content and the latest completed edit revision. A held
B→A write regression keeps Back and Send blocked while the editor again matches
the previously saved A, including the interval where disk has B and final A is
still pending. This prevents content equality from skipping queued persistence.
