## Lead audit

Workers had exclusive file ownership; only the lead ran Flutter checks. The
lead returned concrete defects in proposed patches before accepting them:

- The first installed-app run exposed premature share creation during saved-project
  restoration. Readiness guards and a regression fix that path; the full source
  gate was rerun for the corrected candidate.
- Export identity must be captured eagerly in `initState`, not via lazy fields.
- Mapping rollback must not restore deleted-profile data.
- Quota credential checks must stay salted and process-local; persisted rules
  retain the original origin identity and threshold markers. Reauthorizing one
  provider must not reauthorize the others.
- Failed notification dismissal retains retry bookkeeping until acknowledgement.
- Voice initialization publishes one complete current snapshot; a cancelled
  preflight cannot start or clear a newer operation.
- Recovery rollback and background permit completion respect the latest token
  and epoch.

No generated SDK source, provider account, signing secret or live Termux server
was changed. Draft/plugin storage formats remain compatible. Credential-change
retirement is based on changes observed by the running quota monitor; it is not
an account identity guarantee across unobserved changes or process restarts.
