# Web mode — 13 September 2026

Priority: ship the verified Android UI stabilization candidate. Web is a separate supported-platform slice, not a prerequisite for signing Android and not part of candidate `d49805e`.

Finish line: the real app can connect to supported remote servers in a browser, stream and recover sessions, preserve drafts/attachments through reload, remove profile data, and expose usable browser navigation. Native-only features must state their capabilities. Non-goal: a screenshot facade or a replacement demo application.

## Current runtime evidence

- Actual `lib/main.dart` compiles and boots on pinned Flutter 3.47.2 with `flutter run -d web-server --hot --no-web-resources-cdn`.
- Development link: `http://100.64.0.10:8789`; startup and existing demo navigation were checked in Chromium. The demo remains explicitly simulated; it is not server-connection evidence.
- The matching CanvasKit assets must be served locally; the public CDN does not serve this Shorebird engine revision. No browser security flags were disabled.
- `tool/preview/run_web.py` watches saved Dart sources and requests reload. On the integrated source, an active Chromium client applied two consecutive save-triggered reloads in 492 ms and 330 ms, preserving the browsing context and demo screen, with zero browser errors. Desktop (1280x900) and phone (420x900) captures were reviewed at `docs/qa/web-mode-2026-09-13/`. Earlier stale-client reload timeouts were resolved by a fresh development session; wider multi-client coverage remains pending.
- Browser authentication/storage needs a secure origin. The current Tailscale account rejected TLS certificate issuance. The maintainer was asked for the intended HTTPS hostname/reverse proxy. No insecure credential-storage fallback is acceptable.
