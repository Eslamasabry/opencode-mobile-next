# OpenCode Mobile 3.0.0+10030

Fixes for the update from 2.x, found on a real phone the day 3.0.0+10020 came out as a pre-release. It installs over 2.1.5 and over 3.0.0+10020 and keeps your data.

Change class: hotfix

**Migration.** Nothing to do. If you already updated to 3.0.0+10020 and "This phone" said "Not answering", it corrects itself the first time you open this build.

## What changed for you

- **This phone answers after the update.** OpenCode on the phone comes back by itself; you no longer need to tap Restart.
- **No crash on the first open after an update** when Android cannot bring the phone's server back.
- **AI Team and Memory are not called missing.** The note after updating names only what is really not in this version.
- **Connections list.** A server that is not answering says so on its own row, and you can always switch it off.

## Technical changes

### Fixed
- The "This phone" profile kept the Flutter app's address (port 4097) after the update while the native server listened on its own port. Only a manual restart rewrote it. The address is now moved on every refresh and on the first resume.
- A refused start of the phone server's foreground service stopped without showing its notification, which makes Android end the app. It now keeps the promise first.
- The migration census no longer reports AI Team and Memory as deferred; phones that already migrated stop showing them in the note.
- The connections sheet no longer raises "Could not change this list's connections" when a saved server refuses the connection, and its failure state uses the compact notice with one copy action.

## Known limits
- The crash fix closes the one path in the code that matches the crash recorded on the reporting phone; that phone's own crash trace was not available to confirm it.
- First published as a pre-release: neither 2.1.5 nor this app offers a pre-release as an update, so install it by hand from this page until it is promoted.
- About forty internal checks that compare the native app with the old Flutter source files still fail on this line. They do not describe app behaviour and are being re-pointed.
