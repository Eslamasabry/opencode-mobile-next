# OpenCode Mobile 3.0.0+10030

Fixes for the update from 2.x, found on a real phone the day 3.0.0+10020 came out as a pre-release. It installs over 2.1.5 and over 3.0.0+10020 and keeps your data.

Change class: fix

**Migration.** Nothing to do. If you already updated to 3.0.0+10020 and "This phone" said "Not answering", it corrects itself the first time you open this build.

## What changed for you

- **This phone answers after the update.** OpenCode on the phone comes back by itself; you no longer need to tap Restart.
- **No crash on the first open after an update.** A home-screen widget could end the app while it was still moving your data over.
- **AI Team and Memory are not called missing.** The note after updating names only what is really not in this version.
- **Connections list.** A server that is not answering says so on its own row, and you can always switch it off.
- **All your conversations show.** A server with more than about 150 conversations (sub-conversations count) lost the older ones from the list, and a long conversation stopped at its newest 150 messages. Both are read to the end now.
- **A stopped OpenCode on this phone says it is off.** The home and New conversation offer Start instead of waiting.
- **OpenCode on this phone updates itself.** A phone that came from 2.x with Claude Code installed stayed on the old OpenCode for good. It now moves to the version this app ships with, about two minutes after you open the app and only while nothing is working.
- **This phone stays connected after its server restarts.** After an update or Restart server the app could say "Not answering" until you reopened it.
- **Models with the same name are separate entries.** "Fast" and similar variants showed twice under one name and could not be picked; each now has its own name and can be chosen.
- **Claude Code installed before the update is recognised.** Agents on this phone shows it as installed and asks you to sign in, instead of offering to install it again.

## Technical changes

### Fixed
- The "This phone" profile kept the Flutter app's address (port 4097) after the update while the native server listened on its own port. Only a manual restart rewrote it. The address is now moved on every refresh and on the first resume.
- A widget refresh that arrived before the one-time migration had finished read the saved settings early; the store threw (its test-build rule was active in release builds) and the app ended. Release builds now count such a read and answer it, and no widget callback can let an error out.
- A refused start of the phone server's foreground service stopped without showing its notification, which makes Android end the app. It now keeps the promise first.
- New conversation did nothing while its server was opening or not answering; it now says so and offers the way forward.
- Conversation and message pages asked for by cursor came back 50 rows long, which the app read as the last page: lists ended after 150 rows. The page size is now sent with every cursor (OpenCode 2.1.1 and 2.2.6 honour it).
- After Stop OpenCode on this phone the home kept reading "Connected" and New conversation waited without end; the stop now closes the connection and both offer Start.
- The automatic OpenCode update was never started, and once it was, every setup job (update, Repair, Add tools) was refused on phones whose last saved job was the Flutter app's agent install: its owner group in setup.json was validated as a setup parameter. The group is dropped when the saved job is read.
- The phone server moved to the next port on every restart (4098, 4100, 4102): the port check bound without address reuse, which Linux refuses for about a minute after a server with an open connection stops. The check now binds the way a server does; a port another program listens on is still refused.
- The model list keyed entries by the upstream model name, which several catalog entries share; it now uses each entry's own id for the list, the selection and the server default.
- A release build writes one log tag to logcat while a tester has switched that tag on (`adb shell setprop log.tag.OcAutoUpdate DEBUG`); otherwise nothing is written, as before.
- A typed home path in the project path dialog was refused without a word; it now says why.
- Privacy and data showed a stray backslash before apostrophes.
- The migration census no longer reports AI Team and Memory as deferred; phones that already migrated stop showing them in the note.
- The connections sheet no longer raises "Could not change this list's connections" when a saved server refuses the connection, and its failure state uses the compact notice with one copy action.

## Known limits
- First published as a pre-release: neither 2.1.5 nor this app offers a pre-release as an update, so install it by hand from this page until it is promoted.
- About forty internal checks that compare the native app with the old Flutter source files still fail on this line. They do not describe app behaviour and are being re-pointed.
