# OpenCode Mobile 2.1.0+57

This release adds two home-screen widgets, Git inside the conversation, an Inbox for everything that waits on you, and a new Appearance with five styles. The chat is calmer while an agent works, with one Stop that is always in the same place. Many replies that used to stall, fail or show the wrong state now behave.

**After you update:** everyone starts on the Solid style with the moving background off. To bring a background back, open Settings › This app › Appearance and pick one under "What moves behind your pages?".

Change class: feature

## What changed for you

- **Two home-screen widgets**, Conversations and Status, that put what needs you first.
- **Git in the chat**: tap the branch to save the files you ticked and send them to GitHub.
- **Inbox** lists everything that waits on you, with **one Stop** always in the same place while a reply runs.
- **A new Appearance** with five styles, one question at a time; you start on Solid with the background off.
- **Simplified Chinese** now covers about 92 % of the app (thanks @Azx8788, #107).

## Technical changes

### Highlights

**Two new home-screen widgets: Conversations and Status**  
Add Conversations (4×2) or Status (2×2) from your launcher's widget list. Conversations puts what needs you first; Status shows your servers, this phone and the plan limit closest to running out.  
_For: anyone who checks on agents without opening the app. Accessibility: Lines are read as shown; every tap target is 48dp and Allow and Reply are read as buttons._

### Chat

**Stop after this step**  
Hold Stop, or tap the live line and choose Stop after this step. The agent finishes the step it is on; the line reads "Stopping after this step · Undo".  
_For: when you want a clean stopping point instead of cutting a step in half. Accessibility: Screen readers get a Stop after this step action; the ring is still under reduced motion._

**A command that runs too long says so**  
A command still running after 15 minutes reads, for example, "git add -A · still running after 2 h 29 min, may be stuck", with Stop on the same line. For agents that cannot take a message mid-reply, Send offers Stop and send.  
_For: anyone whose agent hangs on a command. Accessibility: The stuck state is said in words, not only in amber._

**Work still running in the background is shown**  
After a Claude Code turn ends, a quiet line under it says what is still running, such as a build, and for how long. Tap it to see each task and go to the step that started it.  
_For: Claude Code users who start builds or servers. Accessibility: One tappable line with a spoken label; respects reduced motion._

<img src="https://raw.githubusercontent.com/Eslamasabry/opencode-mobile-next/master/docs/releases/v2.1.0%2B57/img/bgline.jpg" width="300" alt="A chat where Claude started npm run build and then said the build runs in the background; under the turn a quiet line reads Still running in the background · npm run build · 2 min.">

**Send later, or repeat, from a long press on Send**  
Hold Send to open scheduling with your words and this conversation already filled in. A normal tap still sends.  
_For: anyone who wants a prompt to run later or every day. Accessibility: The menu is exposed as a screen-reader action; a tap still sends._

<img src="https://raw.githubusercontent.com/Eslamasabry/opencode-mobile-next/master/docs/releases/v2.1.0%2B57/img/sendlater.jpg" width="300" alt="The New scheduled prompt sheet opened by holding Send: the typed request already filled in, Once selected, Tomorrow at 9:00 AM on the wheel, the weather-app conversation, and a Schedule for tomorrow, 9:00 AM button.">

**"No model signed in" before your first message**  
When no model is signed in, a quiet line at the top of a new conversation says so and links to Sign in.  
_For: new users and anyone whose sign-in expired. Accessibility: ok._

<img src="https://raw.githubusercontent.com/Eslamasabry/opencode-mobile-next/master/docs/releases/v2.1.0%2B57/img/nomodel.jpg" width="300" alt="A new, empty conversation with a quiet line at the top reading No model signed in · Sign in, starter chips, and a Sign in to a model chip above the message box.">

**A calmer chat while the agent works**  
You see the conversation, one live line such as "Writing index.html · 12 s", and the message box, which reads "Steer while it works…". The header is the title with the project and branch, each tappable.  
_For: everyone who watches a reply run. Accessibility: ok._

**Stop is one button in one place**  
While a reply runs, Stop sits at the end of the row above the message box, whether the field is empty or you are typing. The model chip and the approval chip, which reads Auto-approve on or Ask first, stay beside it. Stop turns amber and says so if a step looks stuck.  
_For: anyone who stops replies. Accessibility: 48dp, named Stop plus the agent; the amber state also changes the words._

**Requests name the action, its target and what it touches**  
A permission card reads, for example, "Run flutter test?" with the exact command, Reject and Allow once, and "Always allow flutter test" underneath. A request outside the project says write, read or run, with the exact path.  
_For: anyone approving agent actions. Accessibility: ok._

<img src="https://raw.githubusercontent.com/Eslamasabry/opencode-mobile-next/master/docs/releases/v2.1.0%2B57/img/permcard.jpg" width="300" alt="A chat asking Run npm install in neon-breaker? with the command npm install, a Reject button, a green Allow once button and Always allow npm install underneath.">

**Model picker starts with three plain choices**  
Tap the model chip: In use, Default and Recently used come first, and All models is one tap further, with details and favourites.  
_For: anyone who switches models. Accessibility: Choices are text rows._

<img src="https://raw.githubusercontent.com/Eslamasabry/opencode-mobile-next/master/docs/releases/v2.1.0%2B57/img/modelpicker.jpg" width="300" alt="The Model sheet over a weather-app chat: In use GLM-5.3-Flash Free with a check, Default Big Pickle · Free, Recently used Beam Free, and All models (8).">

**The message box is easier to live with**  
Once your words pass one line, the field takes the full width. Notes above the box wrap, stay until something changes and can be dismissed. A stopped reply says "You stopped this reply." in the footer and the chips offer Try again, and a short reconnect after you come back no longer shows a warning.  
_For: everyone. Accessibility: Readable at large text._

**Steps say what ran**  
A step that only ran tools is titled with each tool and its command, such as "Shell · uptime", instead of "Tools: Shell".  
_For: anyone reading what the agent did. Accessibility: Text only._

**The connection line says when it tries again**  
When a server stops answering, a quiet line such as "Laptop isn't answering · trying again in 12 s · Try now" shows in the chat, Conversations and the Terminal. Details can restart this phone's server or an agent's helper.  
_For: anyone on a patchy connection. Accessibility: One caption line, not colour alone._

**Preview fills the screen, with one Ask for a change field**  
The in-app preview of your running app fills the screen under a slim bar titled Preview. A field at the bottom sends a change request to the conversation it came from; the address and logs are under Details.  
_For: anyone building web apps. Accessibility: ok._

**Smooth, short motion**  
Reply words fade in and the reply grows smoothly, work steps fold open and shut, your sent message lifts out of the box, and a conversation grows out of its row and shrinks back. A caret follows the words as they are written.  
_For: everyone. Accessibility: Instant under reduced motion; with Animations set to Calm, things only fade._

**Faster with long conversations, lighter on the battery**  
Long Claude Code and Pi histories load without freezing the screen, the chat and Conversations list stay smooth while replies stream, and the phone's server does fewer repeated checks and wakes faster.  
_For: anyone with long-running conversations. Accessibility: no screen change._

**The first message after an idle hour no longer fails**  
On OpenCode 2 it could fail with "The request could not finish". The app now waits for the server to wake up.  
_For: anyone who comes back after a break. Accessibility: no screen change._

**A running reply no longer looks finished between steps**  
On OpenCode 2 the chat briefly showed the mic, the idle chips and a finish buzz in the middle of a turn. It now stays running until the turn ends.  
_For: OpenCode 2 users. Accessibility: no screen change._

**The chat catches up after sleep or a reconnect**  
A reply cut short while the phone slept is read again, a permission request the live link missed still reaches you, and a tool result keeps its name instead of showing as "Tool".  
_For: anyone who locks the phone during a reply. Accessibility: no screen change._

**Stopped and failed replies say what really happened**  
"You stopped this reply" appears only when you stopped it here, a cut-off step reads Stopped instead of a raw error, a Claude Code turn that ended on a network error reads as stopped, and a reply that hit a model's usage limit says so and suggests another model.  
_For: everyone. Accessibility: Plain words._

<img src="https://raw.githubusercontent.com/Eslamasabry/opencode-mobile-next/master/docs/releases/v2.1.0%2B57/img/usagelimit.jpg" width="300" alt="A chat where the question Can you draw the refund flow as a list of steps? is marked Not answered, followed by This model's usage limit is reached for now, a hint to choose another model or wait, and Choose another model and Details buttons.">

**A failed send says why and gives your words back**  
A message that did not send shows "Didn't send" with Try again and the reason in plain words.  
_For: anyone on a weak connection. Accessibility: ok._

**Sending is dependable**  
A quick second tap on Send no longer lands on Stop, your new message and its reply stay in view, a message sent just after waking waits for the connection and goes out once, and Stop can cancel a send that has not left yet.  
_For: everyone. Accessibility: no screen change._

**Long tool runs no longer break the reply**  
With Auto-approve on, tools no longer end in interrupted replies on the phone's server, and a message you add while a long tool runs no longer makes the reply look dropped or restarts the live line's clock.  
_For: anyone who lets agents run or steers them. Accessibility: no screen change._

**Chips and model names read in full**  
Chips no longer cut words like "Runnin", a long model name ends in an ellipsis instead of squeezing Ask first, the model chip shows the model's name rather than its id, and the default-model note follows your choice.  
_For: everyone, especially at large text sizes. Accessibility: Text no longer cut._

**Conversations draw correctly**  
No "Thinking…" above a waiting question and no Copy button with nothing to copy. Hidden HTML comments no longer show, a line indented under a list item stays in it, letter tails on the newest line are no longer clipped, a compacted conversation no longer shows an error row, messages between agents read as messages, and Read aloud skips replies with no words.  
_For: everyone. Accessibility: no screen change._

**A reopened chat is steady from its first frame**  
The chips and agent are there at once, the Git chip names the branch straight away, and the preview text in the list is up to date.  
_For: everyone. Accessibility: no screen change._

**Phone agents' requests show once and only offer what works**  
A phone agent's command is no longer shown twice, Always allow appears only where the agent can keep the rule, a sub-agent page no longer shows a Stop that did nothing, and older copies of one conversation are archived with their title kept.  
_For: anyone using Claude Code or other agents on the phone. Accessibility: no screen change._

**Scheduling keeps what you typed**  
Swiping away from Scheduled prompts no longer loses your prompt, and a schedule for an existing conversation keeps its agent.  
_For: anyone using schedules. Accessibility: no screen change._

### Conversations and Search

**Inbox**  
One list of every request waiting on you across servers, projects and phone agents, oldest first, with how long each has waited. Questions open their conversation. Open it from "2 need you" under the Conversations title.  
_For: anyone running several agents. Accessibility: Reject and Allow once reuse the chat's buttons with an Undo window._

**Search opens on a "Go to" list**  
Before you type, Search lists places you can jump to, such as Needs you, Files, Projects, Settings, Servers, Terminal and Help, then your recent conversations. Only places your connection supports are shown.  
_For: anyone moving around the app. Accessibility: ok._

**No bottom bar on phones**  
Conversations is the home. The top bar has the server, Search and a Settings gear; a project's Files open from the conversation's project chip, the + sheet or Search. Tablets and computers keep the side rail.  
_For: Phone users. Accessibility: 48dp round buttons._

**Calmer notices and empty screens**  
Restart, phone-is-hot and plan-limit notices on Conversations are one quiet line with their action. Empty screens show one plain line and the next step.  
_For: everyone. Accessibility: The screen-reader label keeps the time and cause._

**A readable column on tablets, computers and landscape**  
On wide windows, conversations, lists, sheets and controls stay in a centred column instead of stretching edge to edge.  
_For: tablet, foldable and desktop users. Accessibility: Request buttons scroll at 2× text._

**Finished and stopped runs show the right word in the list**  
A finished OpenCode 2 run no longer stays Working until you refresh, a reply you stopped reads Stopped rather than Done, and a phone agent stopped mid-turn settles.  
_For: everyone. Accessibility: no screen change._

**The Conversations list holds still while it opens**  
On a cold start, loading lines and notices no longer push rows down, the Running filter no longer flashes placeholders, and the restart notice folds when you change page, not under your finger.  
_For: everyone. Accessibility: The loading label is still announced._

**Old agent chats no longer jump to Today**  
Reading or refreshing an idle agent chat no longer moves it to the top as "Done · Just now" or starts a process for it.  
_For: Phone agent users. Accessibility: no screen change._

**Load failures name the connection and retry it**  
The quiet line names the connection that failed, Try again retries that list, and "Phone agents couldn't load" and a sign-in nag for agents that cannot chat no longer appear on their own.  
_For: anyone with several connections. Accessibility: no screen change._

### Git

**Git sheet from the branch in a conversation**  
Tap the branch under a conversation's title. Get the latest changes, see and tick changed files, and "Save 2 files and send to GitHub · main" in one tap, or save without sending. Write it for me drafts the summary, and Ask the agent to fix conflicts helps when changes clash. Remotes and GitHub sign-in with a code are on the same sheet.  
_For: anyone who commits and pushes from the phone. Accessibility: Rows and buttons are labelled; the second button is full width and 48dp._

**Review changes starts with one sentence**  
The changes screen opens with the agent's summary and "3 files changed · +42 −8". Each file is a folded row with the first one open. Looks good approves; Send back is a button that leaves a note in the chat.  
_For: anyone reviewing agent work. Accessibility: Send back is a real 48dp button._

### Files

**Markdown changes are shown as formatted text**  
A changed .md, .markdown or .mdx file is drawn as formatted text with its + and − marks in the chat, in Review changes and on the permission sheet.  
_For: anyone whose agent edits docs and notes. Accessibility: + and − marks mean the tint is not the only signal._

**Files shows just the files**  
Files has a large title, the project and one row per file or folder. Changed files get a dot and say Modified or Added. Opening a file shows line numbers, and you can ask about it.  
_For: anyone browsing a project. Accessibility: Change state is spoken as words, not colour alone._
