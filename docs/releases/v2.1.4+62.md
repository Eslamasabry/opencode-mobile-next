# OpenCode Mobile 2.1.4+62

This release gets the phone's built-in Linux set up on phones where its
unpacking tool crashes (issue #117), adds making and publishing a GitHub
repository from the Git page (#118, thanks @Ari-Enzo), and makes the app
Android only.

Change class: feature

## What changed for you

- **Built-in Linux sets up even when its tools crash** (issue #117). On some
  phones, tools inside the built-in Linux crashed during setup, first the
  download tool (fixed in 2.1.3) and then the unpacking tool, and setup stopped
  at Node.js. Now:
  - when unpacking crashes, the app unpacks the file itself. The file is still
    checked against its pinned checksum first, and nothing can be written
    outside its folder;
  - any setup step that crashes is tried once more in a compatibility mode,
    and its row says "Trying again in compatibility mode";
  - the built-in Linux layer (proot) is updated to a newer build with fixes
    for this kind of crash on 64-bit ARM phones.
- **Start a Git repository and publish it to GitHub** (#118, by @Ari-Enzo). On
  the Git page, Initialize turns a project folder into a Git repository (first
  branch `main`). When you are signed in to GitHub, Publish to GitHub creates a
  new repository, private by default, with a name GitHub accepts, and connects
  it as the project's remote.
- **Android only.** The experimental Linux and Windows desktop builds are no
  longer made or attached to releases.

## Technical changes

**Unpack fallback and compatibility retry**  
`oc_untar ARCHIVE DEST STRIP [MEMBER]` runs tar; when tar dies from a signal
(exit 128 or more) the script asks the app with `::oc unpack`, and
`SetupAppUnpack.kt` unpacks the checksum-verified `.tar.gz` with its own reader
(files, directories, symlinks, mode bits, long names, strip count, one named
member; absolute or `..` paths and writes through an escaping link are
refused). Used by the Node.js, OpenCode, AI Team and Paseo Node.js steps. A
step that ends with exit 139, or fails after "Segmentation fault", runs once
more with `PROOT_NO_SECCOMP=1` and `GLIBC_TUNABLES=glibc.pthread.rseq=0`, from
a clean `.new` folder. Emulator proof with a deliberately crashing tar, and a
from-scratch setup on the new proot:
[docs/qa/issue-117-unpack-2026-11-06](../qa/issue-117-unpack-2026-11-06/README.md).
_For: anyone setting up built-in Linux. Accessibility: no new screen; the step
row and Details use plain words._

**Security: app downloads and unpacks stay inside built-in Linux**  
Found in a pre-release review. The app-side download (2.1.3) and unpack
(new here) checked that the requested folder was inside built-in Linux, but
followed a link placed at the target itself, and the handshake files too.
Code running inside built-in Linux during setup could therefore have had the
app write into its own private storage. Now a target or marker that is a link
is refused or replaced, never followed. A hard link in an archive cannot copy
a file through a link. Steps that run as the agent user may only ask for
`/home/oc/` and `/opt/oc-claude/`. Kotlin tests cover each case.
_For: everyone using built-in Linux. No screen change._

**proot 5.1.107.102**  
`tool/builtin_linux/fetch_proot.sh` pins proot 5.1.107.102 (was 5.1.107.94)
and libtalloc 2.5.0 for both ABIs, with SHA-256 from the Termux package index.
This is a native change, so 2.1.4 is a full Shorebird release, not a patch.

**GitHub publish**  
`GitHubDeviceFlow.createUserRepository` calls `POST /user/repos` with the
signed-in token (already `repo` scope, so no new permission). A 422 reads as
"name already taken" only when GitHub says `already_exists`; a missing token
asks you to sign in again. Initialize runs `git init -b main`.
_For: anyone who keeps projects on GitHub. Accessibility: kit rows and sheets,
English and Arabic copy._

**Desktop dropped**  
Removed the `linux/` and `windows/` targets, the desktop workflows,
`scripts/package-linux.sh` and its tests. Desktop-only code in `lib/` is left
for a later clean-up.
