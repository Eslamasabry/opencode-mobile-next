# OpenCode Mobile 3.0.1+10130

**If you use coding agents on your phone, this update offers newer versions of them (Claude Code, Codex, Antigravity and others; about 680 MB for the three most used). The app asks before it updates them and shows the size; on mobile data it says so and waits for your yes.**

This update replaces 3.0.0 in place and keeps your data. It brings newer agents on the phone, a calmer conversation page and a long list of fixes found on real phones.

## In short

- **Newer agents on your phone.** Claude Code 2.1.330, Codex 0.171.0, Antigravity 1.5.13, Qwen Code 0.28.0, Goose 1.60.2, fx 0.0.17 and Kilo 7.8.32. Before they update, the app asks you first.
- **Big downloads ask first on mobile data.** They wait for Wi‑Fi, or ask you, and one yes covers exactly the parts the question named.
- **A floating conversation.** One header capsule, the message box over the words, and the waiting page in the same frame.
- **Your own Stop is respected.** After you stop OpenCode on this phone, Home and your conversations say so, with a Start OpenCode button and no countdown.
- **The Edge light is the one switcher.** Its panel reaches the top of the screen, and its rows stay put when a request arrives.
- **Two more languages.** Japanese and Italian, and the language list shows each language with its flag.
- **Fewer crashes and stalls**, and nothing cut on narrow screens in the places we found.

## New

- Each action has its own small vibration, so a touch answer tells you what it did.
- Usage reports, if you share them, also reach this app's own report server, on the same switch.
- Copying is marked: replies and code copy as ordinary text; secrets and terminal output stay protected.
- The Thinking choice stands first in every model sheet.
- The message box records dictation itself.
- The Voice conversation row says what it needs, and tapping it starts the set‑up.
- An agent's sign‑in page ends by confirming the sign‑in worked.
- Waiting marks come in ink or in colour, as you choose.
- Home shows a running agent update as its own line, naming the part that is really downloading, with its progress.
- A file named in a reply becomes a chip when it really is a file in this conversation's folder.
- A message's menu opens on its own bubble, and the page dims behind it.
- The agents' helper starts sooner on the phone.

## Fixed: sending and reading messages

- Plan mode keeps a conversation read‑only on Codex too.
- Reply headings are sized by their level.
- Back returns to the exact line you were reading.
- A reply no longer looks stuck running after the connection drops and comes back.
- The keyboard's Enter key makes a new line in the message box.
- The waiting line keeps moving while the connection is live, and a stopped turn says the real cause.
- When an agent's sign‑in has run out, the turn says so, with one Sign in again button.
- After you sign in again, the stopped turn no longer asks you to sign in.
- The model chip in the message box is one line and names the effort once.
- A message already sent can no longer be typed over.
- A waiting approval stays visible instead of folding into Stopped.
- Sending a message no longer pulls the list back to the waiting card.
- A step reads unanswered only when it truly asked and was never answered.
- A turn shows Needs you when one of its sub‑agents waits for your answer.
- Messages waiting to send survive a restart; a restored message whose reply had ended reads Not confirmed yet.
- The two‑column change view keeps both halves and wraps long lines.
- A send refused while an undo waits says why, and the undo stays reachable.
- The undo pages say only what is settled, and in a folder without Git they speak of messages only.
- Open parent and Continue in a new conversation work inside a sub‑agent's chat.
- A conversation's first message shows once, not twice.
- A conversation reopened mid‑reply waits for the live answer before it shows.
- An older agent conversation waits for the real start before it gives up.
- A file link in a reply opens the file; a file outside the project says so plainly.
- A retry notice stays on screen between attempts and leaves only when real output arrives.
- Each reply's footer shows that reply's own time, and keeps it when you read the conversation again.

## Fixed: on this phone (set‑up, updates, agents)

- After Linux is unpacked, the app checks that it answers and switches to a compatibility mode if it does not.
- Usage shows the same sign‑in state as the agent's own tile.
- Home says why the phone's OpenCode update is waiting.

- A waiting update no longer spins, and no false "failed to start" flash appears while a download waits.

## Fixed: notifications and the Edge light

- The notification's Stop stops at once and really stops; a stop that fails says so in words.

## Fixed: crashes

- Fixed crashes around closing a server connection, a very large file, the sign‑in page, Android's background time limit, a stalled save, an accent key in the terminal, and a text field's Copy or Paste popup.

## Known in this version

These are known and planned for the next update.

- **Agent updates on mobile data after a restart.** If the app restarts before an agent update starts on mobile data, or a download drops, Home says the update is waiting for Wi‑Fi and offers no button. Connect to Wi‑Fi and the update starts by itself.
- **Sub‑agents that still say Working.** After the app restarts, the sub‑agents of a Claude Code conversation can still say Working, with Stop buttons. Nothing is running; the fix is coming.
- **A stopped text reply reads Done.** A text reply that you cut by stopping OpenCode on this phone can read Done instead of stopped.
- **A stopped server at launch.** Right after the app opens, a server you stopped can look connected for a moment before it shows as stopped.
- On mobile data, agent updates you agreed to start one at a time; on Wi‑Fi they all run by themselves.
- After a dropped connection, the retry notice appears in two steps.
- A "Thought" row can appear above a reply that has already started and push it down one line.
- While your first message sends, the model chip can lose its name for a few seconds.
- On Home, a conversation's picture can be missing for a moment when it arrives, and a saved draft can appear a moment late.
- A request's Allow and Deny can move when the card above them lands.
- A title or label can show twice for a moment while a sheet opens.
- A tip can sit over the text you are reading.
- A sheet or menu that is open in a conversation closes when you rotate the phone.
- On a tablet, opening the keyboard can make the "notify you" row vanish and the conversation jump.
- On wide windows, a sheet's buttons move when a "not enough room" note appears or goes.
- On a phone‑width screen, the file review page cuts its action labels and breaks a long file name mid‑word.
- When Linux cannot start at all, set‑up shows a general error instead of saying this phone can't run it.
- Settings has two names for one page: the row "Notifications" opens "Notifications and background".
- The agents page's status line names only one agent after several were updated.
