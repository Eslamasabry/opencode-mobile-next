# OpenCode Mobile 3.0.0+10060

This build covers what was found and corrected since 3.0.0+10030 on real phones: a clearer step list in conversations, a New conversation page that says where it will run, phone storage for the phone's agents, and a long list of fixes for agents on this phone. It installs over 2.1.5 and over 3.0.0+10020 and 3.0.0+10030 and keeps your data.

Change class: feature

**Migration.** Nothing to do. After the update the phone brings its installed agents up to the versions this app ships with by itself, while no agent is working and not on metered data; the Agents page says what it is doing, and a conversation of the phone's agents opened meanwhile waits and says the agents are updating. The 3.0.0+10020 notes still apply to people coming from 2.1.5 (computers need OpenCode 2, 64-bit phones only, Chinese and Japanese not offered yet).

## What changed for you

### Conversations
- **A turn's work is one list of steps.** The summary work line and the separate Thought fold are replaced by one step list: a turn that ended well is one row that opens in place, a running turn shows its newest rows, and a failed, waiting or stopped turn stays open at that step. Older rows fold behind one row that names what was declined or failed, and sub-agents that ran together are one group.
- **Steps read as plain words.** A command is named by what it ran (tests, a build, a search, a read, git), commands one after another fold into one run, each kind has its own larger glyph, and the agent's words between steps are whole and quieter than the steps.
- **Steps arrive in one movement.** A new step and the rows that fold behind it move together, an opened run's steps stand inside it, and a row you tapped stays under your finger.
- **A running command shows itself.** It opens by itself, has its own clock that starts after your decision, says "No output" when there is none, shows its failed and stopped words, and keeps its output readable under its step while it runs and afterwards. The live line keeps its height while steps arrive.
- **Answer a waiting permission under its step.** The approval card shows the command, and the message box stops saying it waits once you have decided.
- **The reply's footer is quiet** and says when, how long, which model, tokens and cost where the server has them.
- **Running work is always findable.** The conversation's menu always lists it, the background line opens a list of tasks, commands and sub-agents (including Claude Code's background tasks), and the list says in words what a server cannot do. Send to background now works on OpenCode 2.
- **A conversation that is loading shows it,** in every style: a placeholder that breathes, words after a second, and the message box drawn while it loads (only Send waits).
- **A reopened conversation tells the truth from its first frame.** A declined step no longer reads as stopped, and an edited file keeps its card, in the seconds after you reopen.
- **A reply or code block is no longer left half drawn,** and a failed send's Details and Try again line up with its text.
- **Find never shows another search's matches,** and says "Searching..." until the matches arrive.
- **A conversation opens with the ordinary page transition** and shows your message at once, without placeholder rows, a "Model" placeholder or a keyboard that drops and comes back; the header names the conversation from the first frame.
- **A long conversation stays smooth.** A streaming reply costs the same after 20 turns or 1,000, and scrolling a conversation or the home list no longer redraws page-sized layers on every frame.
- **Plan on the phone's agents.** Plan reaches each agent as its own read-only mode, Codex from the first turn, and Plan is offered only to agents that can hold it. The message box no longer shows raw mode names.

### New conversation
- **It says where it will run.** Under the title one line names where the conversation will run and opens the project sheet; one chip in the foot of the message box names the agent and model. The hint, phrase chips and notices scroll below the box while Start stays pinned.
- **It opens on your last setup,** Start no longer waits on loads, and a saved draft's opening always ends, with a plain line if the draft could not be opened.
- **A control that cannot be used says why when you tap it.**
- **A notice that blocks starting puts its action where Start was,** is brought into view when the keyboard comes up, and menus keep out of the keyboard. Start on an empty box focuses the box instead of showing a message.
- **A tap on + while the app is still opening is kept:** New conversation opens as soon as the server answers, and Home offers "Cancel New conversation".
- **Start from a sentence.** "New project" is offered right on the page when a phone agent has no project, and the chooser words an agent that is set up at first use the way the Agents page does.
- **Your own agents are in the list,** and an installed agent that still needs something stays there with what it needs.
- **A signed-out agent reads "Sign in needed"** and the placeholder for the phone's own agent names Antigravity. "Add a server" waits until your saved connections are read.

### Phone storage and projects
- **Phone storage is offered.** The project chooser, the project sheet, Home and Files have a Phone storage row that opens Android's file-access page, and says what agents can do once you allow it. A folder list shows the folders inside it.
- **A folder you choose is really used.** It is bound into the phone's Linux and checked from the agent's side before anything starts, stays visible to the phone's agents after one restart, and shows that the restart is working. A new folder inside phone storage says so, and a folder you just made no longer reads as missing from the server.
- **One restart covers both sides.** When the phone's agents and its OpenCode both started before you chose the folder, one restart makes it visible to both, and it waits for a running reply instead of cutting it.
- **The phone's OpenCode is checked before Start,** and an open conversation says when its phone-storage folder can no longer be reached. The page says once what that storage cannot do.
- **Git works there.** A repository in phone storage is set up for the conversation, and Git trusts repositories one level inside the chosen folder.
- **A folder in phone storage counts as a project.**

### This phone and agents
- **Agents are on their latest versions, updated by themselves.** Claude Code now offers Fable 5.2 and Mythos 5.2; Codex, Goose, Oh My Pi, Qwen Code, Kilo, Antigravity and fx moved to newer versions. OpenCode 2 stays on 2.2.6 for now.
- **An update survives the phone stopping the app.** It picks up where it was cut off on the next start, and no longer crashes that start.
- **The home says when agents are updating,** the connections chip names what is starting, and a source the app is starting takes a tap and keeps its rows in Recent. A tap on a row that cannot open yet is kept, and the row says Connecting.
- **A normal start never reads "couldn't load."** A conversation on This phone keeps loading while the phone's OpenCode is starting, updating or not connected yet, and opens by itself; the failure page is for a real failure after 90 seconds. The home no longer says "No conversations yet" before the server answered.
- **The app starts the phone's agents itself and keeps trying.** A refused start asks the helper to check again, an agent that was refused is checked again, and a turn lost to a helper restart says so instead of reading as finished.
- **Signed-out is said once and the same way everywhere.** A lapsed sign-in reads "Sign in needed" in its conversation and on its Home row; an agent has one status in the three places that show it; an agent older than this app's version counts as behind.
- **A usage limit is never shown as signed out.** Claude Code at its limit shows the usage-limit words with the reset time; a check that could not finish reads "Sign-in not confirmed" with "Check <agent> again"; the tile, the chooser, Usage and Home agree; and Claude Code conversations open with their history.
- **Codex on the phone can run commands,** and asks before every command and every file change.
- **Antigravity carries on after a command it left running.** The app asks it once to wait and continue.
- **Old agent conversations open again.** A saved Claude Code conversation on This phone opens, a phone agent's conversation opens to read after a restart, and continuing hands over what was done. Reading earlier conversations never starts their agents.
- **Your own agent and provider.** Add your own agent, use your own provider with Claude Code, and add a provider endpoint the catalog does not list; a "How this works" sheet explains it. Eight languages.
- **Linux pages end.** Storage, Packages and Installed show numbers or a plain line with Try again instead of waiting for minutes, and a set-up Linux that is slow says it is taking a long time to answer.
- **Setup shows one progress bar** for the whole setup and counts the whole download.
- **Search covers the phone agents' conversations** by title and message text, and each hit opens on its own connection.

### Git and files
- **Git, Changes and Preview work for a phone agent's project.** The Git page leads with what changed, a committed file's change opens, a recent commit opens what it changed, and Preview has a bar and a plain page when it fails.

### Scheduled prompts
- **A scheduled run no longer spends another server's time,** and says "replied" only when the server did reply.

### Home
- **The saved rows of the phone's agents keep their agent and folder,** so a row no longer shows the OpenCode mark and old details.

### Settings and first run
- **The usage-sharing question waits for your first finished reply,** instead of being the first screen on a fresh install. The star question waits for three days and ten replies and shows only when you are at rest.
- **The edge light steps aside under any sheet or menu.**
- **The edge light's list** shows real ages, clears its header, and brings hidden conversations back with "Show again".
- **Review's main button says Done,** and the model list shows the server's default model on that provider's page.
- **Phones stay upright on every screen.** Below 600 dp wide the app stays in portrait; tablets and unfolded foldables still rotate.
- **Narrow phones.** Buttons wrap instead of being cut, sideways rows show that they scroll, field hints wrap, Appearance's tabs and Home's chips rest on a whole item, the agent grid is one column at 360 dp, and row values wrap.
- **The privacy notices say what the app really sends.** Settings > Privacy and data names every event and field the optional reports can send, in every language, and the website and store text match it.
- **Home's top area paints no pane** in any style.

### Glass
- **An untouched Glass page comes to rest** instead of redrawing every frame.

### Languages
- **New lines are in all eight languages** (English, Arabic, Spanish, French, Indonesian, Portuguese, Russian, Vietnamese), including the step list, the agent updates and sign-in, phone storage, own agents and the new New conversation lines.

## Under the hood
- A release now needs a passing CI verdict and a device smoke for the same commit, and the ignore list can only shrink.
- Quality checks run on every fast CI run in eight shards, and a failing run reads red.
- The app's own `llms.txt` lists only documents that are true for the native app, and a check keeps it current.
