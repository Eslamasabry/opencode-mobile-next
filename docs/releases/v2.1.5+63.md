# OpenCode Mobile 2.1.5+63

Draft, not released. This release adds Spanish, removes the Termux app
integration, makes Node.js setup adapt on phones where it crashed, and adds
optional usage and app health numbers and crash reports, in two switches that
stay off unless you turn them on, and a way to send a problem report you review
first.

Change class: feature

## What changed for you

- **Spanish** (#122, thanks @Lxchoooo). The whole app is translated. The
  language picker no longer says "Partly translated".
- **Termux is no longer used.** Built-in Linux is the only way to run an agent
  on the phone itself; you can still connect to an agent on your computer. If
  you set up the app with Termux before, the app tells you once and offers
  "Set up built-in Linux" or "Connect a computer". Your projects in Termux are
  still there: copy them to the phone's shared storage or push them with Git
  to bring them over.
- **Node.js setup adapts on phones where it crashed** (#117, #119). When
  Node.js crashes while setting up built-in Linux, the app checks why, tries
  the builds of Node.js that work on more phones by itself, and checks early
  that Node.js starts. When none works, setup stops early and says so in plain
  words, with a way out, instead of failing later.
- **A VPN is not shown as mobile data.** When a VPN runs over Wi-Fi, the voice
  model download no longer warns that it uses mobile data. When the phone
  can't tell whether a connection costs data, it says so.
- **Integrations page after a reconnect** (#124). The MCP tab loads again by
  itself once the server is back, waits while it connects, and says plainly
  when a server doesn't offer a list (for example on an older version)
  instead of "Could not load this section". Each section has its own reason,
  with the technical text under Details.
- **Crash report offer after an unexpected exit.** When the app closed
  unexpectedly last time, one line offers a crash report. You review exactly
  what it contains and send it yourself through GitHub; nothing is sent by
  itself. Turn the offer off in Settings > Privacy and data.
- **Optional usage and app health, and crash reports** (two switches, both off
  unless you agree). On the first start after this update the app asks once,
  "Help improve OpenCode Mobile?": "Share both" turns both on, "Not now" leaves
  both off and it never asks again, and "Choose" opens the two switches. They
  are also in Settings > Privacy and data: **Usage and app health** and
  **Crash reports**. An answer you already gave in an earlier 2.1.5 preview
  carries over, so you are not asked twice. What is sent is only fixed words,
  ranges and numbers:
  - *Usage and app health:* which kind of page is open, which of eight
    features is used, how long the app stays open, whether connecting,
    sending, the queue, built-in Linux setup (each step, with the exit and
    signal kind and the Node.js safe mode), agents, the background service and
    updates worked and why not, how fast the app starts, how smooth each kind
    of page is, memory warnings, and ranges for the phone's memory, free
    storage, CPU, WebView version and notification permission.
  - *Crash reports:* the kind of error and its code locations (never its
    message), why Android ended the app last time (crash, ANR, low memory and
    so on), the last steps you took as short words such as `conn.connect`, and
    a few keys (app version, build kind, server kind, engine state, number of
    connections, OpenCode major.minor).
  - Never messages, prompts, files, paths, server addresses, passwords,
    keys or the advertising ID. The full list is in
    [PRIVACY.md](../../PRIVACY.md).
- **Send a problem report** (Settings > Help). Shows you the whole report
  first: the app's last 500 log lines, the keys above, recent process ends and
  device ranges, with keys, URLs, host names, addresses and paths already
  blanked. It is sent only when you tap **Send**, asked every time whatever
  the two switches say. You get a **report code** to quote in a GitHub issue;
  Settings > About shows it too.

## Technical changes

**Health and diagnostics telemetry** (`lib/telemetry`, contract in
`docs/telemetry/health-and-diagnostics.md`, shared with the native app)  
Consent split into `usage` and `crashes` (`Telemetry.setUsageConsent`,
`setCrashesConsent`); the old single answer carries over
(`PreferencesTelemetryConsentStore.carriedOver`). `Telemetry.track(event,
props)` needs `usage`; crashes, failures, breadcrumbs and custom keys need
`crashes`. Twenty-three events: the eleven setup and page events plus
`conn_attempt`, `conn_drop`, `send_result`, `turn_stall`, `queue_flush`,
`linux_setup_step`, `agent_start`, `bg_service_end`, `update_result`,
`app_start`, `jank`, `memory_pressure`. Every value is one of a fixed word, a
fixed range or a number with a fixed shape (`health_schema.dart`); anything
else is dropped, and errors are sent as a kind (`failKindOf`), never their
message. Google Analytics for Firebase is a second adapter next to
Crashlytics, present only when the private Firebase file is built in.
Collection off in the manifest until consent; `AD_ID` permission removed;
advertising ID, SSAID, ad personalisation and automatic screen reporting off.
No BigQuery export or paid Firebase product. Jank comes from the framework's
frame timings, registered only while `usage` is on; app start is one stopwatch
read until then. Android's `ApplicationExitInfo` is read through the existing
`oc/lifecycle` exit history; a new small channel, `oc/health`
(`HealthChannel.kt`), answers only device numbers and passes memory-pressure
levels to Dart. The problem report is redacted by `ReportRedaction`
(`KitRedact` plus URLs, hosts, addresses and paths) and sent as one
Crashlytics non-fatal with the text as logs.
_For: people who turn a switch on, and anyone sending a problem report.
Accessibility: two switches and one sheet built from existing kit parts; all
new words are in English and Arabic._

**Crash reports** (`lib/telemetry`)  
Vendor-neutral reporting layer with a no-op adapter by default and a
Crashlytics adapter when the private Firebase file exists. Reports carry only
fixed names, short codes and code locations, passed through the app's
redaction.

**Termux removed**  
The Termux bridge, its setup screens, its strings and its native half are
gone. Profiles made with Termux still load; a notice points to built-in Linux
or a computer.

**Voice download network check**  
A VPN takes its metered state from the network underneath (`VpnMetering`).

**Node.js setup** (#117, #119)  
The Node.js step names each part (unpacking, setting up, checking that it
starts) and runs `node --version` on its own before npm, so a crash says where
it happened.

Native and dependency changes (Firebase, manifest, Kotlin), so this is a full
Shorebird release, not a patch.
