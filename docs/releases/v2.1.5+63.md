# OpenCode Mobile 2.1.5+63

Draft, not released. This release adds Spanish, removes the Termux app
integration, makes Node.js setup adapt on phones where it crashed, and adds
optional crash reports and setup analytics that stay off unless you turn them
on.

Change class: feature

## What changed for you

- **Spanish** (#122, thanks @Lxchoooo). The whole app is translated. The
  language picker no longer says "Partly translated".
- **Termux is no longer used.** Built-in Linux is the only way to run an agent
  on the phone itself; you can still connect to an agent on your computer. If
  you set up the app with Termux before, the app tells you once and offers
  "Set up built-in Linux" or "Connect a computer". Your projects in Termux are
  still there: copy them to the phone's shared storage or push them with Git
  to bring them over.
- **Node.js setup adapts on phones where it crashed** (#117, #119). When
  Node.js crashes while setting up built-in Linux, the app checks why, tries
  the builds of Node.js that work on more phones by itself, and checks early
  that Node.js starts. When none works, setup stops early and says so in plain
  words, with a way out, instead of failing later.
- **A VPN is not shown as mobile data.** When a VPN runs over Wi-Fi, the voice
  model download no longer warns that it uses mobile data. When the phone
  can't tell whether a connection costs data, it says so.
- **Integrations page after a reconnect** (#124). The MCP tab loads again by
  itself once the server is back, waits while it connects, and says plainly
  when a server doesn't offer a list (for example on an older version)
  instead of "Could not load this section". Each section has its own reason,
  with the technical text under Details.
- **Crash report offer after an unexpected exit.** When the app closed
  unexpectedly last time, one line offers a crash report. You review exactly
  what it contains and send it yourself through GitHub; nothing is sent by
  itself. Turn the offer off in Settings > Privacy and data.
- **Optional crash reports and setup analytics** (off unless you turn them
  on). One switch in Settings > Privacy and data, "Send reports to developer", sends crash reports and
  counts how far setup gets, so we can see where it fails. It sends only fixed
  words: which setup step was reached or failed and why (crash, timeout,
  network, space or other), how long setup and the first reply took as a
  range, whether the server is on the phone or a computer, and when an update
  is offered or installed. Never messages, files, paths, server addresses,
  passwords or the advertising ID. The full list is in
  [PRIVACY.md](../../PRIVACY.md).

## Technical changes

**Setup analytics** (`lib/telemetry/analytics_events.dart`)  
`Telemetry.track(event, props)` behind the crash-report consent. Eight events:
`app_open`, `setup_step_reached`, `setup_step_failed`, `setup_done`,
`first_reply`, `connect_computer_chosen`, `update_offered`,
`update_installed`; values only from fixed enums and buckets, checked again
for `/`, `@`, dotted addresses and length. Google Analytics for Firebase is a
second adapter next to Crashlytics, present only when the private Firebase
file is built in. Collection off in the manifest until consent; `AD_ID`
permission removed; advertising ID, SSAID, ad personalisation and automatic
screen reporting off. No BigQuery export or paid Firebase product.
_For: people who turn the switch on. Accessibility: no new screen; the
existing switch's wording changed._

**Crash reports** (`lib/telemetry`)  
Vendor-neutral reporting layer with a no-op adapter by default and a
Crashlytics adapter when the private Firebase file exists. Reports carry only
fixed names, short codes and code locations, passed through the app's
redaction.

**Termux removed**  
The Termux bridge, its setup screens, its strings and its native half are
gone. Profiles made with Termux still load; a notice points to built-in Linux
or a computer.

**Voice download network check**  
A VPN takes its metered state from the network underneath (`VpnMetering`).

**Node.js setup** (#117, #119)  
The Node.js step names each part (unpacking, setting up, checking that it
starts) and runs `node --version` on its own before npm, so a crash says where
it happened.

Native and dependency changes (Firebase, manifest, Kotlin), so this is a full
Shorebird release, not a patch.
