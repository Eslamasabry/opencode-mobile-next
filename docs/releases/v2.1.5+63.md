# OpenCode Mobile 2.1.5+63

This release lets you tell us what breaks and what you
use, only if you agree (analytics, crash reports and timings, all off until you
turn them on), opens phone files in other Android apps, adds Spanish, drops the
Termux integration, and updates the agents' security pins. It upgrades in place
from 2.1.4.

Change class: feature

**Migration.** Upgrades in place from 2.1.4. Your servers, conversations,
settings and downloads are kept, and nothing needs doing. The only new thing is
a one-time question on the first start, "Help improve OpenCode Mobile?", and
you can answer "Not now". If you used Termux before, the app tells you once
(see below).

## What changed for you

- **Help us fix what breaks, only if you agree.** Optional usage, crash and timing numbers, off until you turn them on, plus **Send a problem report**.
- **Open phone files in Android**, and see why a file can't open.
- **Spanish**, and the update notice inside the app.
- **Safer agents**: new Claude Code, Codex, Antigravity and Node.js.

## Feature by feature

- **Analytics, crash reports and timings, only if you agree.** Two switches,
  both off. On the first start you are asked once, "Help improve OpenCode
  Mobile?"; the switches are in Settings > Privacy and data. What is
  collected, what never is, and why: [About analytics and crash
  reports](#about-analytics-and-crash-reports).
- **Timings (Firebase Performance).** If you turn on **Usage and app health**,
  the app also measures how long it takes to start, connect, show the first
  reply, run each setup step and start an agent, and how smooth screens are.
  No web address is ever recorded.
- **Send a problem report** (Settings > Help). Shows you the whole report
  first, with keys, addresses and paths already blanked. It is sent only when
  you tap **Send**, asked every time, whatever the two switches say. You get a
  **report code** to quote in a GitHub issue; Settings > About shows it too.
  After an unexpected exit, one line also offers a crash report you review and
  send yourself through GitHub.
- **Open phone files in Android.** A file in the phone's shared storage (where
  built-in Linux saves) opens in the app you pick, and an .apk goes to
  Android's installer, which asks you to confirm. When a file can't open,
  Files says why in plain words: too big, missing, no permission, not
  something to open, or the helper is unreachable. A `file:` link in chat now
  opens as a file instead of being blocked. Only ordinary files in the phone's
  shared storage open; the app's own private files never do.
- **QR scanner without Google ML Kit.** Scanning a pairing code works as before
  but no longer bundles Google's ML Kit (about 3 MB smaller, and nothing
  proprietary in the scanner). The source also builds for F-Droid, with the
  self-updater and the install permission switched off in that build.
- **An AI Team task carries on after OpenCode restarts mid-turn.** When the
  phone's OpenCode restarts or crashes under a running step, the task notices,
  sends that step again by itself up to twice, and then leaves **Resume** to
  you, instead of ending the task.
- **Claude Code sign-in, fixed** (#137). When the sign-in lapses, the chat says
  "Claude Code needs you to sign in again" with a **Sign in** button, instead
  of showing a raw error. Signing in no longer needs a pasted code: the page
  hands back to the phone by itself, and a code is asked only if the page
  itself shows one.
- **Your account on the subscription details** (#136). The signed-in account
  name is shown on an agent's subscription details, read only from the agent's
  own command inside built-in Linux.
- **An in-app update notice** (#126, thanks @Altaf Yafai). The app checks this
  project's promoted releases, shows "Update available" with the size and
  what's new, checks the download against its published checksum, and hands it
  to Android's installer. It installs only its own download of a build signed
  by the same key.
- **Security updates for the agents on the phone.** Claude Code 2.1.319 (fixes
  a Bash permission bypass, a sed permission skip and a sandbox escape), Codex
  0.167.0, Antigravity 1.5.3 and Node.js v24.22.2 (security fixes and OpenSSL
  3.5.9). Each download is checked against its published checksum.
- **Antigravity limits** (#125, thanks @Altaf Yafai). Its 5-hour and weekly
  limits show in Usage, asked of Antigravity's own command so the app never
  touches its credentials.
- **A visible line between conversations on dark screens** (#129, thanks
  @Altaf Yafai).
- **Spanish** (#122, thanks @Lxchoooo). The whole app is translated.
- **Termux is no longer used.** Built-in Linux is the only way to run an agent
  on the phone itself; you can still connect to an agent on your computer. If
  you set up the app with Termux before, the app tells you once and offers
  "Set up built-in Linux" or "Connect a computer". Your projects in Termux are
  still there: copy them to the phone's shared storage or push them with Git.
- **Node.js setup adapts on phones where it crashed** (#117, #119). The app
  checks why, tries the builds that work on more phones, and checks early that
  Node.js starts. When none works, setup stops early in plain words with a way
  out.
- **A VPN is not shown as mobile data** when you download the voice model.
- **Integrations page after a reconnect** (#124). It loads again by itself, and
  says plainly when a server has no list instead of "Could not load this
  section".

## About analytics and crash reports

Why we added it, what it sends, and what it never does. Everything here matches
the code and the full policy in [PRIVACY.md](../../PRIVACY.md); the exact event
list is in the "Usage and app health" table there.

### Why we added it

- The app runs on many phones and setups we can't test.
- Crashes and failed setups were invisible unless someone wrote to us.
- We want to fix what actually breaks, and to know which features people use,
  so we work on the right things.

### What is collected (only if you turn it on)

- **Usage and app health.** Twenty-three events, each with fixed words, ranges
  or numbers and nothing else:
  - the kind of page open and which of eight features is used (voice, camera,
    file attach, agent switch, model switch, add server, Git action, review),
    and how long the app stays in front;
  - whether connecting, a dropped connection, sending, a stalled reply, the
    send queue, each built-in Linux setup step (with how it ended: exit kind,
    signal, compatibility mode, free-space range), starting an agent, the
    background service and updates worked, and why not (a fixed reason such as
    "timeout" or "offline");
  - how fast the app starts, how many frames are slow on each kind of page, and
    memory warnings;
  - once, as ranges and words: phone memory, free storage, CPU family, WebView
    version, whether notifications are allowed, kind of server, OpenCode
    major.minor.
  - Google Analytics adds on its own the app version, phone model, Android
    version, language and country or region (it does not keep your IP address),
    and a random install ID.
- **Crash reports.** The kind of error and the places in the code it happened
  (never the error's message); why Android ended the app last time (crash,
  not responding, low memory and so on); your last 30 steps as short words
  such as `conn.connect`; and a few keys: app version, build kind (store or
  sideload), server kind, engine state, number of connections, OpenCode
  major.minor.
- **Performance timings.** How long app start, connecting, the first reply,
  each built-in Linux setup step and starting an agent take, and how many
  frames are slow or frozen. Each timing carries one or two fixed words such as
  "phone" or "ok".

### What is never collected

- Message text, prompts, replies, code, file names or paths.
- Server addresses, API keys, passwords, tokens or account names.
- The advertising ID (the app does not even hold that permission) and the
  Android ID.
- Web addresses of network requests: network tracing is off, and the app never
  records a request.
- Anything outside the fixed lists: the app drops it before sending.

### Your choice

- **Off until you turn it on.** The first-start question has three answers:
  **Share both** turns on both switches, **Not now** leaves both off and the
  app never asks again, **Choose** opens the two switches, which start off.
  Nothing is preselected.
- **The switches** are in Settings > Privacy and data: **Usage and app health**
  (events and timings) and **Crash reports**. Turning one off stops collection
  at once; turning Crash reports off also discards what was not yet sent, and
  turning Usage and app health off clears the analytics data kept on the phone,
  with its random install ID.
- **Problem reports** are sent only when you tap **Send**, every time, after you
  read all of it.
- A build without the private Firebase file (for example an F-Droid build)
  has no switches or first-start question and sends no analytics or crash
  data.

### How we will use it

- Fix the most common crashes and failed setup steps first.
- Spot slow steps (connecting, the first reply) and check whether fixes help.
- See which features are used, to decide what to polish.
- Numbers are looked at in aggregate. No data is sold or shared with anyone,
  and Google's own data-sharing options (ad personalisation, ad data, ad
  storage) are off in the app.

### Where it goes

Google Firebase: Analytics for Firebase (usage and app health), Crashlytics
(crash reports and problem reports) and Performance Monitoring (timings). Google
processes it under its own terms. How long it is kept (checked in the
Google Analytics settings): event-level data for 2 months, and user-level data
for 14 months, counted from the person's last activity (it resets with new
activity).

## Technical changes

**QR scanner** (`kit_qr_decoder.dart`, `kit_scanner_camera.dart`)  
`KitScanner` takes frames from the `camera` plugin (CameraX) and decodes them
with `zxing2`, a pure-Dart port. `mobile_scanner` and its ML Kit barcode model
are gone from every build. F-Droid switches: an `OC_FDROID` define that swaps
the Shorebird updater for a stub, a Gradle flavor overlay that removes
`REQUEST_INSTALL_PACKAGES`, and a root Gradle check that refuses Google SDK
dependencies (`tool/fdroid`).

**Opening phone files** (`oc/share`: `openLocalFile`, `supportsOpenLocalFile`)  
An unexported FileProvider (authority `.localfiles`, `local_file_paths.xml`,
`external-path` only) and `REQUEST_INSTALL_PACKAGES`. `LocalFileGate` (Kotlin)
and `canonicalPhoneFile` (Dart) accept only a regular file inside primary
shared storage after symlinks and `..` resolve; never `Android/`, never the
app's private `files/` directory. The updater keeps its own narrow
`file_paths.xml` (cache/updates only).

**AI Team restart resume**  
The engine names `serverRestarted` when a turn accepted by one OpenCode pid is
found under another, resends once per round on its own `restartDispatch`
ledger (the original prompt is never redispatched), retries twice, then leaves
Resume to the person. `await_completion` waits out a restart longer.

**Updater** (#126, #134)  
FileProvider exposes only `cache/updates/`; `installApk` takes only a readable
`.apk` directly inside it, by canonical path.

**Agent pins**  
Claude Code 2.1.319, Codex 0.167.0, Antigravity 1.5.3 (the updater serves only
1.5.3; it carries the 1.5.1 OAuth fix) and Node.js v24.22.2, each SHA-256
computed from the official artifact; no checksum is disabled.

**Firebase Performance Monitoring** (`firebase_performance_adapter.dart`,
`perf_traces.dart`) is a third adapter in `CombinedTelemetryAdapter`, behind the
same private-config wiring. Collection follows `usage` and the manifest keeps
it off before that. The Performance Gradle plugin is not applied, so no HTTP is
traced. Custom traces come only from `PerfSchema`.

**Health and diagnostics telemetry** (`lib/telemetry`, contract in
`docs/telemetry/health-and-diagnostics.md`, shared with the native app)  
Consent split into `usage` and `crashes` (`Telemetry.setUsageConsent`,
`setCrashesConsent`); the old single answer carries over
(`PreferencesTelemetryConsentStore.carriedOver`). `Telemetry.track(event,
props)` needs `usage`; crashes, failures, breadcrumbs and custom keys need
`crashes`. Twenty-three events: the eleven setup and page events plus
`conn_attempt`, `conn_drop`, `send_result`, `turn_stall`, `queue_flush`,
`linux_setup_step`, `agent_start`, `bg_service_end`, `update_result`,
`app_start`, `jank`, `memory_pressure`. Every value is one of a fixed word, a
fixed range or a number with a fixed shape (`health_schema.dart`); anything
else is dropped, and errors are sent as a kind (`failKindOf`), never their
message. Google Analytics for Firebase is a second adapter next to
Crashlytics, present only when the private Firebase file is built in.
Collection off in the manifest until consent; `AD_ID` permission removed;
advertising ID, SSAID, ad personalisation and automatic screen reporting off.
No BigQuery export or paid Firebase product. Jank comes from the framework's
frame timings, registered only while `usage` is on; app start is one stopwatch
read until then. Android's `ApplicationExitInfo` is read through the existing
`oc/lifecycle` exit history; a new small channel, `oc/health`
(`HealthChannel.kt`), answers only device numbers and passes memory-pressure
levels to Dart. The problem report is redacted by `ReportRedaction`
(`KitRedact` plus URLs, hosts, addresses and paths) and sent as one
Crashlytics non-fatal with the text as logs.
_For: people who turn a switch on, and anyone sending a problem report.
Accessibility: two switches and one sheet built from existing kit parts; all
new words are in English and Arabic._

**Crash reports** (`lib/telemetry`)  
Vendor-neutral reporting layer with a no-op adapter by default and a
Crashlytics adapter when the private Firebase file exists. Reports carry only
fixed names, short codes and code locations, passed through the app's
redaction.

**Termux removed**  
The Termux bridge, its setup screens, its strings and its native half are
gone. Profiles made with Termux still load; a notice points to built-in Linux
or a computer.

**Voice download network check**  
A VPN takes its metered state from the network underneath (`VpnMetering`).

**Node.js setup** (#117, #119)  
The Node.js step names each part (unpacking, setting up, checking that it
starts) and runs `node --version` on its own before npm, so a crash says where
it happened.

**Security updates to agents and Node.js**  
Claude Code 2.1.319 (fixes a Bash permission bypass, a `sed` permission-check
skip and a worktree sandbox escape), Codex 0.167.0 (hardened sandbox checks),
Antigravity 1.5.3 (includes the 1.5.1 OAuth token protection) and Node.js
v24.22.2 (security release, OpenSSL 3.5.9). Every download keeps its pinned
SHA-256.

Native and dependency changes (Firebase, manifest, Kotlin), so this is a full
Shorebird release, not a patch.
