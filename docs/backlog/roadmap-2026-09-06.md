## Method, and why not RICE

Context per prioritization-advisor's adaptive ladder:

- **Stage:** public alpha, pre-PMF — the persona doc is explicit that these are
  "design assumptions to validate with users, not interview findings."
- **Team:** effectively one maintainer plus agents — "focus ruthlessly."
- **Data:** minimal by design. The app sends no telemetry
  ([PRIVACY.md](../../PRIVACY.md)); GitHub issues are the only demand signal.

For pre-PMF + small team + minimal data the advisor prescribes **ICE /
Value-vs-Effort, not RICE** (Reach requires usage metrics we deliberately do
not collect). So: gut-check ICE scores as a sorting heuristic, MoSCoW as the
forcing function, and the persona journey as the strategic override — exactly
the "PM judgment overrides scores" rule. Scores below are honest guesses, not
measurements.

## Where the backlog actually stands

All 22 tracked items (BE-001–011, FE-001–011) are implemented. What remains is
four kinds of work: **evidence** (device/live/accessible verification of
shipped code), **dispositions** (v2-native surface awaiting build/hold/drop
decisions), **known gaps** (stash migration, #10 native races), and
**deferred lanes** (localization, desktop, Shorebird rehearsal). The persona
doc's own consequence list — audit the primary journey before adding controls,
sequence advanced operations by user job — is the tiebreaker where scores tie.

### LATER — demand-gated, not forgotten

- **Localization (#15/#18–20):** large effort, zero validated demand signal.
  Honest English-only is documented; revisit when non-English issue reports
  appear.
- **Desktop real-runtime (#22–24):** explicitly experimental; needs contributor
  hands (`.deb` never installed, Windows never run), not more code from us.
- **Shorebird patch rehearsal (#43):** only if patch delivery is promised;
  otherwise it is deferred cost.
- **Persistent session terminals, workspace create/destroy, branch discovery:**
  hold pending a persona-job justification; do not wire server-internal
  controls into UI just because the contract exposes them.

### Explicit non-goals (recorded, per roadmap "what we will not build")

Server-internal controls (plugin/debug/migration inspection, server upgrade,
diagnostics upload, runtime refresh), one-shot generate, and worktree
destructive reset. A raw endpoint count cannot establish product parity —
this matches the backend backlog's own rule.
