## Corrections that change the plan

1. **Termux-native execution remains unproven.** Invoking bionic bash from
   inside proot does not leave proot. Version output and a 401 response are
   partial smoke evidence, not authenticated server/tool functionality. See
   the [corrected spike record](../verification/termux-native-server-spike-2026-09-06.md).
2. **Private address is not private transport.** Neither `100.64.0.0/10`, a
   `ts.net` name, nor an installed VPN app proves a particular route is
   encrypted. Keep HTTPS/loopback policy; prefer private HTTPS serving over a
   verified tailnet. Public Funnel exposure is a distinct opt-in decision.
3. **Subscription quota is not local spend.** Provider account-wide windows,
   OpenCode usage, and user budgets have different scopes and units. No
   token-to-subscription-percentage conversion. An unavailable quota is unknown,
   never zero remaining or unlimited.
4. **Codex app-server, pi RPC, and ACP are not interchangeable.** Capture each
   protocol independently. RUN_COMMAND is not a duplex stream. A small remote
   companion may be appropriate for CLI-only backends; Termux is not required
   for computer-hosted use or iOS remote control.
5. **Copy patterns, not unsupported guarantees.** A late failure must not revive
   a resolved approval; no optimistic approve-then-rollback or invented SSE
   replay. Performance changes require our own trace and benchmark.
6. **Research is not demand measurement.** Stars/downloads are not active users
   or causal growth evidence. No telemetry does not prohibit consented user
   observations, support feedback, or aggregate release-download evidence.
   Earlier numerical ICE guesses are withdrawn rather than treated as facts.

## Acceptance rules for every pulled story

- State **current / missing / unknown**, the affected user job, input/output
  contract, capability gate, and origin scope (profile/location/session/request).
- Include success, first-load failure, stale refresh, cancellation, reconnect,
  and scope replacement where relevant. Acceptance may need multiple scenarios;
  one Gherkin pair is not a repository rule.
- Reuse shipped views before adding chrome. Review 360dp with keyboard and
  2.5x text, 48dp targets, reduced motion, TalkBack, and theme roles.
- Keep observable timing/cost estimates distinct from provider quotas. Retain
  unavailable/unsupported/unknown states and timestamps, not reassuring guesses.
- No third-party code copied without source commit, license/attribution review,
  maintenance-cost estimate, and native/dependency delivery assessment.
- Lead owns the final diff, analyzer and serial full suite. Focused checks run
  serially too. Native/signing/device/publication actions retain approval gates.
