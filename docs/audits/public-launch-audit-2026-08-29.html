Conditional no-go

Do not make the current repository/history public or promote the current APK as stable until the critical deployment, server-controlled-link, CI, deletion, provenance, and release-trust issues are closed.

The app itself is substantially more mature than the headline score suggests. Android boundaries, Keystore credentials, loopback-only cleartext, notification request binding, OAuth handling, diagnostics redaction, verified model downloads, protocol abstraction, and the fail-closed release script are strong.

Hard blockers

Unsafe Ubuntu helper

Defaults can bind OpenCode to all interfaces without a required password and encourage LAN HTTP/firewall exposure.

External form links

Server-supplied form URLs bypass the hardened Markdown link policy and can invoke unsafe schemes.

CI is not authoritative

The current Actions gate is blocked before meaningful jobs run, so release claims lack exact-commit evidence.

Incomplete local deletion

Removing a profile can leave queued prompts, drafts, preferences, and other profile-owned state behind.

Public-history hygiene

Internal handoff material, WIP instructions, local details, and AI session URLs should remain in a private archive.

Third-party provenance

Bundled developer skill packs need removal or complete source, version, license, and notice documentation.

Fresh artifact required

Publish only a new, green, signed, hashed, SBOM-backed artifact from the remediated launch commit.

Recommended publication sequence

  1. Secure the Ubuntu installer and all copied/documented commands.
  2. Use one safe external-link service across Markdown, forms, updates, and OAuth-adjacent flows.
  3. Restore CI and require a green exact-commit gate.
  4. Create a clean public lineage while preserving the current private repository as the internal archive.
  5. Implement transactional cascade deletion and correct privacy copy.
  6. Resolve third-party provenance and add public governance/security files.
  7. Cut a new preview with hashes, signer fingerprint, SBOM, provenance, per-ABI artifacts, and real-device evidence.

Launch gates

  • Repository public: clean tree/history, secret scan, provenance, safe deployment/link policies, accurate privacy, governance.
  • Preview APK: exact commit green, controlled release lane, published artifact identity/provenance, real-device smoke.
  • Stable: complete data lifecycle, accessibility gates, no unresolved high-risk issue, usability validation, support/incident process.
