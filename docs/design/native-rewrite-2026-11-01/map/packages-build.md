## 0. Read this first (the twelve things that matter most for the rewrite)

1. **Most of the Android layer is already native Kotlin and lives in the same Gradle module.** `K/` is 168 files / 25,465 lines (plus 46 JVM test files / 7,977 lines / 645 `@Test`, and 5,109 lines of instrumentation). Only 36 of the 168 files import `io.flutter`. The rewrite can keep the Gradle module, `namespace`, `applicationId`, manifest components, R8 rules, jniLibs and Kotlin tests, and replace `MainActivity : FlutterFragmentActivity` (plus `ManageSpaceActivity`, `WidgetOverlayActivity`, which are `FlutterActivity`) with Compose activities. **[src]**
2. **Four things run Dart from Kotlin today and must be re-implemented natively**: `scheduledPromptMain` (`ScheduledPromptRuntime.kt` boots a headless `FlutterEngine` to run a scheduled prompt), `widgetActionMain` (`WidgetActionRuntime.kt`, widget Allow/Reject/Reply/Stop through a bounded on-demand connection), `widgetOverlayMain` (`WidgetOverlayActivity`, the floating style/steer/voice panels) and `manageSpaceMain` (`ManageSpaceActivity`). They share Dart code with the main app (`lib/scheduling/entrypoint.dart`, `lib/background/widget_action_entrypoint.dart`, `lib/widgets_overlay`, `runManageSpaceApp`). **[src]**
3. **Three signing lineages exist and the brief names only one.** `842284B2…1C` signs every CI/GitHub release (v2.0.0+56, v2.1.0+57) and is what real users have; `1DE5BF08…D60C` is the owner's local release key (all dev/emulator/phone builds, `tool/qa/vps_build_apk.sh` hard-pins it); `2D010C21…D0EC` is the CI test signer (quality-gate APK artifacts, BD9 device smoke). They cannot update one another (§3). **Decide, before the first native build, which installed population the day-1 APK must update, and verify the installed signer, not the doc.** **[src][mem]**
4. **versionCode is a trap.** Published: `57`. Owner phone has local builds in the 4300-4500 range, emulator 4460+, hosted APKs up to 4511; Android refuses a lower versionCode (an uninstall wipes the in-app Linux and local data). The first native build must be above every installed number (suggest a new base, e.g. 10000+, and never go back). Per-ABI APKs share one versionCode. **[mem][src]**
5. **Shorebird ends at the switch**: it patches Dart only, and `libflutter.so` is Shorebird's engine fork. The switch release is a normal full APK. The in-app update notice must be replaced natively (design `app-updates-two-layers`: GitHub `releases/latest` + `SHA256SUMS` + same-signer check + `PackageInstaller`, needs `REQUEST_INSTALL_PACKAGES`, not yet in the manifest). Until a Flutter release carries that installer, **existing Flutter users cannot self-update into the native app**; they must download the APK (Obtainium/GitHub). **[src][mem]**
6. **Native libraries are executables, not just code.** proot, its loader, talloc, android-shmem and the three Rust `libaiteam_*` binaries ship as `jniLibs`, extracted to `nativeLibraryDir` (`useLegacyPackaging = true`) because an app targeting Android 10+ may only exec from there. A Gradle task hashes the packaged binaries against `assets/aiteam-engine-manifest.json` and fails the release build on drift; AGP strip is disabled for `libaiteam_*` for the same reason. Keep all of it. `armeabi-v7a` gets none of these (no on-phone Linux/AI Team on 32-bit). **[src][run]**
7. **Cleartext is allowed by the OS config, by design.** The manifest says `usesCleartextTraffic="false"` but `network_security_config.xml` has `<base-config cleartextTrafficPermitted="true"/>`, and the network config wins. The real gate is in the app (per-profile, origin-bound consent for non-loopback HTTP; no redirects). A native client must carry that gate over; Android cannot express `100.64.0.0/10` (Tailscale) so addresses are checked in code. **[src]**
8. **Localization is big and mixed.** `lib/l10n/app_en.arb` has 9,468 messages (1.76 MB; 261 plurals, 6 `select`, 1,738 with placeholders, 617 with apostrophes); `app_ar.arb` has 10,486 keys (1,018 orphan keys English no longer has); `zh` 8,654; `es` 2,695; `ja`/`pt`/`ru` 661 each. Android resources for notifications/widgets cover only `en` + `ar` (≈ 220 strings each). Compose resources have no ICU `select` (the 6 select messages need flattening) — §24. **[src][web]**
9. **The Flutter-era build knowledge is mostly Flutter-specific and will be deleted**: pinned Shorebird Flutter 3.47.1, "debug builds don't work", `GeneratedPluginRegistrant` traps, the Flutter golden harness, `flutter_animate` ban, widgetbook, `dart format --language-version` trap. What must survive: the release/signing/provenance rules, the size and startup budgets, the commit-message gate G33, the Arabic/partial-locale ratchets, the notice/licence hygiene, and the Kotlin/detekt/lint gates. **[src][mem]**
10. **Release plumbing keys on names that the native app must keep or the tools must be changed in the same change**: tag `v<x.y.z>+<N>`, assets `opencode-mobile-<version>.apk`, `…-arm64-v8a.apk`, `…-armeabi-v7a.apk`, `SHA256SUMS`, notes file `docs/releases/v<version>.md` starting `# OpenCode Mobile <version>`, CI step names checked by `scripts/verify_github_release.py`, output path `build/app/outputs/flutter-apk/app-release.apk` (about 12 scripts/workflows hard-code it). **[src]**
11. **Not yet in this tree**: the app-updates branch (`feat/app-updates-2026-10-31`), the Linux services/vitals/backup branches (see `builtin-linux.md` §0.9). Anything they add to `pubspec.yaml`/manifest is not counted here. `packages/opencode_sdk` and `lib/api` are gone (OpenCode 1 removed, commit `40ba4fa32`) even though `AGENTS.md` still mentions them. **[src]**
12. **Distribution constraints shape the build**: GitHub Releases + Obtainium only. F-Droid is blocked (ML Kit, Shorebird, prebuilt native libs, downloads executables); IzzyOnDroid is blocked by its AI policy; Google Play is risky for the on-phone Linux build (executable download, `MANAGE_EXTERNAL_STORAGE`, FGS types). A native rewrite changes *some* of those blockers (no Shorebird; ML Kit replaceable) but not the proot/Ubuntu or AI-policy ones — §34. **[src]**

#### PACKAGES-BUILD-01  Application identity and variants

- Rewrite note: keep the Android id, label, channel ids and `oc.*` extras; keep a preview variant mechanism (same `applicationIdSuffix` trick).

#### PACKAGES-BUILD-02  Version scheme and versionCode discipline
- Single source today: `pubspec.yaml version: x.y.z+N`. Regex enforced everywhere: `^[0-9]+\.[0-9]+\.[0-9]+\+[1-9][0-9]*$` (release.sh, workflow, `test/repository_hygiene_test.dart`, `test/release_metadata_test.dart`). Tag = `v<version>` (the `+` is in the tag; URLs show `%2B`). Notes file `docs/releases/v<version>.md` first line `# OpenCode Mobile <version>`. Changelog `CHANGELOG.md` top entry must agree (release metadata test). Fastlane changelog `fastlane/metadata/android/{en-US,ar}/changelogs/<versionCode>.txt` (<500 chars).
- Build number rises on every release, never on a patch. Per-ABI APKs and the universal APK carry the **same** versionCode (derived by deleting libs, not by Flutter's per-ABI multiplier).
- Dev builds use numbers in the thousands, allocated by range per agent (memory `apk-build-numbers`): coordinator and agents must never go below the highest APK installed on the emulator or the owner phone. 2026-10-30 trap: a lower-numbered build refused as downgrade; `adb install -d` does not help on release builds. As of 2026-11-01: 4510/4511 built on the VPS, emulator had 4460+, next combined owner candidate 4500+.
- `desktop_release_check.dart` parses `^v\d+\.\d+\.\d+\+(\d+)(?:-[0-9A-Za-z]+(?:[.-][0-9A-Za-z]+)*)?$` and compares **only the build number**; pre-releases count. The native update checker must keep one monotonic integer.
- Change classes (`docs/release/change-classes.md`): hotfix (Dart-only, patchable), fix, feature, breaking; `tool/qa/classify_change.py` proposes it; the `Change-Class:` trailer is optional and only accepts those four values. With no Shorebird, the *hotfix path disappears*: every change is a full release. Keep the classes for notes/gates, drop the "Ships as patch" column.
- Rewrite note: keep `x.y.z+N` and tag format (Obtainium, update checker, scripts depend on it) or change them together.

#### PACKAGES-BUILD-04  Toolchain and Gradle configuration
See §2. Extra rules:
- Release builds must be Shorebird builds today; a plain `flutter build apk` is "never used for anything users install" (owner rule 2026-10-01). After the switch this becomes `./gradlew :app:assembleRelease` + signing; keep the same verification (§32).
- Debug APKs cannot run on the pinned Shorebird engine (only release engine jars); every compile check uses `--release`. Native Gradle removes this restriction (big developer-speed win).
- `local.properties` carries `flutter.sdk` and `sdk.dir`; `settings.gradle.kts` includes `$flutterSdk/packages/flutter_tools/gradle`. Both go away.
- `tasks.matching { package*UnitTestForUnitTest }.dependsOn(copyFlutterAssets*)` exists only so Robolectric widget render tests can read merged assets; re-point to the new asset task.
- Instrumentation runner is chosen by a project property: `ocBd9Smoke`, `ocBb8Smoke`, `ocBuiltinRuntimeQa` (mutually exclusive, enforced by `require`), default `PhoneEngineAcceptance`; `testBuildType = "release"`. `phone-engine-instrumentation.pro` keeps `kotlin.**`, our package, Flutter embedding ABI for the test APK (drop the Flutter parts).
- Dependabot (`.github/dependabot.yml`): weekly pub + GitHub-Actions updates (Mondays), 5 open PRs each, minor/patch grouped, `rebase-strategy: disabled` (refresh one with `@dependabot rebase`); semver-major updates of `flutter_secure_storage` (v10 migrates legacy ciphers; v9→v11 strands credentials) and `sherpa_onnx` (native runtime and the ONNX version recorded in notices) are ignored on purpose and need a deliberate migration.

#### PACKAGES-BUILD-06  R8/ProGuard and release-only breakages
- R8 is on for release (mapping files 43 MB per build are produced and kept at `build/vps-apk/mapping-<n>.txt`; Dart symbols separate).
- `widget-status-release.pro` and `scheduled-prompts.pro` (both repeat `WorkDatabase_Impl` keep): Room constructs `androidx.work.impl.WorkDatabase_Impl` by derived name via its public no-arg constructor at process start; R8 removed it → crash before any activity (APK 900055 startup regression, fix `c664ca2ae`, with a DEX-level guard test of seven parser tests in `tool/qa/verify_scheduled_prompt_apk.py`). `WidgetStatusWorker` and `ScheduledPromptWorker` keep `public <init>(Context, WorkerParameters)` because WorkManager's default `WorkerFactory` restores persisted class names reflectively.
- `phone-engine-instrumentation.pro` is applied for preview, stable-engine QA, BD9 and runtime-QA builds only.
- Rewrite note: any native app using WorkManager + Room (or Compose + kotlinx.serialization reflection, Ktor service loaders) must repeat this class of rules and **test the R8'd APK on a device**; keep `verify_scheduled_prompt_apk.py` and `verify_widget_release_rules.py` (inspect the real DEX).

## 7. Hard-won behaviours a rewrite must not lose (with evidence)

1. **Same-signer rule and downgrade refusal** (§03, §02): uninstall = lose in-app Linux and projects. Evidence: README "Updating", memory `stable-release-1.0.44`, `apk-build-numbers`, release-2.1-prep.
2. **R8 strips `WorkDatabase_Impl()`** (§06): crash before any activity. Evidence: `c664ca2ae`, `tool/qa/verify_scheduled_prompt_apk.py`.
3. **Executables only from `nativeLibraryDir`**, legacy packaging, no strip of `libaiteam_*`, hash manifest verified on the packaged APK (§05). Evidence: `3f1cd39c6`, `69a1e99dc`.
4. **minSdk 26** (Process APIs; `O_CLOEXEC` constant fallback for API 27) — found by lint on CI, `b104591c5`.
5. **compileSdk 37** requirement came from a dependency's AAR metadata; any new library may do the same (`b48ebc165`). The demo needed 37 for Compose Multiplatform too.
6. **Plugin registrant lost mid-build** (APK 4293 crashed on every start): Flutter-specific, but the lesson stands: after any build, assert the APK contains what it must (`tool/qa/apk_has_plugins.sh`) and give each build its own working directory.
7. **Dev-only plugin breaks release lint** (`8331ae7cd`): run lint on the release variant with a release-config registrant. Native equivalent: no debug-only classes referenced from release code paths.
8. **Release preflight reads CI job and step names** — rename both together; `[skip ci]` snapshot tag does not start the release workflow (dispatch by hand, once).
9. **Shorebird tokens**: legacy refresh tokens fail ("Failed to refresh credentials"), now `sb_api_` keys; a `shorebird logout` on the PC revoked the old session. Native build has no equivalent but **GitHub secrets for signing remain** — never print them, rotate after a paste in chat (done once).
10. **Per-ABI split correctness**: same versionCode; v2+ signature only (`--v1-signing-enabled false`); zipalign `-P 16`; apksigner prints digest differently per format — read any line ending in the SHA-256 (`0c8235e67`).
11. **APK size growth gate (5 MiB)** compares with the previous tag's universal APK asset; it needs full git history (`fetch-depth: 0`) to resolve `HEAD^` (`e4d110eb2`).
12. **Arabic is never the fallback**: Flutter's own rule falls back to the first supported locale (Arabic, alphabetical); the app puts English first.
13. **Generated l10n must be regenerated after merges** (binary-merge trap), same for generated ledgers (`docs/design/ui-ledger/build_ledger.py`).
14. **Voice memory gate uses total RAM**, not `memoryClass` (§14).
15. **Widget picker quirks**: owner's launcher ignores `previewLayout` and mis-picks size maps → `previewImage` PNGs, locked 340 dp for four-wide, hidden-from-picker legacy providers kept; every widget keeps the size it was placed at (`176b4bead`, `8e8570b63`, `e79c37b5f`).
16. **`allowBackup=false` + rules exclude everything**: secrets must never reach cloud/device-transfer backups.
17. **Commit rules G33** keep release history auditable; landing as one snapshot commit is the accepted exception, not rewriting history.
18. **Publishing needs an owner yes per step** (push, CI run, tag, publish, signing). Do not automate around it.
19. **Do not kill processes by pattern** on the shared phone/VPS; capture PIDs (AGENTS.md).
20. **Privacy scrub before public pushes**: real Tailscale IP, device names, emails, VPS host must stay out of the repo (`57fa4799`); VPS host lives in a git-ignored env file.

## 8. Performance notes

- Today: APK 108 MB universal / ≈ 36 MB arm64 split; cold start ≈ 0.4 s (owner's demo comparison: native 0.25 s, 2.5 MB). `libapp.so` arm64 31.7 MB raw (12.9 MB deflated; 9.4 MB per ABI deflated with `--split-debug-info`), `libflutter.so` 14 MB, dex 4.3 MB.
- Largest optional native weights: ONNX Runtime 22 MB raw per ABI (voice), ML Kit barcode ≈ 5 MB + models, Rust engine 5.4 MB (+1.2 probe). Moving voice or QR to on-demand modules needs a feature-delivery channel; sideloaded APKs have none (documented as owner decision in `apk-size-2026-10-16.md`).
- Build speed: PC cold APK 5.5 min; VPS cold 19 min (first run); Gradle needs 4-5 GB and trips low-memory alerts (`OC_VPS_*` exists for that reason). PC is 8 CPU / 16 GB shared with one emulator (2 Codex + 1 Claude subagent ceiling, memory `pc-capacity-ceiling`; two OOMs killed GNOME/tmux). Quiet hours midnight-2 am: VPS only.
- Tests: serial 27-40 min; 4 shards fast; 6 CI shards ≈ 10 min; goldens must run on the PC (VPS rasterisation differs 0.2 %).
- l10n: committed generated Dart ≈ 6.9 MB source for 7 locales (compile cost, and every locale class is in `libapp.so`); Android resources are far smaller (≈ 220 strings × 2).
- Startup budget tooling: `tool/release/cold_start.py` (median of `am start -W` TotalTime, default ≤ 3000 ms, emulator only, measures Activity launch not first frame/server readiness).
- Baseline profile: `assets/dexopt/baseline.prof` is auto-added by profileinstaller; a native Compose app should ship its own Baseline Profile + startup profile (large first-frame win for Compose) **[est]**.

## 9. Risks

1. **Signer ambiguity** (§0.3, PACKAGES-BUILD-03): shipping a native APK under the wrong key strands either the owner (needs uninstall → loses Linux/projects) or all public users. Highest-impact decision; verify with `apksigner`/`dumpsys package` on the installed apps first.
2. **versionCode ordering** (PACKAGES-BUILD-02): a published value below an installed one is silently unusable on that device.
3. **No bridge for Flutter users**: without a Flutter release that can install an APK (`REQUEST_INSTALL_PACKAGES` + `PackageInstaller`), the switch relies on manual download/Obtainium. Obtainium works only if asset names, tags and signer stay stable.
4. **Loss of OTA hotfixes**: every fix needs a full release and user install; plan a fast-release path and an in-app "update ready" flow; consider a staged-rollout policy.
5. **Four Dart entrypoints in Kotlin** (PACKAGES-BUILD-39): scheduled prompts and widget actions (which can approve a command from the home screen) are security-sensitive; porting must keep their leases/receipts/claims semantics (tests in the `android-platform` catalog area).
6. **Terminal emulator, syntax highlighter, SVG sanitiser, Ed25519, Phosphor icons, Geist variable font weights** have no drop-in Compose equivalent; each is a small project with security or fidelity requirements.
7. **ICU-style messages** (6 selects, 261 plurals, Arabic 6-form plurals, apostrophe quoting) must be converted losslessly; wrong plural rules are a visible Arabic regression.
8. **Compose Multiplatform maturity**: stable 1.12.2 (2026-10-15) and 1.13.0-beta01 (10-23) exist **[web]**; the owner's demo hit alpha M3 and needed compileSdk 37. Pin exact versions, test on the nubia phone, and re-check `compose-resources` plural/locale support before committing the string pipeline.
9. **R8-only crashes** (WorkManager/Room; Ktor/serialization/Koin reflection): always test the minified release APK on a device before any hand-off (owner's rule: emulator pass first).
10. **Policy surfaces**: the manifest's FGS types, `MANAGE_EXTERNAL_STORAGE`, battery exemption, executable downloads are the first things a Play or F-Droid reviewer reads; a native rewrite is the moment to produce a server-only flavour (`PlatformCapabilities` + Gradle product flavor) if stores matter.
11. **Release plumbing is one big contract** (names, steps, paths, tags). Rewriting the build without updating `verify_github_release.py`, `release.sh`, workflows, `vps_build_apk.sh`, `check_apk_size.py`, docs and site in the same change breaks publication (ten-plus files hard-code `build/app/outputs/flutter-apk/app-release.apk`).
12. **Tooling debt that disappears and tests that must be re-created**: the Flutter test suite is the only spec of many behaviours (14.6k tests). The catalog rows are the transfer mechanism; unconverted widget tests (7,967) are deferred by the owner.
13. **Small things**: Arabic privacy text not bundled (PACKAGES-BUILD-22); `cupertino_icons` dead weight; `AGENTS.md` still mentions `packages/opencode_sdk` and Flutter 3.47.1 vs CI 3.47.2; hygiene test needs `.git` (fails on VPS copies); 1,018 orphan Arabic keys.
14. **Dependency pins with blast radius**: `flutter_secure_storage` (never skip v10 semantics — the native secure store must tolerate unreadable legacy entries), `sherpa_onnx` (native runtime), `mobile_scanner` (compile breaks on toolchain changes).
15. **Machine limits**: PC 8 CPU/16 GB, one emulator, shared Gradle lock, VPS disk fills; native Gradle builds are faster than Flutter's but the same lock discipline applies.
