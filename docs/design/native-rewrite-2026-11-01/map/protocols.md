### PROTOCOLS-01 Server address rules (normalize, validate, classify)
- `normalizeServerProfileUrl` (`lib/state/profiles/validation.dart`): a pasted bare `host[:port]`, bare IPv4, bare IPv6 (`::1` gets brackets;
  `[::1]:4096` keeps its port) gains a scheme: loopback to `http://`, everything else to `https://`. Never infers HTTP for a remote host. A value with a scheme is left alone.
- `validateServerProfileUrl`: must contain `://`; http or https only; port 1..65535 (empty `host:` rejected); no whitespace/`%`/backslash/control chars in host;
  **no credentials in the URL**; no query/fragment; no path (origin only). Returns plain-words error strings (kept verbatim in `validation.dart`).
- `isLoopbackHost` (`lib/domain/loopback_host.dart`): exactly `localhost`, `127.0.0.1`, `::1`. One predicate on purpose (three disagreeing copies once caused `::1` bugs).
- `isPrivateNetworkHost`: 10/8, 172.16/12, 192.168/16, 169.254/16, IPv6 fc00::/7 and fe80::/10, IPv4-mapped IPv6 judged by the inner IPv4, `*.local` mDNS names (not bare `local`). Brackets, trailing dot and IPv6 zone ignored. Used only to choose warning wording.
- `isTailnetHost` (`lib/orchestration/adapters/gascity/gascity_probe.dart`): loopback, `*.ts.net`, IPv4 in 100.64.0.0/10 (`b[0]==100 && (b[1]&0xC0)==0x40`). Gas City URLs allow http only to loopback/tailnet (`isOrchestrationUrlAllowed`). The OpenCode server profile treats Tailscale IPs as "non-loopback http needs consent" like any other.
- `serverUrlNeedsCleartextConfirmation(url)` = scheme http and host not loopback. `cleartextOriginOf(url)` = `scheme://host:port` lowercased (IPv6 bracketed). The confirmation is stored per profile against that origin (PROTOCOLS-02); changing the address asks again.
- `explainConnectionAddress` (`lib/platform/connection_advice.dart`) = local, no-network "Connection help" classifier returning `{empty, malformed, credentials, queryOrFragment, path, unsupportedScheme, remoteHttp, privateHttp, https, loopback}`; never keeps input.
- `normalizeCodexServerUrl`/`validateCodexServerUrl` (Codex WebSocket): `ws://` only for loopback, else `wss://`; no creds/query/path.
- Android manifest: `usesCleartextTraffic="false"` but `network_security_config.xml` sets `<base-config cleartextTrafficPermitted="true"/>` because Android's static config cannot express runtime-chosen hosts or IP ranges (Tailscale 100.64.0.0/10). **Dart is the security boundary**; the native app must keep this same base-config and enforce consent in code.
- Stale doc warning: `docs/connectivity-private-networks.md` and `docs/switching-clients.md` still say LAN/100.64.x HTTP is never accepted; the code (since #85, `2a53ce682`) accepts any non-loopback HTTP origin after an explicit per-origin consent, with stronger wording for public hosts.
- Tests: `profiles` tests, `connection_advice` tests, `api2_transport_trust_test.dart`, `server_probe_test.dart`.

### PROTOCOLS-02 Transport trust: cleartext consent, certificate pinning, origin binding
Files: `lib/domain/server_trust.dart`, `lib/api2/http_keep_alive_io.dart`, `lib/api2/transport.dart`, `lib/state/profiles.dart` (persistence).
- One `HttpClient` per profile connection (never global). Created by `createServerHttpClient`: connection timeout 8 s, **idle timeout 15 s** (was Dio's 3 s; the 15 s keeps one TCP connection across a 4 s reading pause), **`findProxy = DIRECT`** (no ambient proxy), a `connectionFactory` that **refuses any target whose origin/host/port differs** from the trusted origin (throws `ServerOriginChangedException`), and for HTTPS returns `SecureSocket.startConnect` itself (a custom factory owns TLS).
- **Redirects are disabled everywhere** (`followRedirects:false, maxRedirects:0`) so Basic credentials can never cross to another origin.
- A Dio interceptor re-validates on every request: `validateServerTrust` (cleartext consent exact-origin; pin requires HTTPS and a valid 64-hex fingerprint), origin equality against `serverRoot`, and rejects URLs with userinfo.
- **Certificate pin** = SHA-256 of the **leaf certificate DER** (not SPKI), compared in the handshake callback BEFORE any HTTP byte is sent (Dio's `validateCertificate` is deliberately not used: too late). With a pin the `SecurityContext(withTrustedRoots:false)` makes normal PKI/hostname checks irrelevant (a pin is an explicit identity override for self-signed private servers); validity dates (`startValidity..endValidity`) are still enforced. A mismatch records `ServerCertificateChangedException` into the client, and the interceptor then blocks *every later request on that client* until the connection is rebuilt (no silent concurrent retry clears it). Unpinned clients use normal PKI.
- `inspectServerCertificate(url)`: TLS handshake only (empty trust roots, accept any cert) to show subject/issuer/validity/fingerprint (`AA:BB:..` display form) for the user to review and pin. Sends no HTTP bytes or credentials.
- Error tags that survive generic error mapping: `ClientCertificateChanged`, `ClientCertificateInvalid`, `ClientCleartextNotAllowed`, `ClientOriginChanged` (`serverTrustErrorTag`).
- Persistence (per profile): `oc.cleartextOk.<profileId>` (the confirmed origin string); `oc.certificatePin.<profileId>` = JSON `{"origin":"https://host:port","sha256":"<64 hex>"}` (restored only if the profile's current base URL equals that origin, https only, 64-hex validated). Both are swept on profile deletion by the `oc.<what>.<profileId>` naming rule.
- Native caution: OkHttp's `CertificatePinner` pins SPKI, not whole-cert DER; to preserve behaviour the Kotlin app needs a custom `X509TrustManager`/`HostnameVerifier` (leaf DER SHA-256, validity dates, no chain, no hostname).
- Tests: `api2_transport_trust_test.dart` (HTTPS never sends plaintext Basic; remote HTTP needs exact-origin consent; redirects blocked; pin inspected without HTTP; expired matching cert and untrusted TLS are distinct errors; normal PKI cannot bypass an existing pin), `api2_terminal_auth_test.dart`.

### PROTOCOLS-03 Credentials: Basic auth, never in a URL, redaction registry
- Auth is **HTTP Basic**, username `opencode` (a BYO tunnel profile uses `profile.username`, `transientTransport`), header only: `Authorization: Basic base64(user:password)`. No unauthenticated endpoint exists, even `/api/health` (401 + `WWW-Authenticate`).
- The old helper that put `?auth_token=` in URLs was **deleted on purpose** (commit `932210227`): URLs leak into proxies, logs, crash reports and screenshots. Never reintroduce. The PTY WebSocket uses a one-time ticket instead (PROTOCOLS-28).
- `KitRedact.registerKnownSecret(password)` runs in the `Api2Transport` constructor; `registerCredentialValues(json)` runs on `/provider` and `/config` responses **at ingress** (before decoding or diagnostic capture); `connectIntegrationKey` registers the key. Masks everything in logs/diagnostics/copy. A rewrite needs the same registry plus pattern masking (sk-, ghp_, Bearer, Authorization header values, URL userinfo, PEM, JWT; full list in `lib/ui/kit/kit_redact.dart`).
- The serve password changes on every server restart unless `OPENCODE_PASSWORD` is set. A mid-session 401 sets `passwordRejected` and disables retry loops; the banner offers "Update password" (never a modal).
- Secure storage: the password sits in `flutter_secure_storage` under `pw.<profileId>` (also `oc.codexToken.<id>`, `oc.teamEngineAuth.<id>`, `oc.githubToken.<id>`, `oc.quotaToken.<id>`, `oc.byoHostSecrets.<id>`); the profile list is JSON in SharedPreferences `oc.profiles` (no secrets), active id `oc.activeProfile`.

### PROTOCOLS-04 Pairing payload (`opencode2 pair`)
`lib/state/pairing.dart`. The CLI prints a QR whose content is `{"urls":[...],"username":"opencode","password":"..."}`.
- `looksLikePairingPayload` is a loose sniff (starts `{`, ends `}`, contains `"urls"`). `parsePairingPayload`: max 8192 UTF-16 units, max 32 urls, tolerant of an empty `urls` array, username defaults to `opencode`. Every failure is a plain sentence that never quotes the input. `PairingPayload.toString()` redacts; the password is held behind `consume()` (drop the reference once copied into the profile).
- Parse rules: urls are trimmed, empties dropped, duplicates removed, each <= 2048 chars; missing `urls`/`password`, non-text fields, empty list ("server is not listening") each have their own plain sentence.
- Address selection (`selectPairingUrl` in the same file): every URL first goes through the normal profile URL validator (a pairing code is not a licence to relax transport policy). `orderPairingCandidates(preferLoopback)`: on a phone routable addresses are tried before the server's `127.0.0.1` (which is not the phone's loopback unless bridged with `adb reverse`/an SSH forward); on desktop loopback first. A remote `http://` address is **held, never probed** (`needsCleartextConfirm`, "This address uses plain HTTP. Confirm that first; nothing was sent to it.") until its origin is in `confirmedCleartextOrigins`. Candidates are probed in order, the first that connects wins; if none connects but one *answered* (401 stale password, 503 booting) that host is chosen with its honest verdict. Per-address outcome reasons come from a fixed allowlist, never from probe text.
- Scanner: `mobile_scanner` (Android only, gated by `platformCapabilities.supportsQrPairing`). 39 catalog rows in `test/pairing_payload_test.dart`, 2 in `pairing_scanner_test.dart`.

### PROTOCOLS-05 Server probe and flavor detection
`lib/domain/server_probe.dart` (`probeServerConnection`, result `ServerProbeResult{ok,version,message,suggestsMissingServer,flavor,needsPassword,unsupportedLegacy}`), `lib/state/server_trust_probe.dart` (`probeTrustedServerConnection`, the one the setup flow uses: validate URL, require consent, then `Api2Transport.checkServer()`).
Order: `GET /api/health` with Basic. Verdicts:
- 401 (empty body) = **positive OC2 signal**: no password supplied then "This server requires its serve password." (`needsPassword`), else "Password rejected. Copy the current 'server password' line... it changes on every restart unless OPENCODE_PASSWORD is set."
- 2xx JSON with `version` = success (version string kept). `healthy:false` = "responded but reported itself unhealthy" and **does not fall back to the OC1 check**. 503 = "The server is starting. Try again in a moment."
- 404 on `/api/health` then one `GET /api/info`: stable line (>= 2.0.4) answers there. Accepted only in its real shape (`version` string AND (`pid` number OR `urls` list)), or 401, or 503. OC1 and arbitrary web servers that answer every path must still fall through.
- Anything else: one `GET /global/health` (OC1 route): `{healthy:bool, version:string}` means **legacy OC1** and yields the failure `unsupportedLegacy` with `unsupportedOpenCode1Message` = "This server runs OpenCode 1, which this app no longer supports. Update it to OpenCode 2." (the constant `openCode2UpgradeCommand` = `npm uninstall -g opencode-ai && npm install -g @opencode/cli@2.1.1` is what the UI shows beside it). Otherwise "This address did not answer as an OpenCode 2 server."
- Failure explanations are specific and truthful: DNS failure (checks glibc/Android/macOS/"failed host lookup" strings) = spelling; refused = "Is opencode2 serve running...?" (`suggestsMissingServer`); timeout = reachability + setup guide; bad certificate; 401/403 never claim a missing server.
- `Api2Transport.health()` additionally enforces `supportedVersion`: version starts `0.0.0-beta-` or major >= 2; otherwise throws `Api2RequestError(tag: UnexpectedHealthShape, statusCode 200)` so a connect re-probes and shows the legacy-upgrade explanation (an OC2 host serves its web UI HTML with 200 on the OC1 health path).
- `ServerFlavor {v2, unknown}`. The saved profile's `flavor` is now always `v2` on load; profiles saved as OC1 get `requiresOpenCode2Migration = true` (PROTOCOLS-34). A failed connect re-probes once (`redetectOnFailure`).
- Tests: `server_probe_test.dart` (15 rows), `api2_health_identity_test.dart`, `oc2_server_discovery_test.dart`.

### PROTOCOLS-06 Dialect layer: beta-18600 vs stable (2.0.4+ incl. 2.1.x)
`lib/api2/dialect.dart` + the retry logic in `Api2Transport._send`. **Call sites speak the beta vocabulary; `stableRoute()` translates at the edge** once the generation is known. 2.1.x moved nothing (verified by `/openapi.json` diff), so `stable` covers 2.0.4 through 2.1.x (2.2.x unverified).
Generation detection: first `GET /health` success = beta; a 404 on a *moved* route while generation unknown triggers one `GET /info` (version string = stable; clean 404 = beta; other errors leave it unknown). `settleDialect()` lets the connect-time probe record it. The Rust engine and the probe tolerate both.

### PROTOCOLS-07 HTTP transport details
- Dio config: base `<root>/api`; connect timeout **8 s**; default receive timeout **2 min**; long-poll (`/session/{id}/wait`) **10 min**; `validateStatus` 2xx only; JSON response type; `PerfTraceInterceptor` ("OCTRACE" spans per request, logged when >= 50 ms).
- `normalizeServerRoot`: trims trailing `/` and a trailing `/api` so `http://h:4097`, `http://h:4097/api/` resolve identically.
- Query: null values dropped; empty map dropped. Path segments are percent-encoded per segment for ids and file paths.
- Error mapping (`Api2Transport.mapError`): trust tags first; handshake/bad certificate to "The server certificate could not be verified."; body parsing even for byte downloads (UTF-8 decode of error JSON); tag = `_tag` or `code`; 401 or tag `UnauthorizedError` to `Api2AuthRequired` (even with empty body); no status to `Api2NetworkError{timedOut,cancelled}`; 503 or tags `ServiceUnavailableError|service_starting|service_stopping|service_failed` to `Api2Unavailable`; everything else `Api2RequestError{statusCode,tag,body}`. `Api2Error.detail(key)` reads extras (`sessionID`, `requestID`, `id`, `field`, `maxBytes`).
- Large JSON: Dio's FusedTransformer decodes bodies >= 50 KiB on a worker isolate; a rewrite must decode big message pages off the main thread (model construction still hurt main-isolate time).
- Server boots lazily: "any non-health request during boot returns 503 `{code:service_starting}`"; the pinned server drops a project's services after an idle hour and re-boots on the next request (see PROTOCOLS-12 for the 404 trap).
- `fsReadBytes` returns raw bytes (no envelope), path segments encoded.

### PROTOCOLS-08 Typed client and location scoping
`Api2Client` carries `directory` and `workspace` (set by `setLocation`). Location-scoped calls add `location[directory]=<abs>` and `location[workspace]=<id>`: models, providers, agents, permissions pending, forms pending, fs, vcs, pty, shell, skills, commands, mcp, config, plugin, reference, websearch, integration. `POST /session` carries `location:{directory,workspaceID}` in the body. ### PROTOCOLS-10 Messages: paging and the history contract
- `GET /session/{id}/message?limit&order&cursor` (limit 1..200, default order desc). App requests `limit=100&order=desc`, **reverses** the page to chronological order, and only reports `nextCursor` (older) when `page.nextCursor` is non-empty **and** `page.length >= limit` (OC2 returns a cursor even on the last page; without the length test every new chat offered "Load older messages"). Cursor continuation never mixes with `order`.

### PROTOCOLS-11 Sending a prompt
`POST /session/{id}/prompt` body `{id?, text, files?[], agents?[], skills?[], metadata?, delivery?, resume?}`. Response is an **inbox receipt**, not the assistant message: `{data:{id:"msg_...", sessionID, timeCreated, type:"user", payload:{text,files?}, delivery}}`. 409 if a client-supplied `id` is reused. **No model/agent/system/tools fields**: model and agent are session state (`POST .../model`, `.../agent`, or set at create). Completion is observed by events or `POST .../wait`.
- `delivery`: `steer` (default; adds to the running turn at the next step boundary) or `queue` (after the run). The app's owner rule is **steer, never queue** (`PromptDelivery`; the app only sends `queue` when the user explicitly picks it, otherwise omits the field).
- Attachments are URIs: `data:<mime>;base64,...` inline or `file:///abs/path[?start=&end=]` (server-local). Max 20 MB per attachment; the server resizes images. `PromptAttachment {mime, filename, url, mentionPath, mentionStart/End}`: `@path` file mentions carry UTF-16 offsets `{start,end,text:"@path"}`; directory references use mime `application/x-directory`. Agent `@mentions` are `agents:[{name, mention{start,end,text}}]` (these are attachment hints, not agent selection).
- `promptAttachmentMime` (`prompt_attachment.dart`): allow png/jpeg/gif/webp/pdf; text-like mimes (text/*, json, xml, yaml, toml, sh, sql, graphql, ndjson, +json, +xml) and ~35 extensions (md, txt, log, html, css, csv, json, xml, yaml, toml, dart, js, ts, tsx, jsx, py, go, rs, java, kt, c, cc, cpp, h, hpp, sh, sql...) normalize to `text/plain` ONLY if the bytes look like text (no NUL, valid UTF-8, no C0 controls except tab/LF/VT/FF/CR); other images and unknown binaries are refused (null). Reason: OpenCode expands exact `text/plain` data URLs into text. Office files are converted to text first (`office_text.dart`, uses `xml`).
- `ModelRef.normalized`/`bareModelID(providerID, modelID)`: strip a leading `providerID/` from a composite model id; sending `openai/gpt-5` produced "Model not found: openai/gpt-5. Did you mean: gpt-5?". Ids that merely contain a slash are left alone.
- Pre-send steps in `Api2Gateway._promptAsync`: dispatch fence (`beforeSessionDispatch`/`sessionDispatchSettled`, used by the phone engine admission), then `_prepareSessionDispatch` (PROTOCOLS-12), then the POST. **A staged revert blocks sending** (`SessionRevertPending`, 409, copy "Review the staged revert, then clear it or make it permanent before sending.") because the server would implicitly commit it (even with `resume:false`).
- Slash commands: `POST /session/{id}/command {command (stable: name), text}`; leading `/` stripped. Shell in transcript: `POST /session/{id}/shell {command}` (allowed while a revert is staged). `PromptTrace.track` records admission latency.
- Offline queue (`oc.offlineQueue`, `lib/state/offline_queue.dart`/`connection/queue.dart`) replays through the same path, with command receipts (PROTOCOLS-35).
- Tests: `api2_interaction_gateway_test.dart` (18), `api2_permission_dispatch_test.dart`, `api2_phone_chat_dispatch_test.dart`, `model_ref_normalization_test.dart`.

### PROTOCOLS-12 Per-session permission policy ("ask for everything" and Auto-approve)
`lib/api2/session_permission_policy.dart` + `Api2Gateway._applyPermissionMode/_prepareSessionDispatch/syncSessionPermissions`.
Why: OC2 evaluates the **agent's rules first, then the session's rules, last match wins**. The app wants every tool to ask the phone, so before each send it rewrites the session's `permissions` (via `PATCH /session/{id} {permissions, metadata}`) to `[{action:"*",resource:"*",effect:"ask"}, ...agent rules with allow turned into ask, ...original session rules with allow turned into ask]` (denials preserved in order). Rules: `{action, resource, effect: allow|ask|deny}`, max 1000.
- Provenance is kept in **server-side session metadata key `oc.mobile.permissionRequests`** = `{version:1, original:[rules], applied:[rules]}`. If another client changed the rules since the app applied them (`rules != applied`), the new truth is kept as the original. Switching agents re-derives from `original`, so a previous build agent's allow rules do not mask a plan agent's denials.
- **Read-back is mandatory**: after the PATCH the session is read again; the agent, rules and metadata provenance must match exactly or the send aborts with "Could not turn on permission requests. Your message was not sent." Strict parsing, fail closed (malformed rules/provenance throw).
- **Auto-approve (2026-10-25 root-cause fix, commit `3b90a4c65`)**: for a session the person approves automatically (`serverRunsTools(sessionID)`), the original rules are restored (server runs what its own rules allow; its asks/denials still reach the phone). Reason: OC2.0.29 glob/grep put undefined metadata in permission requests, which makes `GET /permission/request` and `/session/{id}/permission` return **400 for the whole list** while one is pending (upstream bug #37650, fixed in 2.1.x). A missed ask then could never be recovered; the tool sat unexecuted until the server's **60-minute idle sweep interrupted the reply** (reason `inactivity`) and cancelled sub-agents. `syncSessionPermissions` re-applies the mode mid-reply when the toggle flips; the next message installs it anyway.
- **Agent boot 404 retry** (`800f93a4c`): the server drops project services after an idle hour; for a moment after reboot `GET /agent/{id}` returns 404 for an agent that exists, which failed the first message after a quiet hour. `_readAgent` retries twice, 500 ms apart.
- Default agent: `GET /agent` list; the first entry is the resolved default; must be `hidden:false` and mode `primary|all`.
- Tests: `api2_session_permission_policy_test.dart` (11), `api2_permission_dispatch_test.dart` (6).

### PROTOCOLS-13 Permissions (requests and saved grants)
- Pending: `GET /permission/request` (L) and `GET /session/{id}/permission`. Event `permission.asked` carries the full request `{id, sessionID, action, resources[], save[], metadata, source{type,messageID,id(=callID)}, message}`. Reply: `POST /session/{sid}/permission/{rid}/reply {reply:"once"|"always"|"reject", message?}` (stable renames `reply` to `decision`); `message` is shown to the model on reject (steering-by-rejection). The app maps `allow` to once and `deny` to reject for notification actions (`mapPermissionReply`, unknown value = `ProductException`).
- Reply by request id only: `respondPermission` recovers the owning session from the pending list; if not pending, throws `ApiException(404, tag PermissionNotFoundError, requestID)` (answering an externally resolved request is idempotent in the controller).
- Saved grants (`Always allow`): `GET /permission/saved?projectID=<current>`, `DELETE /permission/saved/{id}` (2.1 adds `PATCH`, unused). Items `{id, projectID, action, resource}`.
- **Events are ephemeral**: asks are NOT replayed on reconnect. After every (re)connect the controller re-reads pending permissions, questions and forms (PROTOCOLS-20); a turn that is waiting re-reads every 15 s (`turnStallRereadEvery`).
- Legacy question requests do not exist on OC2 (`legacyQuestionRequests:false`); forms replaced them. The old `question.*` event handlers and `QuestionGateway` remain as inert interfaces (used by Paseo/Codex).

### PROTOCOLS-14 Forms (structured questions and MCP elicitation)

### PROTOCOLS-15 Inbox (pending sends, steer/queue flip, cancel)
`GET /session/{id}/inbox` lists durably admitted undelivered items `{id, sessionID, timeCreated, type: user|synthetic|compaction|move, payload, delivery}`. `DELETE .../inbox/{id}` cancels (409 if delivered), steer/queue flip (stable PATCH). ### PROTOCOLS-17 Event stream: SSE framing, reconnect, status
`GET /api/event` (text/event-stream, Accept header, no receive timeout). Frames are bare `data: <json>` lines; keep-alive is the comment `: heartbeat`. First event `server.connected`.
- `Sse2Parser`: byte-wise; handles LF/CRLF; `:` comments ignored; multi-line `data:` joined with `\n`; `event:`/`id:` kept; a frame/line larger than **16 MiB is dropped without killing the stream** (reference client caps at the same); `flush()` dispatches a trailing frame; a frame cut mid-write is discarded; malformed JSON frames are skipped.
- `Api2EventStream`: statuses `connecting|connected|reconnecting|disconnected`; automatic reconnect with exponential backoff (attempt is incremented before use, so the delays are **1 s, 2 s, 4 s, 8 s, then 16 s cap**: `500 ms * 2^min(attempt,5)` clamped to [500 ms, 16 s]); backoff resets only after 30 s of stable connection; status becomes `disconnected` after 6 consecutive failures (but it keeps retrying; the label is visual only); generation counter fences stale pumps; `dispose()` cancels the Dio token and subscription. `nextAttempt` (ValueListenable<DateTime?>) exposes the real retry time so the UI can count down ("trying again in 12 s"): set with the timer, kept while the try is in flight, null when connected/disposed.
- First-event latency is traced (`events.first`).
- **Contract: the stream is volatile.** A disconnect loses events; a slow consumer overflows and fails the stream. Nothing replays. All reconciliation is by refetch (PROTOCOLS-20).
- Two channels per connection: a pinned-location channel (client-side filter on `envelope.location.directory == pinned`, events without a location pass) and a **global** channel (unfiltered; stamps `directory/project/workspace` on the app envelope) used for "what are my other projects doing" attention, the chat feed refresh, and `installation.*`/`worktree.*` events.
- Tests: `api2_sse_test.dart` (9 rows), `connection_sse_wake_test.dart`, `reconnect_hardening_test.dart` (mid-stream drop, long sleep, network switch, Wi-Fi to LTE flap with a prompt in flight sends nothing twice).

### PROTOCOLS-19 Event adaptation: v2 events to the app's event model (`Api2EventAdapter`)
The controller and chat still consume a v1-shaped event vocabulary, so `lib/api2/gateway_events.dart` is a stateful adapter. **A native rewrite should keep the semantics, not necessarily the v1 names**: it needs an internal reducer from fine-grained events to message/part state. Behaviours that matter:
- `server.connected` to `server.connected`. `session.created` to `session.created {info:{id,title,projectID,directory,parentID,workspaceID,path(subpath),serverSelection:true,model,agent,time}}`; `renamed`/`moved` to `session.metadata.updated` (a move replaces BOTH directory and workspaceID so moving back clears a workspace); `deleted`; `model.selected`/`agent.selected` (ignored if empty); `viewed`; `usage.updated {cost,tokens}` (merged into the session in place, never via session.updated which would reset other fields); `revert.*` passthrough.
- `execution.started` to `session.status busy`. `execution.succeeded|interrupted` to `session.idle` (+ `interruptReason`) and settles open tool calls (interrupt marks them failed "Tool execution interrupted"). `execution.failed` to `session.error {name:error.type, message}` ONLY (adding idle would overwrite the error settle with "complete"); a blank message uses `sessionErrorFallbackText(type)`; beta-18600 sent empty messages for provider failures; blank is treated as missing at the source.
- `session.status {type:busy|idle|retry...}`: idle becomes `session.idle`; retry and `retry.scheduled` become `session.status {type:retry, attempt, message, next}` (message falls back to the error type).
- `step.started` to `session.status busy` (restores a lost busy state), settles earlier steps' open calls, emits an assistant `message.updated` (agent, providerID, modelID remembered per message id; `step.ended`/`failed` do not repeat them); `step.ended` to completed `message.updated` (finish, cost, tokens, time.created from the remembered start); `step.failed` to completed + error (message, or "The model step failed without a message from the server" + type + "HTTP status"); `step.streamed` ignored.
- Parts have **stable ids that match the refetch mapper**: `text-<ordinal>`, `reasoning-<ordinal>` (ordinal per type), tool part id = callID. Text/reasoning: `started` to part with empty text; `delta` to `message.part.delta {field:"text"}`; `ended` to full text + `time.end`. Tool: `input.started` to pending part (name remembered), `input.delta` to delta on `state.raw`, `input.ended` to pending with full raw, `called` to running with input, `progress` to running + metadata (replacement), `success|failed` to completed/error with joined text output, file items as `attachments:[{url,mime,name}]`, `executed`.
- **Open-call settling** (volatile stream may lose `tool.success`): the adapter keeps up to **256** tracked tool calls and step records (insertion-ordered, oldest evicted); when a step ends, a later step starts, or the execution ends, still-open calls of that session are emitted as completed (or error when the step/execution failed or was interrupted) and the chat is told `session.transcript.stale {sessionID}` to re-read the real result. A result for a call the adapter never saw (reconnect: tool name and input are only sent when the input starts) also triggers `session.transcript.stale`. Fixes `697658cd8`, `13366168a`.
- `instructions.updated` to a neutral "Session instructions updated." notice (message id = event id with `evt_`->`msg_`, so it matches the later REST transcript); server instruction text is never shown.
- `skill.activated`/`session.shell.*` to `session.skill.changed`/`session.shell.changed` (rehydrate; event text never exposed). `shell.*` (managed shells) pass through as freshness hints only, never messages.
- `permission.asked` to `permission.v2.asked` (copies `source.id` into `callID`); `form.*` to `form.v2.*`; inbox passthrough (+ user echo).
- Refresh hints: `agent.updated`, `config.updated`, `plugin.*`, `websearch.updated` pass by name; `catalog.updated`/`models-dev.refreshed` to `catalog.updated`; `integration.updated`/`credential.updated` to `integration.connection.updated`; `credential.switched {integrationID, credentialID|null}` forwarded only if well-formed (explicit null = no active credential), never credential payloads.
- Controller reaction (`ConnectionController._onEvent`): catalog/agent/config/integration events refetch the catalog behind the current list, bursts share one reload.
- Tests: `api2_gateway_events_test.dart` (incl. lost-result settling), `chat_oc2_step_gap_test.dart`, `chat_feed_oc2_run_end_test.dart`.

### PROTOCOLS-20 Reconnect, wake and refetch reconciliation (controller rules)
What happens when the stream (re)connects (`lib/state/connection/events.dart`):
1. status `connected`: refetch pending permissions, questions and forms; flush the offline queue; refresh gen-UI scope; clear last error/`passwordRejected`.
2. if it was `reconnecting|disconnected` before: `_markDataRefreshReady` (screens rehydrate from REST, because events missed during a network handoff are gone) and `_refreshAfterReconnect` (`refreshSessions`, then clears the quiet-reconnect token). If it was the first attach after `connecting`, the open chat reloads once more (events between transport-up and stream-live were never heard).
3. The reconnect is recorded as an "automatic act" (While you were away) when the stream recovered by itself.
4. `_streamConnects` counter lets a waiting-request read know whether the stream has carried every change since it started.
Other rules:
- **Quiet reconnect**: a healthy link that drops is not shown for 15 s (`_quietReconnectTimer`); a return from background has a 4 s `resumeQuietGrace`; connect has an 8 s status grace. An agent command running when the link dropped holds "busy" up to 10 min (`agentCommandHoldOff`); a phone server alive but not answering is "busy" not "dead" (native liveness read, 2 min before a neutral line).
- **Polling fallback** every 5 s: reconcile `sessionStatuses()` for busy sessions (a healthy SSE can still lose one terminal event during a handoff); **a run ends only after two consecutive idle answers** (`_idleOnce`) because OC2 omits a running session from `/session/active` for a moment between steps (fix `f267a25a2`: one idle answer cleared busy for good: no Stop, no progress).
- `messageCompletionEndsRun:false` on OC2: a completed assistant message (step end) must NOT end the run; only `execution.succeeded|failed|interrupted` does.
- Turn stall (`turn_stall.dart`, `state/connection/turn_stall.dart`): 45 s of silence on the target session starts a bounded (10 s) probe on a 5 s tick; classification `modelSlow | helperDown | network`; before calling a turn "dropped" the controller asks the server's status (`checkTurnStillRuns`); a running command counts as activity (`a0000cff4`).
- Global channel loss marks other-project attention stale and clears feed question/form caches; any `session.created|deleted|updated` on the global channel schedules a chat-feed refresh.
- Wake from background: `prepareActionTransport()` waits until the wake-time transport answers and returns the replacement gateway; retained screens must not capture `api` before it completes (lifecycle replacement can swap gateway and repository together).
- Auth failure mid-session: `_noteAuthFailure` flags `passwordRejected` and stops retry loops.

### PROTOCOLS-23 Message/tool content model (what the transcript needs from the wire)
`mapApi2Message` (`gateway_mappers.dart`) converts the 10-variant union to `MessageWithParts` (still v1-shaped `Part{id,type,text,toolName,toolState,url,filename,mime,callID,noticeMetadata,synthetic}`):
- user: `text-0` + `file-<i>` parts; attachment url = source uri, else rebuilt `data:` URI from stored base64.
- assistant: `parts` from content with ids `text-<n>`/`reasoning-<n>`/callID; MessageInfo gets agent, providerID, modelID, cost, tokens, `time.completed`, `finish ?? rawFinish`, error text and `MessageErrorKind`.
- shell message: an assistant message with ONE tool part named `shell` (input `{command}`, output = captured output, metadata `{exit, truncated, shellID, shellStatus}`); `running` = running; `exited` with exit 0 = completed; else error (timeout/killed keep raw status).

Time `{created,ran,completed,pruned}` maps to `{start(prefers ran),end,compacted}`; `pruned` (newer builds) means output was removed, so it cannot be opened; `executed:false` = tool never ran.

- Unknown message types/content degrade to a "Server message" notice, never crash. 2.1 renamed provider replay blobs to `native`; the app does not read them.
- Active context inspection (`GET /session/{id}/context`, `active_context_mapper.dart`): explicit, read-only view of the live model context; metadata/binary bodies/URLs not rendered; pruned items shown as such; unsupported (404 non-session / 405 / 501) latches `activeContextSupported=false`.

### PROTOCOLS-36 Errors: from wire to words (no raw errors)

## 6. Tricky behaviours and hard-won fixes a rewrite must not lose (checklist)
1. **OC2 turn stays running between steps**: only `execution.succeeded|failed|interrupted` end a run; never end on `step.ended`/completed message; status poll needs two idle answers (`697658cd8`, `f267a25a2`).
2. **Lost tool results** on the volatile stream: settle open calls when the step ends/next starts/execution ends; ask for a transcript reread; reread when a result arrives for an unseen call (after reconnect) (`697658cd8`, `13366168a`).
3. **Permissions poison**: auto-approved sessions keep the server's own rules; other sessions get ask-all with metadata provenance and read-back; permission list can 400 on 2.0.x glob/grep; asks are not replayed, re-read after reconnect and every 15 s during a turn; 60-min server idle sweep interrupts (`3b90a4c65`).
4. **First message after an idle hour**: agent GET 404 during server boot; retry twice at 500 ms (`800f93a4c`); server may answer 503 `service_starting` for any non-health request during boot.
5. **Model modes** are separate models keyed by server id; `'default'` variant = none; send bare model ids (`574537c91`, `8c6da5c1c`).
6. **Staged revert** blocks send; server would implicitly commit; skip staged-away history pages; commit/clear are different endpoints (`91ab6419e`, `c6fde6da4`).
7. **Steer in the inbox** joins the newest turn and must not make the running reply look finished/dropped (`9de34551c`); default delivery is steer, omit the field unless the user picks queue.
8. **Stop reasons**: carry `interruptReason`; honest wording; ask the server before saying "connection dropped" (`3ea4a9381`); blank error messages count as missing; Details never empty.
9. **Health shape**: OC2 host serves HTML on the OC1 health path; a 200 without OC2 version must be treated as wrong generation (`26be1e01a`); `/api/info` accepted only in its real shape.
10. **No credentials in URLs**, exact-origin consent, no redirects, no proxy, pin before first byte, pinned client latched after mismatch (`932210227`, `a2c629aba`).
11. **`GET /session/active` validated strictly**; invalid never means idle.
12. **Message page "more" test**: `nextCursor` present AND page length >= limit.
13. **Message ids**: user echo for an inbox item uses the inbox id as message id; part ids are `text-N`/`reasoning-N`/callID, identical in live and refetch; `v2:` role-user rows must not count as prompts.
14. **Session note** is counted in bytes of the JSON encoding; 8192 max; the 413 body carries `maxBytes`.
15. **PTY**: resize via REST; ticket needs the CSRF header; Basic header also on the upgrade; cursor bookkeeping; 0x00 meta frame; closing an already-gone terminal is success.
16. **Integration attempts** remember their original location and survive gateway replacement without contacting the server.
17. **Worktree DELETE error** has the old `{name, data:{forceRequired}}` shape, not `_tag`.
18. **Creating a worktree** needs a project with a commit; git init 409 = success; stable returns `{directory}` without envelope.
19. **OC1 history copy** (db + wal + shm) before first OC2 start; never overwrite; resumable; Termux link2symlink objects as files.
20. **Plugin/websearch/shell/etc. responses are untrusted**: bounded sizes, fixed sentences, no server text in messages, credentials registered for redaction at ingress.
21. **Pairing payload** is a credential: size caps, redacting toString, drop the password reference after use.
22. **Idle-stream backoff**: 1 s doubling to a 16 s cap, reset only after 30 s of stability; visual "disconnected" after 6 attempts while still retrying; quiet reconnect (15 s) and resume grace (4 s) so the UI does not flash.
23. **Cleartext base permission** in the Android network security config because ranges cannot be expressed; Dart/Kotlin must enforce consent.
24. **Do not log or echo provider credentials**: `/config/providers` style endpoints return keys; `/provider` registration on ingress.

## 7. Performance notes (summary)
Reuse one TCP connection per profile (15 s idle); decode big JSON off the main thread; 100-item pages; coalesce refreshes; first-paint caches; throttle stream deltas into the UI; byte-budgeted reads for untrusted history; 16 MiB SSE frame cap; 256 tracked tool calls; 32-entry attempt maps; avoid per-line allocations in SSE; server cold start after idle is slow on the phone (use generous first-request timeouts and the 503/404 boot retries); the phone-hosted server can be "busy not dead" for minutes during builds.

## 8. Risks for the rewrite
1. **Event semantics are the product**: the app's smoothness complaints came from the Dart adapter plus Flutter rebuilds; but the adapter's rules (PROTOCOLS-19/20) encode 6+ weeks of live-found bugs. Port the test files (`api2_gateway_events_test.dart`, `chat_oc2_step_gap_test.dart`, `reconnect_hardening_test.dart`, `connection_v2_requests_test.dart`, `connection_interaction_test.dart`) before writing the reducer.
2. **Server volatility**: OC2 changes weekly in beta; stable still moves (2.2.5 today, unprobed). Budget a probe + diff step and keep the dialect layer as a table with tests. Capability flags should follow the version.
3. **Static capability flags per backend** will mislead on mixed server versions (archive, notes, import/export latch themselves off at runtime on 405/501/404).
4. **Rust engine pin mismatch**: engine hard-requires 2.0.29 while the app pins 2.1.1; a native rewrite that talks to the engine must reconcile this (probably bump the engine pin and re-run its OC2 proof).
5. **Command receipt `type` value** (`'prompt'` vs real `'user'`) is unverified on live (PROTOCOLS-35).
6. **Durable log unused**: switching to it would change reconnect behaviour (replay duplicates vs refetch); needs a design decision and a live probe on current versions.
7. **Stale docs**: `contracts/README.md`, parts of `docs/connectivity-private-networks.md`, `docs/switching-clients.md`, `docs/opencode2-port-matrix.md` (OC1-flavoured) disagree with the code; trust code and tests.
8. **Security regressions are easy**: leaf-DER pin vs SPKI, redirect/proxy handling, URL credentials, raw error text, logging of `/provider` bodies. Port the transport-trust tests as contract tests on day one.
9. **Day-1 migration**: profiles + secrets + consent + pins + queues + receipts must survive the in-place update (same key names above); a missed `oc.cleartextOk.*` or `oc.certificatePin.*` would silently disable a user's plain-HTTP/pinned servers (fail-closed: they would be asked again, a pin loss would drop to PKI-only, which is a downgrade of trust: carry pins as hard requirements).
10. **Bundled assumptions about v1-shaped events** in `ConnectionController`/chat: the rewrite should define its own state model and not copy v1 names such as `message.part.delta` unless it also ports the consumers.
11. Hidden 2.2.x differences (scheduling, Claude Agent provider, new permission split between integrations/MCP/skills/plugins per the owner's brief) are unknown; plan a spike.

## 9. Suggested native module split (protocol layer)
`:protocol-core` (KMP commonMain): `Dialect` (pure, table-driven), `Transport` (Ktor/OkHttp, trust policy interface with Android actual), `SseParser`, `EventStream` (Flow + backoff + nextAttempt), `WireModels` (tolerant DTOs), `EventUnion`, `OC2Client`. `:domain` (commonMain): gateway interfaces, `ServerCapabilities` (data class + builder from probed version), value types, pure logic listed in PROTOCOLS-43. `:protocol-android`: `X509` pin trust manager, WebSocket with headers, network-change hook, secure storage adapter. Contract tests: fixtures from `test/fixtures/api2/*`, the dialect table, SSE parser vectors from `api2_sse_test.dart`, and the live-proof script. Keep `ProductException`-style "authored message + cause" split so server text cannot reach UI strings.
