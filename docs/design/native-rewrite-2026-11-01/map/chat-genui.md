### 0.2 The one idea that explains the structure

The chat is **protocol-neutral**. Every backend is mapped (in `lib/api2/*`, `lib/paseo/*`, `lib/codex/*`) into the same
`MessageWithParts` / `Part` / `ToolState` / `EventEnvelope` model (`lib/domain/models*.dart`) and the same `ServerGateway` interface
(`lib/domain/server_gateway/interfaces.dart`, 494 lines) plus `ServerCapabilities` flags (`capabilities.dart`, 395 lines). The chat
asks **capabilities**, never "which server is this". A rewrite should keep that seam exactly: it is what lets the same transcript code
serve OpenCode 2, Claude Code (via Paseo), Codex and the AI Team.

Data flow of one conversation:

```
gateway (HTTP/SSE | WebSocket | JSON-RPC)  -> neutral EventEnvelope + MessageWithParts
      -> ConnectionController (lib/state/connection*.dart, single owner; broadcasts raw events on `events` bus,
         notifies only for non-text changes)
      -> ChatScreen state (lib/ui/screens/chat_screen.dart + chat/*.dart): _messages list, version maps, deferred maps
      -> display passes (settle stale live, fold work, merge text, turn owners)  [cached per turn]
      -> kit parts (KitTurn, KitMessage, KitWorkLine, KitToolRow, KitMarkdown, KitComposer, KitRequestCard ...)
```

The ChatScreen is **one Dart library split into 70 `part` files** (State mixins hold fields, `extension _ChatX on _ChatScreenState`
holds code). It is a single-owner unit in this repo. For Kotlin, treat it as **one chat feature module with ~25 collaborating
classes** (see section 2 for the cut), not one huge class.

### 0.3 Owner rules that govern every UI decision here (carry into the rewrite)

From `AGENTS.md`, the memory index and the task brief:

- **Kit only.** Every visible component is a kit part (`lib/ui/kit/`); screens only arrange kit parts. A missing part is added to the kit.
  In Compose: one `kit` package; screens never hand-build a card/row/button.
- **No glass** (10-26: "very artificial"; Glass+Crystal styles and the refraction shader were removed): flat, solid surfaces, flat lists not boxes.
  **One sanctioned exception (owner 2026-10-30, ColorOS/HarmonyOS-style frost, `KitFrost`, commits `f52b92493`, `1ba8c9e10`)**: exactly two places - the chat's floating
  composer (chip row + field as one pane) and the chat header - are frosted (blur + 1.2-1.6x saturation + surface tint + faint noise + top hairline) **only while the conversation
  is scrolled under them; solid at rest**. User choice `KitGlassChoice` off|weak|balanced(default)|strong in pref `oc.glass` (device-wide). No refraction, no rim light.
  In Compose use `Modifier.blur`/`RenderEffect` (API 31+) behind a capability check and keep the solid fallback for API < 31 and `held-solid` cases (`KitFrost.heldBy`: e.g. reduced effects/thermal).
- **Android-native feel at maximum**: native ripple, predictive back, stretch overscroll, haptics (`KitHaptics`: send tick, done, commit,
  selection, long-press; never on scroll or plain taps), system bars.
- **Motion** 150-250 ms (`KitMotion.quick` 150 ms, `standard` 250 ms), exits faster than entrances, reduced-motion = no travel (Calm keeps fade).
- **Plain words, never raw errors**: server/exception text only under "Details", redacted (`KitRedact`). Every failure = fixed sentence + a way forward.
- **Obvious options first**: main actions as visible rows, not in overflow menus. **No new bar/row levels**: fold new status into an existing row.
- **Actions name their target**; **steer, never queue** (sending mid-turn adds to the turn wherever steering is possible).
- **Component hard max widths**: conversation column 700 dp (`KitLayout.paneDetailMaxWidth`), prompt bubble <= 85% of the column (`bubbleMaxShare`)
  with a 48 dp start inset, composer field <= 40% of window height (`composerMaxShare`), request card <= 45% of window height (60% large).
- **Text scale**: frame/chrome text capped at 1.3x, reading text (replies, code) scales fully; kit does it, not screens.
- **Arabic RTL** everywhere (rails mirror, bidi isolation of agent text, directional icons mirrored, code always LTR).
- **Teach hidden gestures** (hold Send = send later, hold Stop = stop after this step, hold mic = push to talk): tips via `TipController` (`oc.tips`).
- **Security invariants**: every URL the app did not author goes through `openExternalLink` (https direct; http after insecure confirm;
  everything else refused; host shown before opening); never echo provider credentials; per-profile keys named `oc.<what>.<profileId>`.

## 2. Features

### A. Transcript model and streaming

#### CHAT-GENUI-01 Transcript model (the vocabulary everything else uses)
- **What**: A conversation is a flat server list of messages; the person reads **prompts**, **turns**, **steps**, **notices**, **replies**
  (frozen as STATE-16 / KIT-41 in `lib/ui/screens/chat/transcript_turns.dart`):
  *prompt* = what you sent (words + attachments); *turn* = one prompt + everything the agent did until it handed back (gets exactly one footer);
  *step* = one model call = one assistant message (thought, a sentence, tool calls; boundaries between steps are never drawn);
  *notice* = something that happened during a turn that nobody typed (project moved, instructions changed, context added, compaction);
  servers file notices under role `user`, they do **not** end a turn; *reply* = the prose of a whole turn (what "copy" copies).
- **How**: `lib/domain/models/models_messages.dart`:
  `MessageInfo{id, sessionID, role user|assistant, agent, providerID, modelID, cost, Tokens{input,output,reasoning,cacheRead,cacheWrite}, MsgTime{created,completed}, errorText, errorKind(MessageErrorKind), finish(stop|length|tool-calls|content-filter|error...), parentID}`;
  `Part{id, type text|reasoning|tool|file|step-start|step-finish|snapshot|patch|v2:switch|v2:notice|v2:compaction|..., text, messageID, callID, toolName, ToolState, mime, filename, url, synthetic, ended, noticeMetadata}`;
  `Part.isRenderable` = not synthetic and (non-blank text|reasoning, or tool, or file); bookkeeping parts (`step-finish`, `patch`, `snapshot`) draw nothing.
  `ToolState{status pending|running|completed|error|cancelled, title, input map, inputJson (raw streamed text while pending), output, outputValue, metadata, outputFiles[], segments[] (ordered text/file interleave, OC2 only), startedAt, completedAt, pruned, executed}`.
  OC2 variant rows are mapper-tagged parts whose type starts `v2:` (`v2VariantPart` in `transcript_turns.dart`): `v2:switch` (model/agent/location switch), `v2:notice`, `v2:compaction`.
  A `subtask` part (command run as sub-agent) is mapped to a text part with the description.
- **Traps**:
  - `declined` tool = status `error` + output containing "user declined" / "user rejected permission": the person's choice, NOT a failure, NOT a stop.
  - `_toolRan`: OC2 beta stamps `executed:false` on tools that plainly ran; outcome wins over the flag (completed/error/has time = executed).
  - `status` unknown -> `running`. `cancelled` renders as Stopped.
  - `pruned` (v1 `time.compacted`, v2 `time.pruned`): output gone, nothing can be opened.
  - Tool output files are extracted from output/attachments/`filePath`/`outputPath` metadata (`_toolOutputFiles`: depth<=6, max 8 files, only explicit file signals; plain URLs or path-like prose are NOT files; `read` attachments inherit the requested file name).
  - `MessageErrorKind.fromName` normalises names (`ContextOverflowError`, v2 `provider.auth` with empty message...); `refineFromText` recovers kind from text ("ProviderModelNotFoundError: ...", "Not logged in - Please run /login", "OAuth session expired", "failed to authenticate", "invalid api key").
  - `sessionErrorFallbackText` gives plain sentences for empty server messages (provider auth, overflow, length, content filter, aborted, model not found).
  - `errorHeadline` = first non-stack line, strips `XError:` prefix; `errorHasDetails` = has more lines -> show Details.
- **Data**: in-memory only (plus the text-only excerpt cache, feature 04).
- **Tests (catalog)**: `test/tool_state_test.dart:5,36,58`, `test/v2_transcript_rows_test.dart:68`, `test/run_result_test.dart`.
- **Stance**: KEEP the model verbatim as a Kotlin common data model; keep mappers per backend outside the chat module.

#### CHAT-GENUI-02 Live event pipeline (streaming into the transcript)
- **What**: Tokens appear while the agent writes; parts update in place; nothing flickers or duplicates.
- **How**: `lib/ui/screens/chat/chat_stream.dart` (561 lines). The screen subscribes to `ConnectionController.events` (broadcast bus of `EventEnvelope{type, properties, directory, project, workspace}`). Events handled for the open session:
  `message.updated` (info), `message.part.updated` (whole part), `message.part.delta` (`{messageID, partID, field, delta}`), `message.part.removed`, `message.removed`,
  `session.idle` / `session.status` (busy|idle|retry), `session.error`, `session.updated`, `session.compacted`, `session.history.reset` (with `removedFrom`),
  `session.skill.changed`, `session.inbox.delivered`, `session.transcript.stale` (the last three trigger a recent-history refetch), `shell.*`, `session.shell.changed`.
  Connection-level events (`lib/state/connection/events.dart`, `session_events.dart`, `request_events.dart`) also handle `permission.asked/replied/updated`, `permission.v2.*`, `question.*`, `question.v2.*`, `form.v2.created/replied/cancelled`, `session.inbox.enqueued/cancelled/delivery.changed`, `session.revert.staged/cleared/committed`, `session.usage.updated`, `session.viewed`, `todo.updated`, `retry`, `busy`, `idle`, `catalog.updated`, `config.updated`, `agent.updated`, `session.model.selected`, `session.agent.selected`, `session.metadata.updated`, `session.instructions.updated`, `pty.*`.
  - **Versioning**: every message/part event does `_partVersions[messageID\0partID] = ++_eventVersion` (and `_messageVersions[id]`) **synchronously**. A concurrent history read remembers `versionAtStart`; entries whose version advanced during the read win over the snapshot (feature 03).
  - **Deltas**: supported fields only `text`, `input`, `raw`, `state.input`, `state.raw`. Text appends to a `text`/`reasoning` part; input/raw append to a pending tool's `inputJson`. A delta whose part is not loaded yet is stored in `_deferredPartDeltas[key]` and replayed when the part/message arrives. Parts of unloaded messages go in `_deferredParts` until `message.updated` creates the message (a late edit to old history is NOT a new row; it only triggers a refetch if it could be in the recent window).
  - **Coalescing (C1)**: model mutation is synchronous and ordered; the rebuild is batched: first delta of an idle stream flushes on the next microtask, then at most one flush per **50 ms** while deltas keep flowing (leading+trailing edge). `debugChatStreamFlushes` counter exists for tests.
  - **Optimistic bubble reconcile**: `message.updated` for a user message first tries `_reconcilePendingMessage` (feature 32).
  - `message.updated` with `errorText` on an assistant message sets the prompt error banner, notes the turn error, and if the error text implies "model not found" re-reads the model catalog. A *new* assistant step after an error clears the stale banner.
  - `session.idle` without a prior busy clears the phone's local turn guess.
- **Traps**:
  - OC2 deltas are volatile: **after a reconnect reconcile by refetch, never replay** (the beta session log replays durable events only; deltas and `tool.progress` never replay).
  - `message.removed` sets `_resetHistoryOnLoad` + `_olderNeedsReload` and drops pending sends with that id.
  - Controller-wide `notifyListeners` must NOT fire for text part updates (perf baseline in `docs/qa/codex-perf-2026-09-28/chat.md`); the chat listens on the bus.
  - `session.history.reset` with no staged revert removes messages `>= removedFrom` immediately and clears deferred maps before reloading (never reveal a stale staged tail).
- **Data**: none. **Tests**: `test/chat_live_events_test.dart`, `test/api2_gateway_events_test.dart:443` (lost tool results settle), `test/revamp/slice_p4_4_test.dart:173` (5,000 fragments merge linear), `test/paseo_gateway_test.dart:583`.
- **Stance**: KEEP semantics. In Kotlin this is a reducer over a `StateFlow<TranscriptState>` fed by a `SharedFlow<Event>`; keep the version-fence maps; coalesce UI emission to <=1 per 50 ms.

#### CHAT-GENUI-03 History hydration, older pages, merge with live state
- **What**: Opening a chat loads the newest page; scrolling to the top shows "Load older"; reloads after reconnect/compaction merge without losing live changes or the reader's place.
- **How**: `chat_history.dart` (496 lines). `_load({resetHistory})` is fenced by `_loadGeneration` + `_HistoryScope{api, locationRevision, profileId, session}`; a stale result is dropped. Reads via `ConnectionController.loadSessionTail` (shared with a prefetch fired on the tap that opened the chat; also saves the opening excerpt) or `readHistoryAtStagedBoundary` for a staged revert (`lib/domain/session_history.dart`: skips raw pages that are entirely staged-away rows without inventing a cursor, keeps raw boundary page so Clear can rehydrate). Older pages: `api.messagePage(session, cursor:)`; a cursor repeated (`_usedOlderCursors`) or HTTP 400/410 -> "Reload" (cursor expired) instead of looping.
  `_mergeHydratedMessages`: for every hydrated message, if its version advanced since read start keep the live copy; parts likewise (`_partVersions`); live parts missing from the snapshot but newer are appended; messages not in the snapshot are kept only if pending send / newer / `preserveUnseen` (older-page loads); withdrawn prompts are skipped (`WithdrawnPromptMemory`).
  Reader place: `_historyAnchor()` (first visible message id + alignment) is taken before and restored after the merge unless a jump to newest happened meanwhile (`_latestJumps` counter).
  `_scheduleRecentHistoryRefresh` debounces **150 ms**. A refresh is also issued on resume (watching), inbox delivery, skill change, stale transcript, end of a run that crossed a drop/resume.
  The link being down while messages are on screen: say nothing (the connection line speaks); never "isn't answering" after a trip to the background (owner 2026-10-27).
- **Traps**: `anchor` lost (message gone) -> go to latest quietly with no "History refreshed" note (commit `f614d6a3b`). Perf marks `chat.open_to_fresh`, `chat.open_to_first_transcript`.
- **Tests**: `test/chat_cold_open_test.dart`, `test/staged_revert_message_count_test.dart`, `test/chat_earlier_pill_scroll_test.dart`.
- **Stance**: KEEP (generation + scope fences and version-merge are the correctness core).

#### CHAT-GENUI-04 Opening excerpt (instant first paint)
- **What**: While the first history read is on its way the chat shows the end it had last time (read-only text), not placeholder turns (speed contract item 2). It already carries the phrase row and the agent chip so nothing jumps when live history lands (jitter J9, `0380766e5`).

- **Data**: SharedPreferences `oc.chatTail.<profileId>` (JSON). Deleted with the profile.

- **Stance**: KEEP.

#### CHAT-GENUI-05 Display passes (what the transcript draws is derived, not stored)
- **What**: Before drawing, three passes turn the raw message list into what the person reads.
- **How**: `chat_page_cache.dart` (400 lines) `_deriveTranscript`; passes in `lib/domain/transcript_settle.dart`, `transcript_turns.dart`, `message_view.dart`:
  1. **`settleStaleLive`** (domain): a closing event that never came is settled: a running **compaction line** is hidden (kind becomes `compactionPassed`, message KEPT so row indexes stay aligned) once anything follows it or the chat is not busy; a **tool still `running`** is shown finished when the same turn wrote words after it or the conversation is no longer busy - unless it is a background process (`background:true`). A late `running` report cannot revive a finished call. Returns the same list object when nothing changed so caches hold.
  2. **`_markFoldedWork`** (finished turns only): the passing words an agent says between steps ("Now let me run the tests:") and mid-turn notices fold under the turn's one work line; an explanation written before the last step (`_isPassingWords` false: >1 line, paragraph break or code block) **stays in view** ("the work folds; the prose never hides", decision 2026-09-28). The running turn keeps everything in place.
  3. **`_mergeTextParts`** (linear time; commit/perf item #1): adjacent text parts of one reply are merged; tracks "ends with newline" incrementally; keeps first-part identity, skips whitespace-only fragments.
  4. **`_turnActionOwners`**: which single message carries each turn's footer (the step ending the turn if it draws anything, else the last step that does); the running turn has none.
  Caching: everything before the newest prompt is kept while message/part objects are identical (`identities` list); a stream flush recomputes only the newest turn (`debugChatDisplayPassMessages` counter proves it). `_pageConnectionKey()` compares ~50 connection fields so a notification that moved none is not a rebuild.
- **Traps**: the "transcript reads rows, parts and turn owners by the same index" invariant: dropping a message in a pass shifted every later index and the newest row read past the end ("This part of OpenCode hit an error" under a compaction, 2026-10-28, `43fabb514`). Never remove messages in a display pass; neutralise them.
- **Tests**: `test/transcript_settle_test.dart:61,98`, `test/chat_compaction_midturn_test.dart`, `test/chat_rebuild_budget_test.dart`.
- **Stance**: KEEP the three passes as pure functions over immutable lists (easy to unit-test and cache in Kotlin).

#### CHAT-GENUI-06 Turn rows (prompt, steps, work line, notices, markers)
- **What**: The list is virtualised, one server message per row; a turn spans several rows drawn as `KitTurn` segments (first = prompt, middle = step, last = ends turn + footer).
- **How**: `message_view.dart` (763), `transcript_turns.dart` (748), `transcript_rows.dart` (798), kit `kit_turn.dart`, `kit_message.dart`, `kit_work_line.dart`, `kit_step_timeline.dart`, `kit_step_node.dart`, `kit_step_light.dart`, `kit_step_signal.dart`, `kit_tool_row.dart`.
  - **Prompt bubble**: end-aligned, hugs words, <=85% width, its words go through the same `KitMarkdown` with `selectable:false` (`_proseMarkdown` in `transcript_turns.dart:242`; a prompt's long-press is the prompt menu; thoughts and notices use the same non-selectable path), path chips counted, attachments as thumbnails (photos) or read-only chips, "Not answered" mark when unanswered.
  - **Reply**: plain prose, Markdown (feature 16), blocks separated by the kit gap; agent-card calls are lifted OUT of the work line and drawn as cards in the reply (`_MessageViewAgentCards`).
  - **Work line** (`KitWorkLine`): one chip per turn - "Read 3 files . edited 1" - states running / waitingForYou / done / endedFailed / stopped; opens in place to a **timeline** (rail + dots for sentences, tiles with glyph for tool calls, live "light" for the running step, compact change preview for writes/edits); opening folds steps in/out over 250 ms, new steps slide+fade in. Failures the agent got past stay quiet; only an unrecovered failure or a produced file opens it unasked. Long running turns keep newest steps in view and fold older under "Show N earlier steps". A thought that opens with a heading line titles the next step (`_AssistantPartRun.heading/note`); placeholder thoughts ("No reasoning available.", markup-only) are dropped.
  - **Notices** (`TranscriptNotice`): one line that opens to its text; title = first short line; failures said in words, never red, open at first; compaction words use host details when known (`_compactionWords`); a failed newest compaction offers "Compact again".
  - **Marker** (`TranscriptMarker`): hairline-word-hairline for model/agent/location switches and the running compaction ("names the model, not its id", `f375ee90e`).
  - **Background results** (`BackgroundShellResultRow`, `BackgroundAgentResultCard`): OC2 files finished background commands as notices whose text is a raw `<shell ...>` envelope - shown as one line (command as a person says it + how it ended) opening to command/output; server-authored agent results stay separate from the parent's reply with protocol text behind Details.
  - **Unknown `v2:` types** degrade to a generic notice; an unknown message that is only an id-like word ("idle") draws nothing.
  - **Watching a team agent**: a long user-role message was not typed by the person (start-up instructions, mail, nudges) -> one folded line, never a bubble; leading `[phone] ... 2026-...` stamp dropped.
- **Traps**: `_isPrompt` excludes server notices filed as `user`. A prompt waiting in the server inbox is NOT a prompt row (feature 33). The turn's "live/end" row logic: footer absent while busy even if the newest step is written; stopped/cut-off/interrupted lines (feature 08/51). Alignment of "meta line" (model label only when changed, usage + time only when the person opted in via the timestamps toggle).
- **Tests**: `test/kit/kit_message_test.dart:155`, `kit_step_timeline_test.dart:156`, `kit_work_line_test.dart:177`, `v2_transcript_rows_test.dart:68`, `chat_background_result_test.dart:57`, `background_tasks_test.dart`.
- **Stance**: PORT as Compose components with the same state machine; the kit docs `docs/ux-system/kit-api/KitTurn.md`, `KitMessage.md`, `KitWorkLine.md`, `KitStepTimeline.md`, `KitToolRow.md` are the normative specs (frozen 2026-09-26) - give them to the rewrite agents.

#### CHAT-GENUI-70 The card contract (agent -> app)
- **What**: An agent calls one MCP tool on the app-owned server **`oc-ui`**: **`show`** (display a card; may ask) and **`find_connectors`** (read-only catalogue search). The card is one JSON object `{v:1, id, title, body:[Node 0..40], ask?: Ask, connector?: {catalogId, reason}}` (`ask` and `connector` are mutually exclusive). Unknown keys anywhere -> unreadable (strict); wrong types and explicit nulls invalid; no coercion.
  Nodes (`type` + exact fields): `text`(<=2,000), `keyValue`(rows 0..20, key 1..60, value <=200), `list`(items 0..30 `{text, done?}`, style bullet|check), `table`(1..6 columns <=80, 0..20 rows exactly column count, cells <=80), `chart`(kind bar|line, unit <=24, labels 1..30 <=80, 1..3 series each `values` length == labels, finite numbers, name <=80), `code`(language <=32, text <=4,000, display only), `diffStat`(files 0..30 `{path<=256, added, removed}` ints 0..2^53-1), `progress`(label <=120, value finite 0..1), `callout`(tone info|warning|success, text <=500), `link`(label 1..120, url <=2,048 absolute **https** only, host non-empty, no userinfo/whitespace/control chars/backslash, port <= 65535).
  Asks (`kind` + exact fields): `choice`(options 2..8 `{id [a-zA-Z0-9_-]{1,32}, label 1..120, detail<=200}` unique ids, `multi?`), `form`(fields 1..12 `{id [a-zA-Z0-9_]{1,32}, label 1..120, type text|multiline|number|toggle|select|date, required?, placeholder<=120, default?, options? (select only, 2..20), min?/max? (number only, min<=max)}`, `submitLabel<=24`), `confirm`(confirmLabel/cancelLabel <=24, tone normal|danger), `photo`(purpose 1..200, max 1..4). `file` and `voice` asks are reserved -> `unsupportedAsk`.
  Limits before normalisation: compact UTF-8 JSON <= **32,768 bytes**, depth <= 8, <= 4,096 values/containers, string length counted in Unicode **scalar values** (reject unpaired surrogates), single strings <= 65,536 UTF-16 units / 32,768 scalars, cumulative string bytes <= 32,768, cyclic input invalid. Presentation text: strip C0/C1 controls except LF/TAB and Unicode bidi controls (U+061C, U+200E-200F, U+202A-202E, U+2066-2069); trim labels/titles; reject empty required labels; preserve whitespace in code/text bodies. IDs/URLs validated as supplied, never repaired. Credential-solicitation heuristic: ids/labels matching `password|passwd|token|secret|apikey` after separator normalisation -> `secretField`.
  Tool result text (the helper returns at once, never claims delivery): "Card accepted for display in OpenCode Mobile. If it asks a question, end your turn and wait for the person's next message tagged [oc-ui answer <id>]. This call does not return their answer." Invalid/disabled/unknown calls return a generic MCP `isError` without echoing input.
- **Admission** (`genUiFromPart`): exact qualified tool names only (`mcp__oc-ui__show` for Claude Code, `oc-ui_show` for OpenCode 2; never suffix/substring/title match), assistant-owned **non-synthetic** tool part, complete structured input (`toolState.input` non-empty; a streamed input preview is NOT JSON to parse; no reconstruction from `inputJson`/raw deltas), `status == completed`, `executed == true`, non-empty callID/message/session/scope. Pending/running/error/unexecuted calls stay ordinary tool rows and cannot be answered. Missing input/name after event loss triggers reconciliation, not a permanent invalid mark.
- **How**: `lib/domain/genui/gen_ui_codec.dart` (341) + `gen_ui_validation.dart` (539) + `gen_ui_mapping.dart` (110) + `gen_ui_nodes.dart` + `gen_ui_asks.dart` + `gen_ui_answers.dart` + `gen_ui_types.dart` (`GenUiScope{profileID, sourceId, directory, workspace}`, `GenUiCard{scope, id, title, sessionID, callID, messageID, revision, body, ask, connector}`, `GenUiParse` = `GenUiParsed | GenUiUnreadable(reason: notACard|version|tooLarge|unknownKey|badValue|secretField|unsupportedAsk)`), `gen_ui_status.dart`, `gen_ui_controller.dart`, `lib/domain/agent_tools/agent_tool_adapter.dart` (`PhoneTool.cards = {server 'oc-ui', tools [show, find_connectors]}`).

#### CHAT-GENUI-72 State machine and receipts
- **What**: Card states: **waiting** (newest eligible ask after the latest authoritative user turn; actionable only when the session is idle), **answered** (receipt), **passedOver** ("Not answered"), **report** (no ask), **unknown** (incomplete/stale history: never equivalent to answered, absent or actionable). Delivery states (controller, not transcript facts): idle, held, sending, deliveryUnknown, failed.
  Answer wire format: a normal user message of exactly two lines:
  ```
  [oc-ui answer db-choice] Postgres
  {"v":1,"cardId":"db-choice","callId":"call_123","value":{"choice":["postgres"]}}
  ```
  Line 1: app-generated single-line summary <= 240 scalars (regex `^\[oc-ui answer ([a-z0-9-]{1,48})\] (.+)$`, no TAB, control-stripped). Line 2: compact JSON <= 32,768 bytes, envelope keys exactly `v/cardId/callId/value`; `value` is exactly one of `{choice:[ids]}`(1..8 distinct), `{form:{fieldId:string|number|bool}}`(<=12, string <=2,000 scalars, absent optional fields omitted never null), `{confirm:bool}`, `{photo:n}`(1..4). Summaries: choice = labels joined ", "; form = "Submitted N fields"; confirm = confirmLabel/"Confirmed" or cancelLabel/"Declined"; photo = "Submitted N photo(s)". Validate against the ORIGINAL ask at encode and decode (date fields: real calendar date with leap years; select ids known; numbers within min/max; required text non-blank; extra keys invalid).
  Settlement rules (`genUiStateFor`): only an **authoritative, non-synthetic user** message after the matching call, same scope/session, whose envelope (cardId + callId) validates, settles a card; the FIRST later real user message either answers it (matching envelope) or passes it over; reports never supersede asks; a newer ask supersedes an older unanswered ask (passedOver); duplicate message ids, wrong session, repeated identity or changed revision -> `unknown`; incomplete tail -> `unknown`. Hide the JSON line only for a fully validated matching receipt, otherwise ordinary text. A tag is correlation not proof of UI authorship. Revert / message-or-part removal / changed tool input invalidates dependent state and triggers reconciliation. Photo receipts report the submitted count and must not claim the server retained images (on Paseo the echo is text-only).

## 7. Performance notes (what the Flutter app learned the hard way)

- **Per-frame work is bounded by caching**: derived display passes cached per turn (stream flush recomputes only the newest turn; `debugChatDisplayPassMessages`), `_pageConnectionKey` skip, Markdown parse cache keyed by source with settled blocks reused (`debugParseCount`), grammar parse cache 48 entries, diff file facts cached per immutable `KitDiffFile`, decoded `data:` image bytes cached per part, `_SentFileImage` provider shared per path+profile, `_PathLink` memoised futures.
- `docs/qa/codex-perf-2026-09-28/chat.md` baseline: one fragmented 5,000-part reply was ~15x the 1,000-part cost despite the same flush/parse counts (quadratic text merge + full-block layout); fixed by linear `_mergeTextParts` and a semantics boundary. **Test fixture to port**: `test/perf_chat_test.dart` (1,000/5,000 parts in two shapes; 10 spaced deltas + a 100-delta burst; counts, not timings, are asserted).
- Scroll perf (2026-10-23/24): the earlier-messages pill must not rebuild per scroll frame (ValueNotifier); the transcript sits in a `RepaintBoundary`; blur/halo layers recorded per frame cost 47 ms/frame on the emulator (the reason Glass was removed); frost on header/composer must live on its own layer.
- `PerfTrace` marks to keep: `chat.open_to_first_transcript` (attrs source saved_excerpt|live), `chat.open_to_fresh`, `chat.send_to_bubble` (order bubble_first|transport_first), `chat.send_to_ack`, `prompt.first_token`, `prompt.turn`, `events.connected`, `lifecycle.reload` (feed the in-app Performance report the owner pastes into issues).
- Large inline tool output is cut before it reaches the block (PERF-2); code reader virtualised per line; diff highlighting lazy per row and skipped for huge/unknown files; markdown tables cell-measured once.
- Cold start / memory: SharedPreferences read whole at startup, so queue/draft stores are size-capped (offline queue 60 MiB ceiling, drafts 50). A native store (Room/SQLDelight) removes that tax.
- Memory on phone hosts: Android 15 background caps; the Linux rootfs hosts the card helper (tiny Node process); card recovery must not wake agents (76).

## 8. Risks and rewrite considerations

1. **Size/ownership**: the chat is ~48k lines of Dart across screen+kit+widgets+domain. It is also the most hand-polished area (every owner date in the comments is a bug someone hit). Do not "simplify" a branch without finding the test or comment that created it. Port **domain logic and its tests first** (transcript model, settle/fold/merge passes, turn stall, run result, search index, phrase chips/moment, context usage, offline queue rules, review reference formatting, card codec/state/answers, permission wording, tool presentation, attachment MIME/office text, redaction, dev preview rules, background tasks, error classification). Roughly 124 catalog behaviours + ~1,500 logic tests map onto these and run as plain JVM tests.
2. **Compose-specific traps**
   - Reverse-layout `LazyColumn` + anchor restoration on prepend/reload + "item positions" (first visible id/alignment) + measured scroll-to-center needs a purpose-built `TranscriptListState`; `animateScrollToItem` across thousands of unmeasured items is the known jank source. Prototype early with a 5,000-part single message and a 1,000-message history.
   - **Selection**: SelectionContainer across custom Markdown blocks, RTL, and bidi-isolated agent text; prompt bubbles must not be selectable (long-press = menu).
   - **Streaming text**: per-word fade needs span-level alpha with paint-only invalidation (use `drawWithContent`/`TextLayoutResult` or `AnnotatedString` colour animation with stable layout); keep "no layout change when fresh runs fade".
   - **IME**: keyboard images (`contentReceiver`), multiline field with a height budget that does not reparent the focused field, composing text preserved across prompt-history navigation.
   - **Predictive back + container transform** (from the demo): list-row -> chat transitions fight predictive back; disable the transform during the back gesture. The chat's Back rule (instant when saved, else wait for save) maps to `BackHandler`/`PredictiveBackHandler`.
