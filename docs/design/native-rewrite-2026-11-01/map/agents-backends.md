Three separate "agent" families live here and must not be confused:

1. **Phone agents** = CLIs (Claude Code, Codex, ACP agents) installed into the app's own Ubuntu as Linux user
   `oc` (uid 1000) and driven by one Paseo helper daemon on `127.0.0.1:4099`. The app talks to Paseo only.
2. **Remote agents** = a Paseo daemon on the owner's PC over Tailscale (saved server, backend `paseo`) and
   a Codex app-server (saved server, backend `codex`). Same client code as (1), different transport target.
3. **AI Team** = multi-agent project orchestration, with two engines: the native Rust **phone engine**
   (projects/lanes/merge queue, drives OpenCode 2 sessions) and **Gas City** (Go supervisor on a PC, or
   inside the phone's Ubuntu, or in Termux).

OpenCode 1 is **gone** (`lib/api/` removed, commit 40ba4fa32; "OpenCode 1 removed; phones still on it move to
OpenCode 2 automatically" 55e0c56b6). `AgentRoute.opencode2` stays in the catalog only as the server type row.

## 3. Feature inventory

### A. Routing, catalog and chat integration

#### AGENTS-BACKENDS-01 — Agent catalog and `AgentRoute`
- **User sees:** the list of agents this phone can run (Claude Code, Codex, Gemini CLI, Qwen Code, Kilo, Cline, Goose, Oh My Pi, fx) with sizes ("98 MB") and plain limitation lines; OpenCode is a separate chat choice.
- **How:** `lib/domain/agent_catalog.dart` is app-authored data, never inferred from agent identity. `AgentRoute { opencode2, paseoNative, acpPaseo }`. `AgentDescriptor` = id, name, iconKey, route, providerId, signInMethod (`browserOAuthHost | apiKeyHost | none`), `AgentInstallRecipe` (version, executable, per-arch `AgentArtifact`, `launchArgs`, `signInArgs`), `AgentCapabilities` (resumeVerified, modelList, permissions, images, cancel), availability (`available | limited | hidden`), `limitation`, `resumeReason`. `AgentArtifact` enforces HTTPS without credentials, exact lowercase SHA-256, safe archive member, positive sizes. Formats: `executable, tarGz, tarBz2, zip, npmTarGz`.
- **Pins (as of this commit):** `opencode2` 2.1.1 (`@opencode/cli-linux-arm64` / `x64-baseline`, member `package/bin/opencode`, launch `serve --hostname 127.0.0.1`); `claude` 2.1.294 (official `downloads.claude.ai/claude-code-releases/2.1.294/linux-{arm64,x64}/claude`, 252 MB, sign-in `auth login --claudeai`); `codex` 0.162.1 (GitHub `openai/codex` musl tarballs, launch `app-server`, sign-in `login --device-auth`); `gemini` 0.63.0 (npm tarball, `--acp`, needs Node); `qwen` 0.25.0 (npm, `--acp`, API-key host); `kilo` 7.8.3 (`acp`, sign-in `auth login`); `cline` 3.0.68 (`--acp`, sign-in `auth`); `goose` 1.54.0 (`acp`, sign-in `configure`, API-key host); `omp-acp` 18.5.1 (executable `omp`, `acp`); `fx` 0.0.13 (`acp`, sign-in `login`). Full URLs and hashes: `lib/domain/agent_catalog.dart` `_builtInCatalog()` (copy verbatim, they are verified pins).
- **Constants:** `agentResumeUnverifiedLabel = "Can't reopen old chats"`, `agentStartsNewChatNote = 'Starts a new chat'`.
- **Tricky:** an installable download proves nothing about sign-in, resume or phone compatibility. Capabilities come only from certification cells (BA4), never from a name. `descriptor.installableOn(arch)` is separate from selectable-for-chat.
- **Tests:** `test/agent_catalog_test.dart` (7), `agent_certification_test.dart` (16).
- **Rewrite stance:** PORT as pure Kotlin data in `commonMain`; keep the validators; keep the pins file as a single source (it is also read by scripts).

#### AGENTS-BACKENDS-02 — Agent rows and readiness state machine
- **User sees:** per agent one row with one next action: Install, Run phone check, Sign in, Resume, or "Ready to use"; plain status lines ("Stopped while the app was in the background.", "Usage limit reached. Try again when it resets.", "This phone cannot run this agent.").
- **How:** `lib/domain/phone_agents.dart` `buildAgentRow(descriptor, architecture, serverCapabilities, runtime)` is a pure function. Order of checks (keep it exactly): catalog hidden → `catalogUnavailable`; no runtime fact or not installed → `unsupportedArchitecture` / `unverifiedDownload` / Install (`runtimeUnknown` if never inspected, `needsInstall` if inspected); not `architectureQualified` → `needsQualification` + Run phone check (a fresh install has no running host, the check starts it, never "Resume"); `stoppedInBackground` → Resume; host not available → Resume; sign-in not yet inspected → "Checking sign-in on your phone" (`runtimeUnknown`); `limitReached`; `failed` → signIn fix; not `signedIn` → signedOut (apiKeyHost says "Set up a provider key on the host"). Ready rows: `chatVisible/chatSelectable true`; capabilities = runtime proof AND server flags (`permissions` needs `hostAgentPermissionActions`, `images` needs `promptAttachments`). `installedOnPhone` getter. `PhoneAgentRuntime` carries `checkRequiredReason` (`firstCheck | agentVersion | helperVersion | installationChanged`).
- **Owner rule 2026-10-03 "Don't hide":** an agent whose resume is unverified is shown and selectable, labelled "Can't reopen old chats"; `UnverifiedResumePolicy.hide` cannot hide on resume alone.
- **Tricky:** `signInPhase == null` means "not inspected", never "signed out". A re-read that cannot run keeps the last signed-in/out answer (commit dc67923c0, 5e161bbea). A row still "Checking sign-in…" is re-read after 5 s (`_paScheduleSignInRecheck`). Setup inventory (`setupVisible`) differs from chat choice (`chatVisible`), otherwise hiding uninstalled Claude would remove its Install journey.
- **Tests:** `phone_agent_*` files (19 files / 168 tests), `agents_ui_test.dart`.
- **Rewrite stance:** PORT the function and its table-driven tests first.

#### AGENTS-BACKENDS-03 — Agent chip, selected agent and model per agent
- **User sees:** New conversation has two chips, project and agent; the composer says "Ask Claude Code…"; the model chip lists only that agent's models; the choice is remembered.
- **How:** `selectedChatAgentId` reads `oc.chatAgent.<profileId>`; falls back to `openCodeChatAgentId` when the agent is not selectable (but before the first row read the saved choice stands, so the chip does not flicker). `selectAgentModel(agentId, modelId)` writes `oc.agentModel.<profileId>` (JSON `{agentId: modelId}`). `agentModels(agentId)` reads the provider's models from the open Paseo source (any `/root/projects/...` folder opens the global provider list), mapping name/isDefault. Model names are remembered (`rememberAgentModels`, `agentModelLabel`) so rows say "Sonnet" not an id. Chip is a visible chip, not a menu (owner: obvious options first).
- **Tricky:** folders outside `/root/projects/` disable Send for phone agents and say why ("Agents on this phone work in projects under /root/projects. Choose one of those."). "In a separate copy" (worktree launch) is hidden for agents.
- **Rewrite stance:** PORT; keep the preference key formats if the migration reuses them.

#### AGENTS-BACKENDS-04 — One backend per conversation (agent backend controller)
- **User sees:** opening a Claude conversation does not reconnect OpenCode; the model chip, approvals, auto-approve, banner and Stop are Claude's own; going back to OpenCode is instant.
- **How:** `ConnectionController.agentBackend(...)` = a second controller with role `agent` connected to a **virtual** Paseo profile id `<phoneProfileId>.agents` (`agentBackendProfileSuffix`), never saved in the profile list, transport leased from the host (`transientTransport`). `backendForConversation(sessionID)` resolves the owner: `_paOwners[id]` → main's own sessions → live agent backend → other servers' side controllers. Chat routes are wrapped so the screen reads the backend's controller (`connProvider` override). Docs: `docs/design/one-backend-per-conversation-2026-10-05.md`, `backend-differences-scope-2026-10-05.md`.
- **Data:** agent backend keys are `oc.<what>.<phoneId>.agents` and are swept with the phone profile (`phone_agent_owner.dart:167` matches `oc.*.<owner>.agents`).
- **Tricky:** the old design swapped one controller's gateway per conversation (`_paActivateRoute`); it broke banners, watchdogs, reopen rules and auto-approve separately. Never go back. The backend is created on first need, started with the helper, kept connected while the helper runs, recovered when Android stops the helper (`recoverPhoneAgentBackend`).
- **Rewrite stance:** PORT as architecture, not code: a conversation holds a reference to its backend object; the UI never asks "which server is global".

#### AGENTS-BACKENDS-05 — One conversations list (merged feed)
- **User sees:** one list for OpenCode chats, phone agent chats and other servers' chats; every row starts with the agent's mark and name; Needs you, Running, then recent; a quiet "Loading Claude Code conversations…" line; Done tag for runs that ended unseen.
- **How:** `lib/domain/merged_chat_feed.dart` `MergedChatFeed(defaultSourceId:'opencode', sources:[NamedChatFeedSource…])`; source ids `opencode`, `paseo:<directory>` (max 4 folders: `_maxPaseoSources`), and side servers (`side_connections.dart`). `ChatFeedItem` has `identity`, `sourceId`, `agentId`, `agentLabel`, `sourceLabel`, `canReopen`. Sources keep partial failures (one unreachable folder never hides others). Saved rows paint first: `oc.agentFeed.<profile>` (≤200 rows), `oc.mainFeed.<profile>`, `oc.sideFeed.<serverId>`, `oc.agentSignedOut.<profile>` (so the signed-out line is present from first paint), `oc.phoneAgentsUsed.<profile>` (bool: hold first paint). First-paint hold is 4 s (`_paFeedHold`); the loading line stops after 30 s (`_paReadingFor`); while the helper starts, folders are re-read every 3 s for 30 s then every 15 s for 2 more minutes (max 18 retries), and every 5 s for rows still "reading". A saved row never claims to be running; live rows replace saved rows folder by folder without an entrance animation (jitter J3/J4).
- **Tricky:** use `item.identity` as list key (session ids collide across sources). `ChatFeedFilter.agentId` composes with project/needs-you/subagents filters. Conversations the daemon holds as older copies of one conversation (Paseo mints a record per resume) are folded and the older ones archived in the background (see 21).
- **Tests:** `paseo_chat_feed_source_test.dart` (13), `merged_chat_feed` tests, `phone_agents_*`.
- **Rewrite stance:** PORT the model; the "paint once" behaviour is a hard requirement (owner jitter list).

#### AGENTS-BACKENDS-06 — Open, resume and replace an agent conversation
- **User sees:** tapping a row opens it live; an old Claude chat reopens and continues with memory; if it cannot reopen the row says "Can't reopen old chats / Starts a new chat" and a **Start new chat** action that needs the person's explicit tap.
- **How:** `openChatFeedItem` → `_paOpenChatFeedItem` (phone_agents_routes.dart): saved row of a folder not read yet opens on the agent backend directly (starts the helper); still loaded in the helper → live; otherwise **open in place** by reading the timeline (`fetch_agent_timeline_request` makes the daemon call `ensureAgentLoaded`) not `resume_agent_request`. `agentResumeNotice(item)`, `startNewChatReplacing(old, newChatAcknowledged: true)` (never silently replaces, never reuses the old id, never replays the last prompt). `_paResumeFailed` makes the next tap offer a new chat. Chat id handling: the feed holds the draft's local id until the first prompt creates the daemon agent; the chat gateway only knows the daemon id (commit 503cb8929).
- **Tricky (hard-won):** Paseo 0.11.2 `resume_agent_request` takes no agent id and creates a NEW agent on every call: reopening forked Kilo each time (ace6fcb28). A resumed record can come back without a title; the title is kept app-side (`oc.conversationTitles.<profile>`) and **never written back with `update_agent_request`** (that bumps the row to "Just now"). Opening a chat must not move it to the top as Done · Just now (b4339921c, idle guard in 21).
- **Rewrite stance:** PORT.

#### AGENTS-BACKENDS-07 — Agent screens: Settings › Agents, agent sheet, Conversations notices, Cards row
- **User sees:** Settings › Agents (and Settings › This phone › Agents): rows per agent with the one act each needs, **Check this phone**, **Cards from agents** switch with status per agent; the agent sheet (opened from the chip) that becomes Install → Phone check → Sign in in place; quiet lines on Conversations for plan limit / signed out / stopped host / one restart offer, each naming its target; a remote server or Termux gets a one-line explanation plus the switch to the built-in server.

#### AGENTS-BACKENDS-09 — Phone check ("Run phone check")
- **User sees:** four steps (Install → Version → Connection → Ready), each passed/failed/waiting with one plain sentence; "Use previous version" for Claude after an update problem.
- **How:** `selfTest(agentId)`: (1) install proof, (2) `agentHostVersion` (installed + version equals pin; also checks oc can read/write the shared projects bind via `agentHostWorkspace`), (3) start the helper (`startAgentHost` with `expectedHelperVersion` 0.11.2, `restartIfVersionChanged`), (4) authenticated Paseo `hello` only (no model request, no login). On pass it writes the **gate**: `oc.agentPhoneGate.<owner>` = JSON `{ "<agentId>": {fingerprint, architecture, activeVersion} }` where `fingerprint = jsonEncode([agentId, recipeVersion, artifactSha256, paseoVersion, lockSha256, nodeVersion])`. Any change of agent/pin/Paseo/lock/Node invalidates proof and gives `checkRequiredReason`. `AgentPhoneCheckResult.arm64Qualified` is true only for an ARM64 pass (x86 emulator passes never unlock ARM64). For Claude the check ends with a sign-in read; signed-out → `needsSignIn` (turns a dead end into "needs sign-in").
- **Tricky:** an installed version that is not the pin but runs counts as installed (ea6b3d726); a phone check does not restart a helper that already runs the pinned Paseo (457d4f22e on the trial branch); `_checkInFlight` also refuses a first message ("phone check running", named under Details); auth reads inside the check take turns (below).
- **Tests:** `phone_agent_host_*`, `claude_phone_auth_test.dart`, Kotlin `NativeAgentHostAdmissionTest`.
- **Rewrite stance:** PORT; keep the fingerprint format (stored proof survives the migration only if the format is identical).

#### AGENTS-BACKENDS-10 — The Paseo helper process (native `PhoneAgentHost`)
- **How:** Kotlin `PhoneAgentHost` (`android/.../PhoneAgentHost.kt`) starts `/home/oc/.local/bin/paseo daemon run --home $HOME/paseo` through proot as uid 1000. Port is fixed **4099** on **127.0.0.1**. Password = 64 lowercase hex generated by Dart, stored in secure storage `oc.agentHostSecret.<owner>`, written to the child's **stdin** (never argv/env/log). Env: `PASEO_LISTEN=127.0.0.1:4099`, `PASEO_RELAY_ENABLED=false`, `PASEO_WEB_UI_ENABLED=false`, `PASEO_DICTATION_ENABLED=false`, `PASEO_VOICE_MODE_ENABLED=false`, `PASEO_SERVICE_PROXY_ENABLED=false`, log level fatal. `config.json` (written by `configuration()` each start): `daemon.listen 127.0.0.1:4099`, relay off, `mcp.injectIntoAgents false`, features webUi/dictation/voiceMode off, log file `daemon.log` rotate 1M ×1, and `agents.providers.<providerId> = {extends:"acp", label, command:["/home/oc/.local/bin/<exe>", ...launchArgs]}` for every `acpPaseo` catalog agent. Startup grace 1.5 s: exit inside it = `agent_host_exited`. #### AGENTS-BACKENDS-19 — Paseo transport (WebSocket, protocol 1)
- **How:** `lib/paseo/transport.dart`. One WebSocket at `/ws`, one JSON object per text frame. Manual HTTP upgrade (redirects off **before** credentials are attached; response must be 101 with the right `Sec-WebSocket-Accept`, no `Sec-WebSocket-Extensions`, and any echoed subprotocol must equal ours; compression off; max payload 8 MiB). Password rides as `Sec-WebSocket-Protocol: paseo.bearer.<password>` **and** `Authorization: Bearer`, and again in-protocol in `hello.auth {kind:'password', password}` (daemon ≥0.10; the header form is accepted until 2027-03-24). `hello` = `{type:'hello', clientId:'cid_<32 hex>', clientType:'mobile', protocolVersion:1, appVersion:'0.8.0', auth?, capabilities:{all_providers:true, hello_rejection:true, provider_subagents:true, projected_subagent_timeline:true}}`. Answer: `session`/`status` `server_info` (version, permissions, `features` incl. `workspaceFileEditing`). Everything after: `{type:'session', message:{...body, type:T, requestId:'m<epoch>_<n>'}}`; response type ends `_response` or `.response`; optional progress messages per request; `ping` every 20 s plus WebSocket ping 20 s; handshake wait 8 s; default request timeout 20 s (create agent 90 s; the browser-launch send path 60 s); max 64 pending; reads time out as `disconnected`, **mutations time out as `deliveryUnknown` and are never retried**. Connection **epochs** fence every request and every answer (`staleRequest`). Frames ≥64 K chars are JSON-decoded on a background isolate, with an in-order inbox so messages never overtake. `requestBoundedHistory` opens a private second connection with a 1 MiB frame budget and 10 s limit for recovery reads. Binary frames `[opcode, slot, …payload]` carry terminal output.
- **Failure kinds** (fixed copy, daemon text goes only to Details, trimmed to 240 chars): `invalidEndpoint, authentication, hostRefused, disconnected, invalidResponse, unavailable, newChatRequired, overloaded, deliveryUnknown, staleRequest, scopeMismatch, notFound, incompatibleProtocol`. Close **4401** after a successful upgrade = wrong password; **4003** or `hello.rejected` = protocol mismatch; HTTP 403 with a password sent = authentication, without = host not in the daemon's allowlist.
- **Version policy:** `lib/paseo/tested_versions.dart`: `paseoTestedVersions = {0.9.2, 0.11.2}`; `claudeCodeTestedVersions = {2.1.283, 2.1.294}`. Behaviour once keyed to one exact version now asks here. Add a version only with runtime evidence.
- **Daemon quirks that shaped the client:** released 0.8.0 lacked `agent.create.request` (the gateway aliases its own session id to the daemon id and holds events that race the create answer); legacy `create_agent_request` answers via `status/agent_created`; archive answers with an `agent_archived` push (transport settles a request on any payload carrying its requestId); agent snapshots lag the stream (an idle snapshot appears after `turn_started`) so **turn events own busy state**; do not claim `explicit_event_subscriptions` in `hello` or permission/stream events stop arriving implicitly; send `appVersion` ≥0.1.45 or Pi is hidden.
- **Tests:** `paseo_gateway_test.dart` (19), `paseo_background_decode_test.dart`, fixtures `test/fixtures/paseo/native_questions_0_9_2.json`, capture `docs/research/paseo-backend-spike-2026-09-19.md`, live proofs `tool/qa/paseo_live_proof_test.dart`, `paseo_first_message_live_test.dart`.
- **Rewrite stance:** PORT on Ktor/OkHttp with a custom handshake. Required: subprotocol auth, no redirects, no extensions, frame cap, epoch fencing, mutation-vs-read timeout semantics. Background JSON decode is a non-issue with `Dispatchers.Default`.

## 8. Performance notes

- **Cold start budget:** first Claude message ≈6 s on the emulator after the 2026-10-04 fixes (create on the folder's gateway while the backend connects). Helper start up to 30 s on a cold phone; Paseo first handshake 8 s; agent create timeout 90 s (cold daemon); Gas City agent start 22 s–4 min cold under proot.
- **Memory/process:** Android stops an app's child processes past ~32 (oldest first). Per-agent `claude` processes add up; Gas City default peaked at 33-40; OpenCode server ~410 MB; extra `opencode acp` ~563 MB each. dataSync foreground service capped at 6 h per rolling 24 h on Android 15+ (battery exemption does not lift it). Nothing in the agent code may assume unbounded lifetime.
- **Disk:** Claude binary 252 MB, Codex 104-111 MB download / 255-294 MB installed, Node ~58 MB download / ~216 MB installed, Paseo `npm ci` ~773 MB with its deps (earlier npm-based estimate), install guard reserves download **plus** extracted size; flutter test temp dirs filling `Storage` once made tests "hang".
- **Lists:** max 4 Paseo folder sources, 5 pages × 200 rows per source (`maxPages`, 45 s refresh timeout), saved rows ≤200, first-paint hold 4 s, loading line 30 s.
- **JSON:** Paseo history frames up to 8 MiB; decoding hundreds of ms on the UI isolate (measured); a native app should decode and map on a background dispatcher and page long timelines.
- **Native APK facts:** engine .so 5.4 MB; whole native demo was 2.5 MB APK / ~0.25 s cold start vs Flutter 107 MB / ~0.4 s.
- **Ping/keepalive:** Paseo 20 s app ping + 20 s WS ping; Codex 20 s WS ping; engine heartbeat 10 s lease 30 s; Gas City supervisor patrol 60 s; sign-in recheck 5 s; usage monitor 5/15 min.
