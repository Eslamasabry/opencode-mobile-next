## Why shots still fail

1. **Glyph rasterisation.** Most remaining shots are text or icon shots whose layout is identical to Flutter (same ink
   width, same position) and whose only difference is anti-aliasing of the letters (blob 0 to 25 px, box 3 to 9 %).
   Examples: `kit_since_slow_*` (blob 0), `kit_tappable_enabled_text2_*` (blob 0), `kit_surface_tile_*` (blob 0). They
   exceed the T1/T2 box limits only because the ink box of a one-line shot is tiny. This needs a lead decision (tier
   calibration, standard 9.3), not a part change.
2. **Phosphor icons.** Native icons are Phosphor path vectors; Flutter draws the Phosphor font glyphs. Outline pixels
   differ at every glyph edge (`kit_icon_*`, blob 33 to 52 px).
3. **Parts owned by other orders** (standard 13, item 3), not editable here:
   - `kit_signal_{home,home_ar,chat,chat_folded}`: whole screens built from rows, request cards, step timelines and
     the feed (orders 08-30) in the Signal style (order 03). Only the matrix of `KitRunningFeedLine` is rendered.
   - `kit_tappable_menu_open`: needs `KitMenu` (kit_menu.dart) and a `menu` parameter on `KitTappable`; not rendered.
   - `kit_tab_switcher_needs_you_*`: the badge is `KitNeedsYou.badge` (another order); the native stand-in differs.
   - `kit_motion_spin_fixed_*`: Flutter shows the Material `Icons.terminal` glyph, which is not in AppIconography.
4. **Interaction looks** (`kit_tappable_hovered/pressed/focused`, `kit_tab_switcher_focused`): the pressed fill, hover
   fill and focus ring of `KitTappable` are not yet the Flutter ones in dark mode (large blob); light mode is close.
5. **Duotone high contrast** (`kit_icon_duotone_*`): native icons carry both layers in one vector, so the "one layer"
   row cannot be shown; the platform high-contrast signal is not read by `KitIcon`.

## Deviations from the standard, with reason

- **`:ui:gate` is not a compiled dependency of the kits.** `ModuleRules.kt` (build-logic, not in any write set) has no
  `:ui:gate` edges, so `:ui:gate` -> `:ui:kit` and `:ui:kit` -> `:ui:gate` both fail at configuration. Instead
  `native/ui/gate/src/desktopMain/{kotlin,resources}` is added to the `desktopTest` source set of `:ui:kit`,
  `:ui:kit-chat` and `:ui:kit-content` (their build files), and `:ui:gate` compiles nothing itself. The lead should add
  the rule edges, after which the three `srcDir` lines can become `implementation(project(":ui:gate"))`. As a result
  `GateSelfTest` lives in `:ui:kit` and `GateProofTest` in `:ui:kit-chat` (both under `rb/o01`).
- **`desktopTest` never caches.** The gate writes its rows and pictures as a side effect of those tests; a
  `FROM-CACHE` or up-to-date `desktopTest` leaves `looks-out/gate` empty and the evaluation fails with "no gate row".
  The three build files switch caching and up-to-date checks off for that task.
- `FlutterGoldenGate.check` gained two defaulted parameters, `textScale` (the `_ar` goldens are taken at 1.3) and `act`
  (hover, press and focus need an interaction before the capture).
- Public defaults changed to Flutter's: `KitIcon` size Large and tone Primary, `KitText` tone by role.
