## The shared API for orders 32 and 33

```kotlin
abstract class KitLiveStyle { val id: String; val label: StringResource; open val ceilingFactor = 1.0;
    open fun wantsTextHalo(p: KitLivePalette) = false; open val framesPerSecond = 12
    abstract fun paint(canvas: DrawScope, size: Size, frame: KitLiveFrame) }   // size in logical pixels
class KitLiveFrame(t, running, strength, palette, memory, text: KitLiveText? = null)
```

Helpers: `KitLiveSupport.kt` (`liveHash`, `liveFbm`, `liveSmooth`, `liveMix`, `liveAlpha`, `livePeak`, `liveRandom` →
`DartRandom`, `liveClock`, `liveCached`) and `KitLiveToolkit.kt` (`hash2`, `valueNoise`, `fbm`, `smooth`, `rgb`,
`mixRgb`, `packArgb`, `strengthOf`, `paintField`/`LiveField`, `LiveFbmGrid`, `liveTextReads`, `liveMost`, `LiveHsl`).
A look is a Kotlin `object`; adding it is uncommenting its one line in `kitLiveStyles` (the slots are there, in Dart
order). `KitLiveFrame.text` carries the measurer and the mono family for matrix rain.

## Smooth: how and how much

- Each look draws in its own `graphicsLayer` (a `Spacer` under the page in `KitLiveBackground`), reading the clock and
  the running lift only inside `drawWithCache { onDrawBehind { … } }`: a tick invalidates that layer's draw alone; the
  page above never recomposes or redraws for it (`KitLiveBackground.kt`).
- Time: one shared `KitLiveClock` at Flutter's 12 ticks a second (a look may ask for fewer), at most 3 ticks per late
  frame, resting after 30 s without a touch, scroll or key and carrying on at the next one. Each shown page waits one
  interval, then offers the frame time (`withFrameNanos`); the first offer of an interval moves the clock, so two pages
  never double its speed. Off, Calm, reduced motion: the still frame (second 0) and the clock is not attached.
- No allocation for geometry per frame: paths, brushes, shaders and bitmaps are built once per size/colour/strength in
  `KitLiveFrame.memory` and only moved (`translate`, `rotateRad`, draw alpha). Per-pixel fields (aurora haze, caustics)
  are written into one small reused bitmap and drawn with bilinear smoothing (Flutter's coloured vertex mesh, same
  grid). Their fractal noise is separable, so `LiveFbmGrid` hashes each lattice point once a frame instead of four
  times per octave per vertex: bit-identical values (`theGridNoiseIsFbmBitForBit`), 4× faster.
- The aurora's ribbons (Flutter: 8 `drawVertices` a frame) are drawn once per size/theme into four bitmaps at the
  page's logical scale and moved; hardware canvases draw vertices only from API 29, the app's minimum is 26, so this
  also makes them appear on Android 8–9.
- AGSL was not needed: the Canvas path is already under budget on every look, so there is one path on every API.

Frame cost, `KitLiveFrameCostTest` (1080 × 2400 at density 2.75, dark, 300 warm-up frames, median of 120, second
pass; Intel Xeon 2.1 GHz, one core, JDK 21; CPU Skia):

| Look | record ms (UI-thread work) median | p95 | CPU raster ms (upper bound; a phone rasters on its GPU) |
|---|---|---|---|
| blueprint | 0.004 | 0.006 | 2.8 |
| bokeh | 0.014 | 0.020 | 2.3 |
| brushedMetal | 0.003 | 0.006 | 5.2 |
| caustics | 0.383 | 0.413 | 11.8 |
| circuit | 0.013 | 0.019 | 1.1 |
| aurora | 0.269 | 0.339 | 34.4 |

A mid phone's core is roughly 2–3× slower than this one for this kind of maths, so the heaviest looks (caustics,
aurora) should record a frame in about 1 ms, inside the 4 ms target; this is an estimate until measured on a device
(below). The CPU raster column is not the phone's cost: the GPU rasters a few textured quads and paths.

Before the noise and bitmap work the same harness measured caustics at 1.8 ms and the aurora at 13.5 ms (most of it
desktop Skia copying a mutable bitmap on every draw, fixed with `liveSettle`).

## Folded gaps (not in this order's files)

- **Text halo.** The aurora's dark-theme brightness is measured assuming text2/text3 keep a halo of the ground
  (`KitTextHalo.cover` .55, `wantsTextHalo` = dark). The native kit has no `KitTextHalo` yet, so in dark themes text2 and
  text3 over the brightest ribbon can fall below the contrast the Flutter app keeps. Owner of the halo: the kit text
  owner; until it lands the aurora still meets the bare-text check for text1 and the accent.
- **Dithering.** Flutter dithers gradients; Compose common has no dither flag, so bokeh's discs show 8-bit steps (at
  most 3 levels from Flutter's pixels).
- **Glass backdrop.** Glass panes blur only the painted aurora (`KitGlassBackdrop`); a drawn look is not recorded into
  the backdrop. Choosing Glass picks the painted aurora, so this only shows when a person picks Glass and then another
  look.
- **`KitLiveBackground.running`.** Flutter brightens every page's look while any composer runs (a static counter). The
  native background takes `replyRunning` per page (default false) and nothing passes it yet; wiring it to the chat's
  running state is the chat owner's.

1. Settings › Appearance › Background: turn Background on. The Look grid shows Off, Aurora drift, Painted aurora,
   Blueprint, Circuit, Brushed metal, Caustics, Bokeh, each with its still sample behind the tiny chat.
2. Pick each look; go to Conversations: the look covers the page ground; rows, cards and the box stay solid on top.
3. Leave the phone untouched 30 s: the look stops moving (GPU profile bars flat); touch: it carries on where it stopped.
4. Profile GPU rendering with Caustics and Aurora on a mid phone: no bar above 16 ms; the frame's UI-thread part well
   under 4 ms; frames only about 12 a second (none between ticks).
5. Motion › Calm and Off, and system "Remove animations": the look shows its still frame and does not move.
6. Appearance › Saver: the page is true black with no look. Style › Brutal or Soft: the look is dimmer (capped at .7).
7. Arabic: the looks are not mirrored (as Flutter); the picker labels read in Arabic.
8. API 26–28: the aurora's ribbons show (they are bitmaps, not hardware vertices).
9. Rotate and resize (split screen): the look rebuilds its geometry for the new size without a hitch.
