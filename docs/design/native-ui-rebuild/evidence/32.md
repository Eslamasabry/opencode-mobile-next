Every look records a frame well under 4 ms (the test asserts it). The raster column is Skia's software rasteriser
filling every pixel of a full-screen gradient or mesh on a CPU and is not what a phone does (the GPU rasterises the
recorded list); the on-device number needs the coordinator's emulator/phone trace. Draws happen at most 12 times a
second (fewer for a look asking fewer), never between ticks, none after 30 s idle.

## Smoothness design

- Each look draws in its own clipped `graphicsLayer` behind the page (`rememberKitLiveLayer`); the clock's seconds
  are read only in the draw phase, so a tick redraws that layer alone and the page above never recomposes
  (`KitLiveBackgroundLooksTest.aDrawnLookShowsAndMovesWithoutRecomposingThePage` counts compositions: 0).
- Paths, paints, shaders, gradient brushes and glyph layouts are kept in the look's memory and rebuilt only when a
  size or colour changes: glow spill and light rays draw one cached unit gradient under a transform; flow threads
  reuse one path per thread and a ring buffer per trail; honeycomb draws one cached lattice and one cached hexagon.
- Mesh and liquid blobs draw Flutter's vertex colour field with Skia `drawVertices` (Android API 29+, desktop), and
  below API 29 on a hardware canvas the same grid as a filtered bitmap. No AGSL shader was needed.
- Time is driven by `withFrameNanos` at the clock's 12 ticks a second (`KitLiveClock.advance`), resting after 30 s
  with no touch; a touch (pointer, initial pass, never consumed) wakes it where it stopped.
