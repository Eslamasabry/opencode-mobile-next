## Appearance supported controls

Theme choices now use the Flutter three-column swatches (two in a guided question), with theme-coloured ground,
accent stripe, partner dot and selected check. Picking a theme applies through `onPack` immediately, as
`appearance_screen.dart:912-930` does. Style choices use a two-column grid with each style's own sample;
mode is the tall icon control, and Text precedes Motion. Background, glow, frost, reset-all and Glass selection remain
blocked by missing state/actions or the presentation enum (`SurfaceStyle` has no Glass).

The owner explicitly permits adding missing kit parts. The order manifest's older WRITES list does not include
`native/ui/kit/**`, so its W1 checker rejects the newly required `choice/KitOptionCard.kt`. The gate tooling and manifest
were left unchanged; this conflict must be resolved by the coordinator before a clean static order pass is possible.

## Group page and Language

Group rows now show their Flutter icons and put current values at the end (Language, Appearance, background,
notifications and server counts), with the kit moving values below the title when text needs room. Conversation
switches use `KitIconSwitchRow`, a single semantic toggle with the shared icon rail. Language opens the kit sheet locally;
choosing a language calls the existing action and dismisses it. A focused test covers both flows.

Missing group data: selected model and default shell values, hidden-by-server count and its explanation, hardware
keyboard presence and diagnostics badge count are absent from `SettingsUi`/`GroupUi`. Those details remain unimplemented.
