## Blocked (standard §13), one line each

1. **Confirm frame has no handle and the wrong padding** (§13.1). `modal/KitDialog.kt` `DialogLayer` (order 11) pads
   the content 20 dp on every side and draws no handle. Flutter's `presentKitConfirmFrame` (kit_confirm_sheet.dart:
   155-176) draws a 22 dp handle band and no frame padding; the body pads itself (rail / space3 / rail / space4,
   :502-506), and a wide panel adds space3 on top (:157-159). This shifts every confirm shot by 10-14 px, and it is
   most of each box %.
2. **Tertiary words in accent** (§13.1). `KitButton.kt:162,169` (order 07) colours a tertiary `colors.accent`. In the
   goldens Flutter's tertiary ("Export first", "Copy fox instead") is text1.
3. **KitField's input target is 24 dp** (§13.1, layout `small-target`, align `target`, matrix X2).
   `input/KitField.kt:540` puts the field's semantics after the box padding, so the tappable node is the inner
   348×24. It needs to be on the 48 dp box.
4. **KitNotice action gap of 10 dp** (§13.1, align `gap-step`, kit_confirm_failed): `state/KitNotice` (its owner order).
5. **KitDetailsFold words at x 32** (§13.1, align `start-edge`, Arabic shots after the Details tap):
   `state/KitDetailsFold.kt`.
6. **Consequences panel versus the alignment columns** (§13.6, the rule and the standard disagree). Flutter's panel
   (kit_consequences.dart:102-131) puts the words at rail 20 + space4 16 + mark 20 + space3 12 = **68 dp**. That is in
   the goldens, but it is not a column in `native/config/align/spec.json` (16, 20, 48, 52, 56, 60). Drawing the marks
   as KitIcon glyphs also trips `icon-label`, because Flutter top-aligns a 20 dp mark on a 22 dp line (1 dp). I kept
   Flutter's geometry, did not baseline it, and drew the marks as images so the mark column adds no findings of its
   own. The lead decides: add the inset-panel column (68, and 64 off the gutter) to the align spec, or accept a
   departure from Flutter. This also changes order 11's `kit_sheet_consequences` shot: it renders this panel, so it
   now shows the start-edge findings, and its old baseline line (`gap-step "# queued prompts…"`) no longer
   reproduces.

Fixed in my files after the guards flagged them: the consequence hairline took 1 dp of layout (Flutter's
`Divider(height: 0)` takes none), so it is now drawn on the row; the neutral dot no longer makes its own semantics
node; and the tertiary is no longer pulled back twice (`KitButton` already bleeds its space 2, which is `KitInset`).

## Folded gaps (read-only check, not edited)

### kit_sheet_frame / kit_sheet_modal / kit_sheet_parts → `modal/KitSheet.kt`, `KitDialog.kt` (order 11)
- Confirm frame: no handle (22 dp band, 36×5 bar, "Dismiss"), 20 dp padding all round plus `spacedBy(S3)` instead of
  none; on a wide panel, 20 dp on top where Flutter has space3 + the body's space3; the medium window gets the 640 dp
  sheet where Flutter uses 560; the window class is decided by width only (Flutter's `modalWindowOf` sends a short wide
  window to the bottom sheet); a confirm raised from inside a sheet opens a second layer instead of replacing the
  sheet's content (§4.7); the panel scales in from .96 where Flutter fades over STANDARD.
- Sheet: full height .9 vs Flutter .95; a half-height panel sizes to its content instead of 50%; the side sheet is a
  fixed 440 vs 40% of the window clamped 400–480, slides from the wrong side in RTL, and has no top safe area; non-Glass
  styles get flat `surface2` instead of `_KitModalSurface`; drag-to-dismiss works on the handle only, by distance only
  (no 700 px/s fling), and the sheet does not follow the finger; Close can be hidden on panel and side sheets (Flutter
  always shows it there); `KitSheetStep` does not drive the header; drafts are a flag with no restore or auto-save.
- Frame: when the header scrolls (Flutter: header + max(96, room/2) > room; native: under 400 dp or font scale ≥ 2);
  pinned block cap −64 vs −96, and it scrolls where Flutter clips; the header moves inside the scroller; there is an
  extra labelGap; no pull-down off-switch.
- Parts: no `_KitSheetBar` (tertiary at the start ≤ 2/5, then the primary); the icon tile glyph is a fixed 22 dp where
  Flutter's grows to 33 dp with text size; the tile is a flat surface3 box instead of a style-resolved control
  surface; the handle has no "Dismiss" label.

### kit_request_answers → `kit-chat/request/KitPermissionCard.kt`, `KitQuestionCard.kt` (order 11)
- No keyboard shortcuts (A, D, 1–9 on a fine pointer, wide window); no lock against sending twice or single Send
  haptic; "Always allow" is a full Secondary button instead of the quiet line with its own confirm; stacked order keyed
  on `secondary` instead of the question look; "{n} more answers" sits in the pinned slot without KitInset; no
  sending/receipt phase; choices are plain strings with no disabled state; the Answer role has no `secondary` flag;
  `KitRequestGo` and `KitRequestReply` are missing (Reply is rebuilt on the screen in `ChatRequestSlot.kt:396`); no
  gate defaults ("Approve" / "Send back").
