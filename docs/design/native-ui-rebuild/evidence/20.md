   is 100 dp tall at 3 lines (native 94). Owner: part-kit_field, order 05 (`input/KitField.kt`). With Flutter's
   geometry the gaps become 54 dp (page layout, unchecked) and 28 dp (on grid). Not baselined, as instructed.
2. text2 shots of every card — the `KitActionBlock`/`KitButton` label does not grow at 2.0× and the button is shorter,
   while Flutter's label scales; card bodies match. Owner: part-kit_buttons, order 07. (A `DEPENDS_ON 07` waiver fits if
   order 07 is still open; not filed because the done-state of 07 cannot be checked from here.)
3. kit_server_trust certificate shots — `KitMonoText` (`KitText.kt`) wraps the fingerprint mid-pair ("…89:A|B:CD");
   Flutter breaks after a colon. Owner of `KitText.kt` (order 01/02). Every other line matches.
4. part-kit_server_trust matrix cap X2 — the manifest caps `KitServerTrustBody` at sheet 640, but Flutter's body has
   no cap of its own and the 1280/1600 goldens draw it 688 dp wide; capping it would break those goldens. Needs a lead
   decision (manifest role or golden wins).

   from the icon font with heavier ink. Same shapes and positions (looked at 3× zoom). Calibration item for the lead.

## Folded gaps and seams the lead must resolve

1. **Order 28 is a missing dependency.** Every team part (3-10) is a thin wrapper over `team_parts.dart`
   (`teamCard`, `teamRow`, `teamIcon`, `teamTone`) and the types of `kit_team_data.dart` (`KitTeamState`,
   `KitTeamItem`, `KitTeamFinding`, `KitFindingSeverity`, `KitPlanTask`, `KitPlanPhase`). Their native home is order
   28 (`team/KitTeamData.kt`, `team/TeamParts.kt`), which is not merged on this base, and order 20's header lists only
   `DEPENDS: 01`. So the parts could draw at all, the types (public, Flutter names) and the card/row helpers
   (`internal`, as `TeamCard`/`TeamRow`/`TeamGlyph`/`TeamGlyphs`/`KitTeamRules`) live in a marked block at the top of
   `team/KitDigest.kt`. **When order 28 merges, the types will be declared twice in package `…ui.kit.team`; delete
   the block in `KitDigest.kt` and keep order 28's files** (or keep this block and drop 28's duplicates). Same names,
   same package, same shapes, so no caller changes.
2. **Two older parts share names with this order's.** `ui/kit/KitSteerBox.kt` (package `…ui.kit`) and
   `ui/kit/state/KitServerTrustBody.kt` (package `…ui.kit.state`) predate this order and are used by
   `feature/widget-panels`, `feature/widgetactions` and `feature/servers`. They are outside order 20's write set, so they
   stay. The order-20 parts are the Flutter-shaped replacements: `…ui.kitchat.composer.KitSteerBox` (title + close
   row, `hint`, `sendLabel`, `caption`, revealed note, Send cross-fade) and `…ui.kit.modal.KitServerTrustBody` /
   `KitServerTrust` (chooses its own title, body and accept words from `certificate`/`changed`/`privateNetwork`).
   Owners of those features move to them, then the old files can go.
3. **Material glyphs.** `team_parts.dart` draws Material `Icons.*` (check_circle_outline, pending_outlined,
   notifications_none, error_outline, pause_circle_outline, history, inbox_outlined, hourglass_empty, chevron_right).
   The kit's `KitIcons` (Phosphor) has no twin and the kit has no Material icon artifact, so the nine outline paths are
   carried in `TeamGlyphs` (Apache 2.0, 24-unit viewport). If the lead prefers them in `KitIcons.kt`, move them there.
4. **Check box.** `kit_findings_card.dart` uses Flutter's Material `Checkbox`. The kit has no check-box part, so
   `KitFindingsCard` draws the Material painter's geometry (18 dp box, 2 dp edge/corner, the tick fractions) with
   `Canvas`; numbers carry `// NV:` because they come from the framework painter, not a kit line. A kit `KitCheckbox`
   (order owner TBD) should replace it.
5. **Dates.** Flutter formats `validFrom`/`validTo` with `MaterialLocalizations.formatFullDate`; the native kit has no
   locale date formatter, so `KitServerTrustBody` takes the two dates already written as full dates by the caller.
