### Blocked: kit_widget_style_form_* (standard §13 item 1)

Every line below the preview sits 7 px low, and further at 2.0 text. These are the causes, each in a file outside
the write set:

- `choice/KitSegmented.kt` (order 05): the control is 52 dp tall where Flutter draws 48 (golden: 236-284 against
  native 236-288).
- `choice/KitWidgetStyleForm.kt` (in no order's write set, so it is the lead's):
  - Its section labels use a `FormLabel` with `S4` above and `S2` below. Flutter uses
    `KitSectionLabel.inline(gapBefore: space4)` (kit_widget_style_form.dart:85-88, 103-106).
  - It has no `KitMaxWidth.reading` wrapper (:53) and no `locked` → `widgetV2Sending` reason (:92-93, 117-118).
  - The size segments are disabled while locked, which Flutter does not do (:78).
- `choice/KitSwatch.kt` (order 05): the selected swatch draws a white ring; Flutter's ring is the grey of
  `colorsAnotherSurface`.

## What changed and why

- `KitWidgetPreview.kt`:
  - Ported the Dart file: the `KitWidgetPreviewSize` and `KitWidgetPreviewBackground` enums and `_extent`
    (`widgetPreviewExtent`).
  - The compact body hugs its words and is centred, because AnimatedSwitcher's stack loosens the width.
  - The layouts cross-fade on a size change through `KitMotion.specs.enter()` (instant under reduced motion).
  - The tones are explicit and the count uses tabular figures; the transparent ground is surface1 at alpha 0.
- `widget/KitWidgetStylePreview.kt`: the widget-style screen in `:ui:shell` drew invented bars. Flutter draws
  `KitWidgetPreview` on that screen (kit_widget_style_form.dart:61-73). The signature is kept; a new optional
  `ground` parameter is added.
- `platform/AndroidWidgetThemeColors.kt`: verified and unchanged. It resolves the same roles as `KitTheme` for
  RemoteViews; Flutter has no counterpart drawn in a golden.
- `foundation/KitFrostHeader.kt` (new):
  - The host (`extendUp`, `under`, `loading`, `release`, `frosted`) and `KitFrostTopClaim`.
  - `Clearance` and `topClearance()` (reading it is the body's opt-in), plus `Scope` and `hostOf`.
  - `Frame`: the bar is laid out on top at its own height with the content below, and painted last; its frost pane
    runs `extendTop` up through the status bar.
  - `extendUpFor` and `extendUp`: the gap rule `gap > -.5 && gap <= loadingBarHeight + .5` (kit_frost_header.dart:276).
  - Nothing calls it yet. The page frame (`KitScreen`) and the composer layer belong to other orders and need a
    lead-landed seam.
- `diff/DiffMarkdown.kt`:
  - `_mdUnits` is ported exactly. The old cutter merged sibling list items, read `#tag` as a heading, accepted
    mixed-mark rules (`-*-`) and only allowed three spaces before `>`.
  - The unit gains `markdown` (the joined text), `blank`, `code`, `kind` and `take`. `isMarkdownPath` is ported.
  - `diffDisplay` takes an optional `file`, so a gap's revealed lines form their own run, as in Dart.
  - Blank and code units stay source rows; Dart draws them with the same numbers and an empty line.
- `diff/DiffModel.kt`:
  - An empty before text is now `Modified` (kit_diff_model.dart:146-152). `DiffModelTest` asserted `Added`; that line
    is changed and cites the Dart line.
  - `fullText` and `patch` are kept, and the index gains `longest` and `allLines`.
  - Added the constants `HIGHLIGHT_LINE_LIMIT` 2000, `HIGHLIGHT_LINE_CHARS` 1000, `LEGIBLE_CONTRAST` 4.5 and
    `SELECTION_ALPHA` .2, plus `lineGrammar` (json → javascript), `highlightsLine` and `DiffFile.highlightable`.

No new words: every string the parts use already exists (`widgetV2*`), so `strings_rb25.xml` was not needed.

## Folded gaps (other orders' files; not edited)

**part-kit_diff_chrome / part-kit_diff_rows → `kit-chat/diff/KitDiffView.kt` (order 14)**

- Markdown and display:
  - `KitDiffView.kt:179` joins `unit.lines` with "\n"; it should draw `unit.markdown` (kit_diff_markdown.dart:45-63).
  - `KitDiffView.kt:101` calls `diffDisplay` without `file`; it should pass `file` so revealed gap lines stay apart.
  - `KitDiffView.kt:81` checks for Markdown without excluding binary files (chrome :263). It should use
    `isMarkdownPath(file.path) && !file.binary`.
  - Highlighting uses `totalLines <= 2000`; Dart counts `segments.length` (model :573). It should use
    `file.highlightable` and `DiffModel.highlightsLine`.
- Chrome that is absent:
  - The header: file name, status, `+n −n` counts, menu.
  - Multi-file support: file list, picker sheet, viewed ticks, folded mode.
  - The binary message, the loading skeleton and the too-big footer with Open all.
  - The 150 ms Markdown cross-fade.
- Change navigation: Dart uses chevrons, disables them at the ends and announces "Change n of m" in a live region;
  native has text buttons and no live region.
- Selection bar: Dart uses `KitActionBlock` with Comment as primary, caps it at half the height and announces the
  count in a live region.
- Native `heightIn(max = 560.dp)` has no Dart source.
- Rows:
  - The tint is .12 with attention; Dart uses .10 success and text2 (`codeAddedSurface` / `codeRemovedSurface`).
  - The selection fill is .2 and replaces the tint; Dart blends `markTintAlpha` .16 over it.
  - The glyph colours are all text2; Dart draws success / codeRemoved / text3.
  - Per-line semantic labels ("Line 12 added: …") are absent.
- Gutter: Dart has a 48 dp gutter with drag and shift-select, a right-click menu, an accent number and a focus border.
- Gap bars and split view:
  - The gap bars lack the unfold icon, the surface2 band and the direction-aware wording (`kitDiffFoldAbove/Below/Between`).
  - Gap lines are revealed without `KitReveal` motion.
  - The split view has no hairline divider.
