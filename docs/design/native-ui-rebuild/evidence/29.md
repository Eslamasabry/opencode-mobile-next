## Design notes and seams

- **Interim host.** `KitIllustration.kt` belongs to order 07 and is not on the base. The scene contract and host live
  in `scene/PortalScene.kt` under names that cannot clash with order 07's (`SceneArt`, `ScenePalette`, `SceneFrame`,
  `SceneDraw`, internal `SceneIllustration`). When order 07 lands, `KitIllustration` should host `SceneArt` (or the
  scenes re-parent onto `KitScene`); the coordinator decides at merge. The host is internal, so screens use the scenes
  only through order 07.
- **Fractional size.** Flutter lays out a scene at its exact size (170 wide → 71.4 high); Compose rounds to whole
  pixels, which shrank the fit-scale and moved the drawing. The host lays out at the size rounded up and paints the
  exact size centred in it (`kit_illustration.dart:393-397`); this took `kit_scenes_servers` from 4.5 % to 0.00 %.
- **Stretch.** The default page reproduces Flutter's `CrossAxisAlignment.stretch` for the button with
  `Box(propagateMinConstraints = true)`, so `KitMaxWidth` centres its 400 dp cap as Flutter does.
- **Lazy paths.** Scene paths are `by lazy`: Compose's desktop `Path()` needs the Skiko graphics registry, which a
  class initialiser may run before.
- **Motion.** Entrance 900 ms linear and loop 4000 ms from `FlutterKitMotion`; reduced motion, Motion Off, still frames
  and disabled celebrations show the finished frame at once (PortalSceneParityTest B-KIT-O29-009 proves the Off path).
- **Words.** Scenes have no words; `strings_rb29.xml` is not needed and was not created.
- **Static.** 7 `// NV:` lines (cap 20), all in the arc and rotation maths that convert Dart's `arcToPoint` and radians.
