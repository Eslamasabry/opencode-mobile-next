# Agent catalog evidence — 2026-10-03

Finish line: one immutable catalog entry supplies identity, route, host-auth category and a checksummed installation recipe to the generic host installer. Non-goal: installation metadata does not enable an agent or establish phone/auth/resume/permission qualification. No UI or controller belongs to this slice.

`lib/domain/agent_catalog.dart` is the frontend/backend contract. `AgentCatalog.builtIn` contains nine entries; a future agent uses another `AgentDescriptor`, not a new installer branch. `AgentCapabilities` defaults every runtime flag to false. All seeds are visibly limited pending phone qualification; missing recipes must be hidden with an enum reason. Unknown sizes remain null. `installedBytes` is the payload size, not a peak-space guarantee (archives and staging need additional space). `iconKey` is a stable identifier for the kit owner to map to kit assets.

## Installer seam and remaining proof

The installer must verify the complete downloaded SHA-256 before extraction/execution, reject unsafe archive entries and symlinks, preserve a versioned installation, and keep stdout/stderr diagnostics credential-safe. Archive-member path validation here validates catalog data, not every archive entry; the installer owns safe extraction. For `npmTarGz`, preserve **all** package files and point the command wrapper at `archiveMember` with shared pinned Node. Do not `npm install`, run package scripts, or resolve optional dependencies dynamically. `tarGz` OpenCode 2 platform tarballs are intentionally single-binary extraction despite npm origin.

Node/Paseo pins belong to shared host dependencies and are not duplicated per agent. Paseo native IDs and generic ACP extension are grounded in [pinned registry source](https://github.com/getpaseo/paseo/blob/v0.9.2/packages/server/src/server/agent/provider-registry.ts). ACP config uses the catalog executable/argument array; it cannot infer resume/auth support from the route. All capability flags remain false until the selected host proves sign-in, model listing, permission allow/reject, cancel, create/prompt/tool, restart and durable resume. Phone-specific missing system libraries/native extensions/keyring behavior may make an installed binary unavailable at runtime; installation success must remain a separate state.

Pinned fx's [mode registry](https://github.com/vercel-labs/fx/blob/v0.0.12/src/builtins/modes.zig) defaults to `ask`, and its ACP state defaults to permission mode `ask`. Plain `fx acp` preserves that default; MonoCode's explicit switch to `code` is its own policy. The pinned CLI accepts `--model` and `--log-file` after `acp`; do not invent a `--mode` flag. Keep permissions unqualified until the actual host/client responds safely.
